# 설계 독립 재검토 (2026-11-13)

설계 01~09단계 문서를 개발 전에 다시 본 결과입니다. 만든 쪽과 다른 모델의 재검토자 5명이 영역을 나눠 봤고, Claude가 지적마다 원본과 대조해 판정한 뒤 같은 문제끼리 묶었습니다. 고칠 범위는 동희님이 정합니다.

- 결정: 2026-11-13 17:03, 이 작업 대화의 결정 카드에서 동희님이 "5개 영역으로 나눠 지금 (추천)"과 "목록을 보고 정함 (추천)"을 고르셨습니다(17:01에 확인 요청).
- 고칠 범위 결정: 2026-11-13 20:59, 같은 작업 대화의 결정 카드(20:58에 확인 요청)에서 동희님이 네 질문 모두 추천 보기를 고르셨습니다. 높음 12묶음과 중간 20묶음은 지금 고치고, 낮음 27개는 그 뒤에 따로 모아 고치며, 정할 것이 있는 11묶음은 Claude 추천안대로 고칩니다. 질문, 보기, 답은 `fix-scope-decision.md`에 있습니다.
- 기록: Notion 기록 행 `417bf16cc3ec8180ad9af7160aff842d`. 이 폴더와 다르면 이 폴더가 맞습니다.

## 방식

- 영역: A 01~02(도메인, 요구사항), B 03~04(유저 플로우, 기능 명세), C 05(ERD), D 06(API 계약), E 07~09(사이트맵, 화면 상태, 목업).
- 재검토자가 받은 것: 자기 영역 원본, 바로 앞 단계 원본, CORTHEX 단계 계약, 문서가 인용한 1차 출처(법령, 카카오 문서).
- 받지 않은 것: `research/`(E는 목업 보드 폴더만 예외), 커밋 메시지와 PR 설명, Notion 기록. 문서 안의 '검사'·'통과' 절은 만든 쪽의 주장이니 직접 확인하게 했습니다.
- 심각도: 높음은 그대로 개발하면 틀린 동작, 돈이나 데이터 손실, 보안·개인정보·법 문제가 생기거나 개발이 막히는 것입니다. 중간은 개발 전에 정해야 하는 불일치나 빠진 예외이고, 낮음은 일관성, 작은 누락, 표현입니다.
- 재검토자는 저장소 파일을 읽기만 했습니다. 보고서는 받은 그대로 두고, D·E 머리말의 세션 임시 폴더 경로만 `(재검토자 작업 폴더, 저장소에 넣지 않음)`으로 바꿨습니다. 그 폴더에 있던 내려받은 법령·카카오 문서 사본과 측정 스크립트는 넣지 않았습니다.
