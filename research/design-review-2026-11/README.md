## 방식

- 영역: A 01~02(도메인, 요구사항), B 03~04(유저 플로우, 기능 명세), C 05(ERD), D 06(API 계약), E 07~09(사이트맵, 화면 상태, 목업).
- 재검토자가 받은 것: 자기 영역 원본, 바로 앞 단계 원본, CORTHEX 단계 계약, 문서가 인용한 1차 출처(법령, 카카오 문서).
- 받지 않은 것: `research/`(E는 목업 보드 폴더만 예외), 커밋 메시지와 PR 설명, Notion 기록. 문서 안의 '검사'·'통과' 절은 만든 쪽의 주장이니 직접 확인하게 했습니다.
- 심각도: 높음은 그대로 개발하면 틀린 동작, 돈이나 데이터 손실, 보안·개인정보·법 문제가 생기거나 개발이 막히는 것입니다. 중간은 개발 전에 정해야 하는 불일치나 빠진 예외이고, 낮음은 일관성, 작은 누락, 표현입니다.
- 재검토자는 저장소 파일을 읽기만 했습니다. 보고서는 받은 그대로 두고, D·E 머리말의 세션 임시 폴더 경로만 `(재검토자 작업 폴더, 저장소에 넣지 않음)`으로 바꿨습니다. 그 폴더에 있던 내려받은 법령·카카오 문서 사본과 측정 스크립트는 넣지 않았습니다.

## 파일

| 파일 | 내용 |
| --- | --- |
| `reviews/A-01-02.md`, `reviews/B-03-04.md`, `reviews/C-05.md`, `reviews/D-06.md`, `reviews/E-07-09.md` | 재검토자 결과. 지적마다 위치, 관련 ID, 문제, 원문 인용, 영향, 고치는 방향, 확실도 |
| `verdicts.md` | Claude의 판정 장부. 지적마다 재검토자 심각도 → Claude 심각도, 판정, 확인한 것, 묶음 |
| `bundles.md` | 묶음 목록(생성 파일). 손으로 고치지 않습니다 |
| `tools/bundles.py` | 묶음 정의와 `bundles.md` 생성. 모든 지적이 꼭 한 곳에 들어갔는지 확인합니다 |
| `tools/verify_quotes.py` | 지적의 인용이 '위치'에 적힌 파일에 글자 그대로 있는지 1차로 확인 |
| `tools/quotes_anywhere.py` | 위치에 적힌 파일에 없는 인용을 단계 문서 전체에서 찾음 |
| `tools/digest.py` | 지적마다 제목, 문제 앞부분, 확실도를 짧게 보임 |
| `tools/board_text.py` | 목업 보드 프레임의 보이는 글을 뽑음 |

저장소 루트에서 돌립니다.

```bash
python3 -I research/design-review-2026-11/tools/bundles.py research/design-review-2026-11/reviews research/design-review-2026-11/bundles.md
```

```bash
python3 -B research/design-review-2026-11/tools/verify_quotes.py . research/design-review-2026-11/reviews/C-05.md
```
