# TASK-038 무료 저장소 호출 한도 시험

API-017은 도안 사진 50개를 받는다. 현재 사진마다 임시 파일 확인·영구 복사·임시 삭제를 직접 호출하여 Workers Free의 외부 호출 50번 한도를 넘는다. 사진 수·API 응답·요금제를 바꾸지 않고 비공개 서비스 바인딩으로 저장소 작업을 나눌 수 있는지 확인한다.

- 공식 [한도](https://developers.cloudflare.com/workers/platform/limits/)는 Free의 호출별 외부 하위 요청 50번, 같은 최상위 요청의 연결 6개를 명시한다.
- 공식 [서비스 바인딩](https://developers.cloudflare.com/workers/runtime-apis/bindings/service-bindings/)은 추가 비용 없이 호출하며 같은 요청에서 Worker를 최대 32번 부른다고 명시한다. 외부 호출 한도가 각 서비스 호출에서 따로 계산되는지는 실제 Free 환경에서 검증한다.
- `peer.mjs`와 `harness.mjs`는 `workers_dev: false`·공개 경로 없음으로 배포한다. 기본 HTTP 응답은 404이고 RPC만 쓴다. `preview.mjs`는 학원컴 Wrangler 원격 개발의 루프백 주소에서만 실행하고 배포하지 않는다.
- 자신의 스테이징 외부 상태 주소를 자격 증명 없이 최대 211번 호출한다. 응답 몸체·오류 원문·가게 자료를 보관하지 않는다. AI 호출/예상 비용·유료 변경은 0이다.
- 실제 배포한 harness의 직접 49번 성공·51번 한도 도달을 먼저 확인해야 Free 한도를 검증한 것이다. 같은 harness에서 peer를 30번씩 두 번 불러 60번이 모두 성공해야 호출별 분리 가설을 뒷받침한다. peer의 51번도 한도에 도달해야 한다.
- 원격 개발의 한도가 실제 배포와 다를 수 있어 한도 검사는 모두 배포한 두 Worker 안에서 한다. 원격 개발 Worker는 결과 전달만 한다.
