# SCR-048 영업 신고 확인

- 경로: `/operator/shops/:shopId`
- 접근 권한: 운영자
- 상위 화면: SCR-047 영업 신고 확인 목록
- 화면 레이아웃: 운영자 화면(1280 왼쪽 메뉴, 360 위쪽 막대와 메뉴 버튼)
- 플로우: FL-001
- 관련 SPEC: SPEC-003
- API: API-013, API-014
- 와이어프레임: `wireframes.html#SCR-048`(상태 9개, 360·1280)

목적: 운영자가 가게의 신고증 사진과 넣은 영업 신고 번호·영업 종류·상호를 직접 대조해 '확인됨'이나 '보류(사유)'를 남깁니다. 보류하면 사장님께 우리 서비스 채널로 사유가 갑니다. (FL-001)

## 데이터

| 데이터 | 출처 |
| --- | --- |
| 가게 이름·연락처, 상호·대표자·사업자등록번호·통신판매업 신고번호(또는 면제 사유) | API-013 name·contactPhone·businessName·representativeName·businessRegNo·mailOrderRegNo·mailOrderExemption |
| 영업 신고 번호·영업 종류·신고증 사진(15분 동안 열리는 주소) | API-013 foodLicenseNo·foodBusinessType·licensePhotoUrl |
| 영업 신고 상태·보류 사유·마지막으로 확인하거나 보류한 운영자와 시각 | API-013 licenseStatus·licenseHoldReason·licenseReviewedBy·licenseReviewedAt |
| 같은 사업자등록번호의 다른 가게(최대 20곳) | API-013 duplicates |
| 확인·보류 결과 | API-014 outcome·shop |

## 액션

| 액션 | 결과 | 실패 |
| --- | --- | --- |
| 확인됨 | 확인 창(SCR-048#confirm)을 거쳐 '확인됨으로 남겼어요'. '확인 중' 목록에서 빠지고 사장님 화면에 '확인됨' | 다른 운영자가 먼저 정함(409 already_decided)·본 뒤 바뀜(409 version_conflict)은 SCR-048#stale, 없는 가게(404)는 SCR-048#error |
| 보류 | 사유 필드(1~200자)와 '보류로 남기기'가 열림 | 확인된 가게에는 이 버튼이 없음(확인됨을 보류로 바꾸기는 첫 버전에 없음, M7) |
| 보류로 남기기 | '보류로 남겼어요. 사장님께 사유를 알렸어요'. 사장님이 우리 서비스 채널 친구가 아니면 사장님 할 일 목록에 사유가 남음(G4) | 사유가 비었거나 200자를 넘음(422)은 SCR-048#error의 필드 옆, 그 사이 확인됨(409 invalid_state·already_decided)은 SCR-048#stale |
| 신고증 사진 크게 보기 | 사진을 화면 가득 보고 확대함 | 사진 주소가 15분이 지나 열리지 않으면 가게를 다시 불러와 새 주소로 엶 |
| 같은 사업자등록번호의 다른 가게 | 그 가게의 영업 신고 확인(SCR-048) | 그 화면의 상태 |
| 목록으로 | 영업 신고 확인 목록(SCR-047) | 그 화면의 상태 |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이 상태로 오는 응답 |
| --- | --- | --- |
| SCR-048#normal | 확인 중인 가게(pending). 1280: 왼쪽 신고증 사진(누르면 크게), 오른쪽 대조 표(영업 신고 번호·영업 종류·상호·대표자·사업자등록번호·통신판매업 신고번호)와 그 아래 '확인됨'·'보류'. 같은 사업자등록번호의 다른 가게가 있으면 맨 위 배너 '같은 사업자등록번호의 가게가 n곳 더 있어요'와 그 가게들의 링크·상태. 360: 사진 위, 대조 표 아래, 버튼은 아래 고정 | API-013#200:pending |
| SCR-048#loading | 레이아웃은 그대로 두고 데이터 자리에 회색 막대를 보임. 액션 버튼은 누를 수 없음. 사진 자리는 신고증 비율의 회색 | (데이터를 불러오는 동안) |
| SCR-048#on-hold | 보류한 가게(on_hold): '보류' 라벨과 보류 사유·보류한 운영자·시각. 사장님이 신고증을 다시 올리면 '확인 중'으로 돌아옴. 보류 중에도 신고증을 다시 확인해 '확인됨'을 남길 수 있음(SPEC-003) | API-013#200:on_hold |
| SCR-048#error | 없는 가게(404 not_found): '찾을 수 없어요'와 '영업 신고 확인 목록으로' 링크(SCR-047). 보류 사유가 비었거나 200자를 넘음(422 validation_failed): 사유 필드 옆에 '입력한 내용을 확인해 주세요'와 사유, 넣은 글은 그대로 둠. 같은 요청 키로 다른 내용을 보냄(422 idempotency_key_reused): '다시 시도해 주세요'. 새 요청 키로 다시 보냄. 그 밖의 실패: '문제가 생겼어요. 다시 시도해 주세요'와 다시 시도 버튼, 추적 ID | API-013#404:not_found, API-013#default:internal, API-014#404:not_found, API-014#422:validation_failed, API-014#422:idempotency_key_reused, API-014#default:internal |
| SCR-048#permission | 운영자 로그인이 없거나 만료됐거나 운영자 계정이 아님(401 unauthenticated): 운영자 로그인(SCR-046)으로 이동하고, 로그인하면 이 화면으로 돌아옴('다시 로그인해 주세요'). 이동하기 전에도 운영자 기록은 하나도 보이지 않음(G1, 06단계 DEC-11) | API-013#401:unauthenticated, API-014#401:unauthenticated |
| SCR-048#stale | 다른 운영자가 먼저 정함(409 already_decided): '이미 처리됐어요'와 먼저 남은 결정(운영자·시각). 확인된 가게를 보류하려 함(409 invalid_state): '지금 상태에서는 할 수 없어요'와 지금 상태. 본 뒤 바뀜(409 version_conflict, 사장님이 신고증을 다시 올림 등): '그 사이 바뀌었어요. 지금 상태를 확인해 주세요'와 다시 읽은 지금 상태. 쓰던 보류 사유는 버리지 않음 | API-014#409:version_conflict, API-014#409:already_decided, API-014#409:invalid_state |
| SCR-048#submitting | 누른 버튼이 '처리하고 있어요'로 바뀌고 이 화면의 다른 액션과 함께 막힘. 첫 요청을 아직 처리하는 중이면(409 request_in_progress) 1초 뒤 같은 요청 키로 다시 보내고, 결과는 한 번만 보임 | API-014#409:request_in_progress |
| SCR-048#confirm | '확인됨'을 누르면 서버로 보내기 전에 화면이 확인 창을 엶: '확인됨으로 남길까요? 첫 버전에서는 확인됨을 보류로 바꿀 수 없어요'. '확인됨으로 남기기'를 눌러야 보냄. '취소'면 아무것도 바뀌지 않음 | (화면이 여는 확인 창) |
| SCR-048#done | 확인됨(verified): '확인됨으로 남겼어요'와 '목록으로'. 보류(on_hold): '보류로 남겼어요. 사장님께 사유를 알렸어요'. 이미 확인된 가게(unchanged): '이미 확인된 가게예요'. 확인된 가게를 열면 '확인됨'과 확인한 운영자·시각만 보이고 버튼은 없음(M7) | API-014#200:verified, API-014#200:on_hold, API-014#200:unchanged, API-013#200:licenseStatus=verified |
| empty (해당 없음) | 가게 등록 때 신고증을 올려야 가게가 생김(SPEC-002). 빈 영업 신고는 없음 |  |

## 케이스 유형

| 케이스 유형 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 운영자 계정만 확인·보류할 수 있음(SPEC-003). 401은 SCR-048#permission |
| 입력 | 보류 사유 1~200자, 비면 남기지 않음. 틀리면 SCR-048#error의 필드 옆 |
| 대상 | 없는 가게는 SCR-048#error의 '찾을 수 없어요'와 목록 링크 |
| 상태 변화 | 확인된 가게를 다시 확인하면 SCR-048#done의 '이미 확인된 가게예요'. 확인됨을 보류로 바꾸기는 첫 버전에 없음(버튼 없음, 서버도 409 invalid_state로 SCR-048#stale) |
| 반복 | 확인됨·보류로 남기기를 두 번 눌러도 한 번(같은 요청 키, SCR-048#submitting) |
| 동시 변경 | 두 운영자가 같은 가게를 동시에 처리하면 먼저 남긴 것이 이기고 뒤는 SCR-048#stale의 '이미 처리됐어요'(G3) |
| 외부 서비스 | 사장님 알림이 못 가면 사장님 할 일 목록에 보류 사유가 남음(G4). 운영자 화면은 SCR-048#done 그대로 |
| 데이터 노출 | 가게 등록 정보만 보이고 손님·주문 기록은 없음(SPEC-003). 신고증 사진은 15분 동안만 열리는 서명된 주소(06단계 DEC-09) |
| 화면 상태 | 상태마다 360·1280 와이어프레임(`wireframes.html#SCR-048`) |
