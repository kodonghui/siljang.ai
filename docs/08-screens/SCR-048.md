# SCR-048 영업 신고 확인

- 경로: `/operator/shops/:shopId`
- 접근 권한: 운영자
- 상위 화면: SCR-047 영업 신고 확인 목록
- 화면 레이아웃: 운영자 화면(1280 왼쪽 메뉴, 360 위쪽 막대와 메뉴 버튼)
- 플로우: FL-001, FL-002
- 관련 SPEC: SPEC-003, SPEC-078
- API: API-013, API-014, API-082
- 와이어프레임: `wireframes.html#SCR-048`(상태 10개, 360·1280)
- 목업: [`SCR-048-360`](../../research/cake-mockup-2026-11/canvas/project/SCR-048-360.dc.html)(normal·empty·error·confirm), [`SCR-048-1280`](../../research/cake-mockup-2026-11/canvas/project/SCR-048-1280.dc.html)(normal). 캔버스의 '운영자 화면' 페이지([09단계 README](../09-mockup/README.md) 2절)

목적: 운영자가 가게의 신고증 사진과 넣은 영업 신고 번호·영업 종류·상호, 결제 계좌의 예금주가 대표자·상호와 같은지를 직접 대조해 '확인됨'이나 '보류(사유)'를 남깁니다. 확인을 기다리는 사업자 정보 변경 요청이 있으면 증빙 사진과 지금 값·새 값을 보고 먼저 '반영'이나 '보류(이유)'를 남깁니다. 결제 계좌가 없으면 확인됨을 남기지 않고, 보류하면 사장님께 우리 서비스 채널로 사유가 갑니다. (FL-001, FL-002)

## 액션

| 액션 | 결과 | 실패 |
| --- | --- | --- |
| 확인됨 | 확인 창(SCR-048#confirm)을 거쳐 '확인됨으로 남겼어요'. '확인 중' 목록에서 빠지고 사장님 화면에 '확인됨' | 다른 운영자가 먼저 정함(409 already_decided)·본 뒤 바뀜(409 version_conflict)은 SCR-048#stale, 결제 계좌가 없음(409 payment_account_missing)은 SCR-048#empty, 확인을 기다리는 사업자 정보 변경 요청이 있음(409 identity_change_pending)은 SCR-048#stale, 없는 가게(404)는 SCR-048#error |
| 보류 | 사유 필드(1~200자)와 '보류로 남기기'가 열림 | 확인된 가게에는 이 버튼이 없음(확인됨을 보류로 바꾸기는 첫 버전에 없음, M7) |
| 보류로 남기기 | '보류로 남겼어요. 사장님께 사유를 알렸어요'. 사장님이 우리 서비스 채널 친구가 아니면 사장님 할 일 목록에 사유가 남음(G4) | 사유가 비었거나 200자를 넘음(422)은 SCR-048#error의 필드 옆, 그 사이 확인됨(409 invalid_state·already_decided)은 SCR-048#stale |
| 반영(사업자 정보 변경 요청) | 확인 창(SCR-048#confirm)을 거쳐 '반영했어요. 사장님께 알렸어요'. 가게의 상호·대표자·사업자등록번호가 새 값이 되고 예약 링크 페이지·확정 안내가 새 값을 씀(REQ-245) | 다른 운영자가 먼저 정함(409 already_decided)·본 뒤 요청이나 가게의 값이 바뀜(409 version_conflict)은 SCR-048#stale, 없는 요청(404)은 SCR-048#error |
| 보류(사업자 정보 변경 요청) | 이유 필드(1~200자)와 '보류로 남기기'. 남기면 '변경 요청을 보류했어요. 사장님께 이유를 알렸어요' | 이유가 비었거나 200자를 넘음(422)은 SCR-048#error의 필드 옆, 먼저 정해짐(409)은 SCR-048#stale |
| 신고증 사진 크게 보기 | 사진을 화면 가득 보고 확대함. 변경 요청의 증빙 사진도 같음 | 사진 주소가 15분이 지나 열리지 않으면 가게를 다시 불러와 새 주소로 엶 |
| 같은 사업자등록번호의 다른 가게 | 그 가게의 영업 신고 확인(SCR-048) | 그 화면의 상태 |
| 가게 기록 보기 | 그 가게의 주문·상담을 가린 값으로 보는 가게 기록 보기(SCR-050) | 그 화면의 상태 |
| 목록으로 | 영업 신고 확인 목록(SCR-047) | 그 화면의 상태 |

## 케이스 유형

| 케이스 유형 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 운영자 계정만 확인·보류·반영할 수 있음(SPEC-003, SPEC-078). 401은 SCR-048#permission |
| 입력 | 보류 사유와 변경 요청의 보류 이유 1~200자, 비면 남기지 않음. 틀리면 SCR-048#error의 필드 옆. 예금주가 대표자·상호와 다르면 SCR-048#normal의 '예금주가 대표자·상호와 달라요'를 보고 확인됨이나 보류를 정함(SPEC-003) |
| 대상 | 없는 가게는 SCR-048#error의 '찾을 수 없어요'와 목록 링크 |
| 상태 변화 | 결제 계좌가 없으면 SCR-048#empty(확인됨을 남기지 않고 보류는 됨, REQ-197). 확인된 가게를 다시 확인하면 SCR-048#done의 '이미 확인된 가게예요'. 확인됨을 보류로 바꾸기는 첫 버전에 없음(버튼 없음, 서버도 409 invalid_state로 SCR-048#stale). 확인을 기다리는 사업자 정보 변경 요청이 있으면 먼저 반영·보류(확인됨은 SCR-048#stale). 반영은 가게의 세 값이 요청할 때의 값과 같을 때만(아니면 SCR-048#stale) |
| 반복 | 확인됨·보류로 남기기를 두 번 눌러도 한 번(같은 요청 키, SCR-048#submitting) |
| 동시 변경 | 두 운영자가 같은 가게나 같은 변경 요청을 동시에 처리하면 먼저 남긴 것이 이기고 뒤는 SCR-048#stale의 '이미 처리됐어요'(G3) |
| 외부 서비스 | 사장님 알림이 못 가면 사장님 할 일 목록에 보류 사유가 남음(G4). 변경 요청의 반영·보류 알림이 못 가도 사장님은 영업 신고(SCR-035)에서 결과를 봄. 운영자 화면은 SCR-048#done 그대로 |
| 데이터 노출 | 가게 등록 정보와 결제 계좌의 은행·예금주·끝 4자리만. 계좌번호 전체는 운영자에게도 보이지 않음. 손님·주문 기록은 가게 기록 보기(SCR-050)의 가린 값으로만(SPEC-003, SPEC-073). 신고증 사진과 증빙 사진은 15분 동안만 열리는 서명된 주소(06단계 DEC-09) |
| 화면 상태 | 상태마다 360·1280 와이어프레임(`wireframes.html#SCR-048`) |
