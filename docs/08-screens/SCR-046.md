# SCR-046 운영자 로그인

- 경로: `/operator/login`
- 접근 권한: 비로그인
- 상위 화면: 없음(루트)
- 화면 레이아웃: 로그인(가운데 카드)
- 플로우: 플로우 노드 없음(운영자 화면의 진입점이고, FL-001의 운영자 노드는 영업 신고 확인 화면에 있음)
- 관련 SPEC: SPEC-001
- API: API-004
- 와이어프레임: `wireframes.html#SCR-046`(상태 4개, 360·1280)
- 목업: [`SCR-046-360`](../../research/cake-mockup-2026-11/canvas/project/SCR-046-360.dc.html)(normal·error), [`SCR-046-1280`](../../research/cake-mockup-2026-11/canvas/project/SCR-046-1280.dc.html)(normal). 캔버스의 '운영자 화면' 페이지([09단계 README](../09-mockup/README.md) 2절)

목적: 운영자가 이메일·비밀번호·2단계 인증 번호로 들어오고, 영업 신고 확인 목록이나 로그인 전에 열던 운영자 화면으로 갑니다. (플로우 노드 없음: 운영자 화면의 진입점이고, FL-001의 운영자 노드는 영업 신고 확인 화면에 있음)

## 데이터

| 데이터 | 출처 |
| --- | --- |
| 이메일(3~254자)·비밀번호(1~256자)·2단계 인증 번호(6자리) | API-004 요청 email·password·otp |
| 로그인한 운영자 이름 | API-004 operatorId·displayName |

## 액션

| 액션 | 결과 | 실패 |
| --- | --- | --- |
| 로그인 | 영업 신고 확인 목록(SCR-047)이나 로그인 전에 열던 운영자 화면으로 이동 | 맞지 않는 정보(401 operator_login_failed)와 필드 형식 오류(422)는 SCR-046#error, 15분에 5번 넘게 실패(429 too_many_attempts)는 SCR-046#rate-limited |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이 상태로 오는 응답 |
| --- | --- | --- |
| SCR-046#normal | 가운데 '운영자 로그인'과 입력 필드 셋(이메일·비밀번호·2단계 인증 번호), 버튼 '로그인'. 아래 '우리 서비스 운영자용'(사장님 로그인과 헷갈리지 않게). 비밀번호는 마스킹하고, 인증 번호 필드는 숫자 6자리. 로그인 전에 운영자 화면 주소를 열고 왔으면 '로그인하면 보던 화면으로 돌아가요' | API-004#200:signed_in |
| SCR-046#error | 이메일·비밀번호·인증 번호 가운데 맞지 않는 것이 있음(401 operator_login_failed): '로그인 정보가 맞지 않아요'. 어느 필드가 틀렸는지 알리지 않고 입력 필드를 모두 비우고 다시 받음(06단계 계약). 필드가 비었거나 형식이 틀림(422 validation_failed): 필드 옆에 '입력한 내용을 확인해 주세요'와 사유, 넣은 값은 그대로 둠(비밀번호는 비움). 그 밖의 실패: '문제가 생겼어요. 다시 시도해 주세요'와 다시 시도 버튼, 추적 ID | API-004#401:operator_login_failed, API-004#422:validation_failed, API-004#default:internal |
| SCR-046#rate-limited | 로그인 실패가 15분에 5번을 넘음(429 too_many_attempts): '잠시 뒤 다시 로그인해 주세요'. Retry-After 초 동안 로그인 버튼이 막히고 남은 시간을 보임 | API-004#429:too_many_attempts |
| SCR-046#submitting | '로그인'이 '로그인하고 있어요'로 바뀌고 필드와 버튼이 막힘. 결과는 한 번만 보임 | - |
| loading (해당 없음) | 불러올 데이터가 없는 입력 화면. 로그인 결과를 기다리는 동안은 SCR-046#submitting |  |
| empty (해당 없음) | 보일 데이터가 없는 입력 화면 |  |
| permission (해당 없음) | 로그인 전에 여는 화면이라 권한이 필요 없음 |  |
| stale (해당 없음) | 보이는 데이터가 없어 오래될 것이 없음 |  |

## 응답과 상태

06단계 계약(`api/openapi.yaml`)의 응답마다 화면 상태 하나입니다. 오류의 문구는 06단계 오류 코드 표의 '화면에 보이는 말'입니다.

| 응답 | 화면 상태 | 화면에 보이는 것 |
| --- | --- | --- |
| API-004#200:signed_in | SCR-046#normal | 영업 신고 확인 목록(SCR-047)으로 이동 |
| API-004#401:operator_login_failed | SCR-046#error | '로그인 정보가 맞지 않아요' |
| API-004#422:validation_failed | SCR-046#error | '입력한 내용을 확인해 주세요' |
| API-004#429:too_many_attempts | SCR-046#rate-limited | '잠시 뒤 다시 로그인해 주세요' |
| API-004#default:internal | SCR-046#error | '문제가 생겼어요. 다시 시도해 주세요' |

## 케이스 유형

| 케이스 유형 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 운영자 계정(이메일과 2단계 인증)으로만 로그인함. 사장님 카카오 로그인과 섞이지 않음(SPEC-001). 로그인하지 않고 운영자 화면 주소를 열면 이 화면으로 오고, 로그인 뒤 그 주소로 돌아감 |
| 입력 | 이메일 3~254자, 비밀번호 1~256자, 인증 번호 6자리. 비었거나 틀리면 SCR-046#error의 필드 옆 |
| 반복 | 로그인을 두 번 눌러도 요청은 한 번(SCR-046#submitting) |
| 한도 | 15분에 5번 넘게 실패하면 SCR-046#rate-limited(06단계 DEC-16) |
| 외부 서비스 | 운영자 인증 서비스는 개발 전에 고름(OPEN-6). 고른 서비스가 자기 로그인 화면을 쓰면 이 화면은 그 화면으로 보내는 버튼 하나가 되고, 그 서비스가 답하지 않을 때의 오류 상태가 더해짐. 그때 이 정의를 다시 씀 |
| 데이터 노출 | 어느 필드가 틀렸는지 알리지 않음. 비밀번호는 인증 서비스로만 보내고 화면·주소·로그에 남기지 않음(REQ-135) |
| 화면 상태 | 상태마다 360·1280 와이어프레임(`wireframes.html#SCR-046`) |

## 긴 글과 좁은 화면

| 항목 | 한도 | 화면에서 |
| --- | --- | --- |
| 이메일 | 254자 | 필드 안에서 가로 스크롤, 줄바꿈 없음 |
| 돌아갈 주소 | 운영자 화면 주소 | 로그인 뒤 그 주소로 돌아감. 우리 서비스 밖의 주소는 받지 않고 영업 신고 확인 목록으로 |
| 좁은 화면 | 360 | 필드와 버튼은 너비 100%, 버튼 높이 48px. 1280에서는 가운데 너비 400px 카드 |
