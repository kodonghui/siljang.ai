# SCR-024 변경 요청

- 경로: `/owner/change-requests/:changeRequestId`
- 접근 권한: 사장님
- 상위 화면: SCR-021 주문 상세
- 화면 레이아웃: 사장님 화면(1280 왼쪽 메뉴, 360 위쪽 막대와 메뉴 버튼)
- 플로우: FL-008
- 관련 SPEC: SPEC-042, SPEC-043, SPEC-044, SPEC-045
- API: API-062, API-063
- 와이어프레임: `wireframes.html#SCR-024`(상태 9개, 360·1280)
- 목업: [`SCR-024-360`](../../research/cake-mockup-2026-11/canvas/project/SCR-024-360.dc.html)(normal·error·confirm), [`SCR-024-1280`](../../research/cake-mockup-2026-11/canvas/project/SCR-024-1280.dc.html)(normal). 캔버스의 '사장님 화면' 페이지([09단계 README](../09-mockup/README.md) 2절)

목적: 사장님이 손님이 바꾸려는 내용과 지금 주문 버전·운영규정의 변경 마감을 보고 수락하거나 거절합니다. 금액이 오르면 차액 결제 안내로, 그대로거나 내려가면 바로 반영됩니다. 재제작 주문의 변경은 금액이 그대로일 때만 수락합니다(차액 결제·차액 돌려주기 없음). (FL-008)

## 데이터

| 데이터 | 출처 |
| --- | --- |
| 주문번호, 변경 요청이 본 버전과 지금 주문 버전 | API-062 order·baseVersion·orderVersion |
| 바꾸려는 내용(크기·맛·디자인·추가 옵션·도안 메모·문구·색·픽업 일시·퀵)과 새 픽업 일시, 휴무·마감된 날이면 '받을지 정해야 함' | API-062 changes·newPickupAt·needsOwnerDay |
| 변경 마감 시각 | API-062 changeDeadlineAt |
| 상태(요청됨·차액 결제 기다림·반영됨·거절됨·차액 없어 닫힘·답 없어 닫힘·이전 버전을 보고 만든 변경·취소로 닫힘)·금액 변화·거절 사유·반영 버전·차액 결제 안내 | API-062 status·amountDelta·rejectReason·appliedVersion·differencePayment |

## 액션

| 액션 | 결과 | 실패 |
| --- | --- | --- |
| 수락 | 금액 변화(올라가면 +, 내려가면 -, 그대로 0)를 넣고 수락. 그대로·내려감이면 바로 반영 '수락해 반영했어요(버전 {n})'(내려가면 환불 결정 할 일이 생김), 올라가면 '수락했어요. 손님에게 차액 결제 안내를 보냈어요' | 새 날짜에 남은 자리가 없거나 휴무일이면 SCR-024#confirm, 이전 버전을 보고 만든 변경(409 stale_change)·손님이 취소함(order_cancelled)·이미 답함(already_decided)·변경 마감까지 답이 없어 닫힘(invalid_state)·본 뒤 바뀜(version_conflict)은 SCR-024#stale, 금액 변화가 한도 밖이거나 재제작 주문인데 0원이 아님(422 not_allowed)은 SCR-024#error의 필드 옆 |
| 거절 | 사유(0~200자)를 넣고 거절: '거절했어요. 손님에게 알렸어요'. 주문은 그대로 | 이미 답함·취소됨은 SCR-024#stale |
| 주문 상세 보기 | 주문 상세(SCR-021) | 그 화면의 상태 |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이 상태로 오는 응답 |
| --- | --- | --- |
| SCR-024#normal | 위에 '변경 요청 · 주문 {orderNo}'와 '변경 마감 M월 D일 HH:MM까지'(그때까지 답하지 않으면 '답 없어 닫힘'으로 닫히고 주문은 원래대로, REQ-214). 바뀌는 항목마다 '지금 → 바꾸려는 값'(버전 n 기준). 새 날짜가 휴무·마감이면 '이날은 받을지 정해야 해요'. 금액 변화 필드(원), '수락'·'거절' | API-062#200:requested |
| SCR-024#loading | 레이아웃은 그대로 두고 데이터 자리에 회색 막대를 보임. 액션 버튼은 누를 수 없음 | (데이터를 불러오는 동안) |
| SCR-024#error | 없거나 다른 가게의 변경 요청(404 not_found): '찾을 수 없어요'와 '주문 목록으로' 링크(SCR-020). 다른 가게 기록이 있는지는 말하지 않음(G1). 입력이 한도나 형식에 맞지 않음(422 validation_failed): 필드 옆에 '입력한 내용을 확인해 주세요'와 필드마다의 사유. 넣은 값은 그대로 둠. 재제작 주문의 변경에 0원이 아닌 금액 변화(422 not_allowed): 금액 변화 필드 옆에 '재제작 주문은 금액을 바꿀 수 없어요. 0원으로 수락하거나 거절해 주세요'(SPEC-042). 같은 요청 키로 다른 내용을 보냄(422 idempotency_key_reused): '다시 시도해 주세요'. 새 요청 키로 다시 보냄. 그 밖의 실패: '문제가 생겼어요. 다시 시도해 주세요'와 다시 시도 버튼, 추적 ID | API-062#404:not_found, API-062#default:internal, API-063#404:not_found, API-063#422:validation_failed, API-063#422:idempotency_key_reused, API-063#default:internal |
| SCR-024#permission | 로그인이 없거나 만료됨(401 unauthenticated): 로그인 화면으로 이동하고, 로그인하면 이 화면으로 돌아옴('다시 로그인해 주세요') | API-062#401:unauthenticated, API-063#401:unauthenticated |
| SCR-024#stale | 이전 버전을 보고 만든 변경(stale_change): '그 사이 주문이 바뀌어 이 변경은 반영할 수 없어요'와 지금 버전. 할 일 종류 '이전 버전을 보고 만든 변경'으로 열면 처음부터 이 모습. 손님이 취소함(order_cancelled): '그 사이 주문이 취소됐어요'. 이미 답함(already_decided): '이미 처리됐어요'. 변경 마감까지 답이 없어 닫힘(closed_no_answer, 수락·거절하면 409 invalid_state): '변경 마감까지 답이 없어 닫혔어요. 주문은 원래대로예요'. 본 뒤 바뀜(version_conflict): '그 사이 바뀌었어요. 지금 상태를 확인해 주세요'와 다시 읽은 지금 상태 | API-062#200:closed_no_answer, API-063#409:version_conflict, API-063#409:already_decided, API-063#409:order_cancelled, API-063#409:stale_change, API-063#409:invalid_state |
| SCR-024#submitting | 누른 버튼이 '처리하고 있어요'로 바뀌고 이 화면의 다른 액션과 함께 막힘. 첫 요청을 아직 처리하는 중이면(409 request_in_progress) 1초 뒤 같은 요청 키로 다시 보내고, 결과는 한 번만 보임 | API-063#409:request_in_progress |
| SCR-024#confirm | 저장하기 전에 사장님 확인이 필요함(409 confirmation_required, overbooking): 확인 창에 '그날 남은 자리가 없어요. 추가로 받을까요?'. '추가로 받기'를 누르면 confirm에 overbooking를 넣고 새 요청 키로 다시 보냄. '취소'면 아무것도 바뀌지 않음. 새 날짜에 하루 최대 개수를 초과해 자리를 잡음(마감 후 추가 수락). 새 날짜가 휴무일이면(closed_day) 같은 창에 '휴무일이에요. 이날로 정할까요?'를 보이고, 확인하면 마감 후 추가 수락으로 잡음(REQ-221) | API-063#409:confirmation_required |
| SCR-024#awaiting-payment | 차액 결제를 기다림(awaiting_difference): '차액 결제를 기다리고 있어요'와 차액·차액 결제 기한(결제 기한과 변경 마감 가운데 이른 때). 결정 버튼 없음. 차액 결제가 확인되면 입금 대조(SCR-029)에서 반영 | API-062#200:awaiting_difference, API-063#200:awaiting_difference |
| SCR-024#done | 반영됨(applied)·거절됨(rejected): 결과 문구와 읽기 전용 내용. 차액이 기한까지 오지 않아 닫힘(closed_no_difference): '차액이 기한까지 오지 않아 닫혔어요'(원래 주문대로) | API-062#200:closed_no_difference, API-063#200:applied, API-063#200:rejected |
| empty (해당 없음) | 변경 요청은 바꾸려는 내용이 있을 때만 생김 |  |

## 케이스 유형

| 케이스 유형 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 그 가게 변경 요청만(SCR-024#error, G1) |
| 입력 | 금액 변화 -1,000만~1,000만 원(재제작 주문의 변경은 0원만, SPEC-042, SPEC-060), 거절 사유 0~200자. 틀리면 SCR-024#error의 필드 옆 |
| 대상 | 없는 변경 요청은 SCR-024#error |
| 상태 변화 | 차액을 기다리면 SCR-024#awaiting-payment, 차액 없어 닫힘·반영·거절은 SCR-024#done, 손님 취소·이미 답함·변경 마감까지 답이 없어 닫힘은 SCR-024#stale(REQ-214) |
| 반복 | 같은 변경을 두 번 반영하지 않음(같은 요청 키, SCR-024#submitting) |
| 동시 변경 | 변경 요청의 버전이 지금 주문 버전과 다르면 반영하지 않음(SCR-024#stale, REQ-133) |
| 데이터 노출 | 변경 요청 내용은 그 가게 사장님 화면에만 |
| 화면 상태 | 상태마다 360·1280 와이어프레임(`wireframes.html#SCR-024`) |
