# SCR-024 변경 요청

- 경로: `/owner/change-requests/:changeRequestId`
- 접근 권한: 사장님
- 상위 화면: SCR-021 주문 상세
- 화면 레이아웃: 사장님 화면(1280 왼쪽 메뉴, 360 위쪽 막대와 메뉴 버튼)
- 플로우: FL-008
- 관련 SPEC: SPEC-042, SPEC-043, SPEC-044, SPEC-045
- API: API-062, API-063
- 와이어프레임: `wireframes.html#SCR-024`(상태 10개, 360·1280)
- 목업: [`SCR-024-360`](../../research/cake-mockup-2026-11/canvas/project/SCR-024-360.dc.html)(normal·error·confirm), [`SCR-024-1280`](../../research/cake-mockup-2026-11/canvas/project/SCR-024-1280.dc.html)(normal). 캔버스의 '사장님 화면' 페이지([09단계 README](../09-mockup/README.md) 2절)

목적: 사장님이 손님이 바꾸려는 내용과 지금 주문 버전·금액·운영규정의 변경 마감을 보고 수락하거나 거절합니다. 수락은 금액을 '그대로·올라감·내려감'으로 고르고 차이 금액을 양수로 넣으며, 수락 전에 결과 한 줄을 봅니다. 금액이 오르면 손님이 새 금액을 확인한 뒤 차액 결제 안내로, 그대로거나 내려가면 바로 반영됩니다. 재제작 주문의 변경은 금액이 그대로일 때만 수락합니다(차액 결제·차액 돌려주기 없음). (FL-008)

## 액션

| 액션 | 결과 | 실패 |
| --- | --- | --- |
| 수락 | 금액을 '그대로'·'올라감'·'내려감' 가운데 하나로 고르고, 올라감·내려감이면 차이 금액(양수)을 넣고 수락. 고르는 동안 결과 한 줄을 보임: 그대로 '바로 반영해요', 내려감 '바로 반영하고 5,000원을 돌려줄 환불을 정할 일이 생겨요', 올라감 '손님이 새 금액 56,000원(차액 20,000원)을 확인한 뒤 차액 결제 안내가 가요. 변경 마감까지 N시간'. 그대로·내려감은 바로 반영 '수락해 반영했어요(버전 {n})', 올라감은 '수락했어요. 손님이 새 금액을 확인하면 차액 결제 안내가 가요' | 새 날짜에 남은 자리가 없거나 휴무일이면 SCR-024#confirm, 손님이 취소함(409 order_cancelled)·이미 답함(already_decided)·변경 마감이 지남(invalid_state, 답 없어 닫힘)·본 뒤 바뀜(version_conflict)은 SCR-024#stale, 금액 방향을 고르지 않음·차이 금액이 없거나 한도 밖·재제작 주문인데 그대로가 아님(422)은 SCR-024#error의 필드 옆 |
| 거절 | 사유(0~200자)를 넣고 거절: '거절했어요. 손님에게 알렸어요'. 주문은 그대로 | 이미 답함·취소됨은 SCR-024#stale |
| 주문 상세 보기 | 주문 상세(SCR-021) | 그 화면의 상태 |

| SCR-024#stale | 손님이 취소함(order_cancelled): '그 사이 주문이 취소됐어요'. 이미 답함(already_decided): '이미 처리됐어요'. 변경 마감이 지남(closed_no_answer, 닫는 일이 아직 돌지 않았어도 수락·거절하면 409 invalid_state): '변경 마감까지 답이 없어 닫혔어요. 주문은 원래대로예요'. 본 뒤 바뀜(version_conflict): '그 사이 바뀌었어요. 지금 상태를 확인해 주세요'와 다시 읽은 지금 상태 | API-062#200:closed_no_answer, API-063#409:version_conflict, API-063#409:already_decided, API-063#409:order_cancelled, API-063#409:invalid_state |
| SCR-024#submitting | 누른 버튼이 '처리하고 있어요'로 바뀌고 이 화면의 다른 액션과 함께 막힘. 첫 요청을 아직 처리하는 중이면(409 request_in_progress) 1초 뒤 같은 요청 키로 다시 보내고, 결과는 한 번만 보임 | API-063#409:request_in_progress |

## 케이스 유형

| 케이스 유형 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 그 가게 변경 요청만(SCR-024#error, G1) |
| 입력 | 금액은 '그대로·올라감·내려감' 가운데 하나를 꼭 고르고, 부호를 넣는 필드가 없음(DEC-23). 차이 금액은 1원 이상의 원 단위 양수로 내려감은 지금 금액 이하, 올라감은 새 금액이 1,000만 원 이하(재제작 주문은 그대로만, SPEC-042, SPEC-060). 거절 사유 0~200자. 틀리면 SCR-024#error의 필드 옆 |
| 대상 | 없는 변경 요청은 SCR-024#error |
| 상태 변화 | 차액을 기다리면 SCR-024#awaiting-payment(손님이 새 금액을 확인하기 전 포함), 차액 없어 닫힘(손님이 받지 않음·기한 지남·변경 닫기)·반영·거절은 SCR-024#done, 손님 취소·이미 답함·변경 마감이 지남은 SCR-024#stale(REQ-214, REQ-233) |
| 반복 | 같은 변경을 두 번 반영하지 않음(같은 요청 키, SCR-024#submitting) |
| 동시 변경 | 한 주문에 열린 변경 요청은 하나라 그동안 주문 버전이 바뀌지 않고, 반영은 본 버전 위에서만 됨(REQ-133, 변경 요청 카드와 데이터베이스가 지킴). 손님 취소와 동시에 일어나면 먼저 남긴 것이 이기고 뒤는 SCR-024#stale(G3) |
