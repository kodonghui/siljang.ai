# SCR-026 환불 송금

- 경로: `/owner/refunds/:refundId`
- 접근 권한: 사장님
- 상위 화면: SCR-021 주문 상세
- 화면 레이아웃: 사장님 화면(1280 왼쪽 메뉴, 360 위쪽 막대와 메뉴 버튼)
- 플로우: FL-009, FL-011
- 관련 SPEC: SPEC-047, SPEC-049
- API: API-060, API-061
- 와이어프레임: `wireframes.html#SCR-026`(상태 8개, 360·1280)
- 목업: [`SCR-026-360`](../../research/cake-mockup-2026-11/canvas/project/SCR-026-360.dc.html)(normal·empty·error), [`SCR-026-1280`](../../research/cake-mockup-2026-11/canvas/project/SCR-026-1280.dc.html)(normal). 캔버스의 '사장님 화면' 페이지([09단계 README](../09-mockup/README.md) 2절)

목적: 사장님이 정한 환불 금액과 손님 환불 계좌(원래 값)를 보고 은행 앱으로 보내거나 카드 결제를 취소한 뒤 '보냄'을 누릅니다. (FL-009, FL-011)

## 데이터

| 데이터 | 출처 |
| --- | --- |
| 주문번호·원인·결정(전액·일부·없음)·금액·계산값·근거·다르게 정한 사유 | API-060 |
| 손님 환불 계좌(은행·계좌번호·예금주, 원래 값) | API-060 refundAccount |
| 받는 방법·정한 시각·보낸 시각 | API-060 method·decidedAt·sentAt |

## 액션

| 액션 | 결과 | 실패 |
| --- | --- | --- |
| 보냄 | 보낸 방법(계좌 이체·카드 결제 취소)을 고르고 '보냄': '보냄을 남겼어요. 손님에게 환불 안내를 보냈어요'. 상담에서 계좌를 받지 못했으면 사장님이 아는 계좌를 넣을 수 있음 | 계좌 형식이 틀림(422)은 SCR-026#error의 필드 옆, 이미 보냄(200 unchanged)은 SCR-026#done, 지금 상태에서 할 수 없음(invalid_state)·본 뒤 바뀜은 SCR-026#stale |
| 계좌번호 복사 | 클립보드에 복사하고 '복사했어요' | 복사가 막힌 브라우저면 계좌번호를 선택해 두고 '길게 눌러 복사해 주세요' |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이 상태로 오는 응답 |
| --- | --- | --- |
| SCR-026#normal | 환불 금액(크게)·받는 방법·손님 환불 계좌(은행·계좌번호·예금주)와 '복사', 보낸 방법 고르기와 '보냄'. 계좌는 이 화면의 이 환불에만 원래 값으로 보임(R19). '우리는 돈을 옮기지 않아요. 가게 계좌에서 보내 주세요' | API-060#200:with_account |
| SCR-026#loading | 레이아웃은 그대로 두고 데이터 자리에 회색 막대를 보임. 액션 버튼은 누를 수 없음 | (데이터를 불러오는 동안) |
| SCR-026#empty | 손님 환불 계좌를 아직 받지 못함(decided): 계좌 자리에 '상담에서 계좌를 받는 중이에요'와 '내가 아는 계좌 넣기'. 카드 결제 취소는 계좌 없이 '보냄' | API-060#200:decided |
| SCR-026#error | 없거나 다른 가게의 환불(404 not_found): '찾을 수 없어요'와 '주문 목록으로' 링크(SCR-020). 다른 가게 기록이 있는지는 말하지 않음(G1). 입력이 한도나 형식에 맞지 않음(422 validation_failed): 필드 옆에 '입력한 내용을 확인해 주세요'와 필드마다의 사유. 넣은 값은 그대로 둠. 같은 요청 키로 다른 내용을 보냄(422 idempotency_key_reused): '다시 시도해 주세요'. 새 요청 키로 다시 보냄. 그 밖의 실패: '문제가 생겼어요. 다시 시도해 주세요'와 다시 시도 버튼, 추적 ID | API-060#404:not_found, API-060#default:internal, API-061#404:not_found, API-061#422:validation_failed, API-061#422:idempotency_key_reused, API-061#default:internal |
| SCR-026#permission | 로그인이 없거나 만료됨(401 unauthenticated): 로그인 화면으로 이동하고, 로그인하면 이 화면으로 돌아옴('다시 로그인해 주세요') | API-060#401:unauthenticated, API-061#401:unauthenticated |
| SCR-026#stale | 지금 상태에서 할 수 없음(invalid_state): '지금 상태에서는 할 수 없어요'. 본 뒤 바뀜(version_conflict, 손님이 환불 계좌를 막 보냄 등): '그 사이 바뀌었어요. 지금 상태를 확인해 주세요'와 다시 읽은 지금 상태 | API-061#409:version_conflict, API-061#409:invalid_state |
| SCR-026#submitting | 누른 버튼이 '처리하고 있어요'로 바뀌고 이 화면의 다른 액션과 함께 막힘. 첫 요청을 아직 처리하는 중이면(409 request_in_progress) 1초 뒤 같은 요청 키로 다시 보내고, 결과는 한 번만 보임 | API-061#409:request_in_progress |
| SCR-026#done | 보냄(sent): 보낸 시각·방법을 읽기 전용으로. 이미 보낸 환불(unchanged)은 '이미 보냄으로 남긴 환불이에요'. 다시 열어도 이 모습 | API-060#200:sent, API-061#200:sent, API-061#200:unchanged |

## 케이스 유형

| 케이스 유형 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 그 가게 환불만(SCR-026#error, G1) |
| 입력 | 은행 1~30자, 계좌번호는 숫자와 하이픈 1~40자, 예금주 1~30자. 틀리면 SCR-026#error |
| 대상 | 없는 환불은 SCR-026#error |
| 상태 변화 | 계좌를 받기 전은 SCR-026#empty, 이미 보낸 환불은 SCR-026#done |
| 반복 | 보냄을 두 번 눌러도 한 번(같은 요청 키, SCR-026#submitting) |
| 동시 변경 | 본 뒤 계좌가 들어오면 SCR-026#stale에서 다시 읽음 |
| 데이터 노출 | 손님 계좌는 이 화면의 이 환불에만 원래 값(R19, REQ-136). AI·로그·다른 화면에는 없음 |
| 화면 상태 | 상태마다 360·1280 와이어프레임(`wireframes.html#SCR-026`) |
