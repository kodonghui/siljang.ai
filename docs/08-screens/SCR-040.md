# SCR-040 결제 수단

- 경로: `/owner/payment-destination`
- 접근 권한: 사장님
- 상위 화면: SCR-034 가게 설정
- 화면 레이아웃: 사장님 화면(1280 왼쪽 메뉴, 360 위쪽 막대와 메뉴 버튼)
- 플로우: FL-001
- 관련 SPEC: SPEC-006
- API: API-024, API-025
- 와이어프레임: `wireframes.html#SCR-040`(상태 9개, 360·1280)

목적: 사장님이 결제를 받을 가게 명의 계좌(은행·계좌번호·예금주)와 있으면 카드 결제 링크를 등록하거나 바꿉니다. 결제 수단이 없으면 예약 링크가 나오지 않습니다. (FL-001)

## 데이터

| 데이터 | 출처 |
| --- | --- |
| 은행·계좌번호(숫자와 '-' 10~16자리)·예금주·예금주가 상호·대표자와 다른 것을 확인했는지 | API-024 bankName·accountNumber·holderName·holderMismatchConfirmed |
| 카드 결제 링크(https, 선택) | API-024 cardPaymentUrl |
| 등록 시각 | API-024 createdAt |
| 저장 결과 | API-025 outcome·paymentDestination |

## 액션

| 액션 | 결과 | 실패 |
| --- | --- | --- |
| 저장 | '저장했어요. 이제부터 나가는 결제 안내에 이 계좌를 써요'. 이미 나간 결제 안내는 그대로 | 예금주가 상호·대표자와 다르면 SCR-040#confirm, 계좌번호·링크 형식(422)은 SCR-040#error의 필드 옆, 본 뒤 바뀜은 SCR-040#stale |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이 상태로 오는 응답 |
| --- | --- | --- |
| SCR-040#normal | 필드: 은행(고르기)·계좌번호·예금주·카드 결제 링크(선택), '저장'. 설명 '결제 안내에는 이 계좌와 링크만 나가요. 우리 회사 계좌는 쓰지 않아요'(REQ-079) | API-024#200:account |
| SCR-040#loading | 레이아웃은 그대로 두고 데이터 자리에 회색 막대를 보임. 액션 버튼은 누를 수 없음 | (데이터를 불러오는 동안) |
| SCR-040#empty | 결제 수단을 아직 등록하지 않음(404 not_set): 빈 필드와 위에 '결제 수단을 등록해야 예약 링크가 나와요'(REQ-164) | API-024#404:not_set |
| SCR-040#error | 입력이 한도나 형식에 맞지 않음(422 validation_failed): 필드 옆에 '입력한 내용을 확인해 주세요'와 필드마다의 사유. 넣은 값은 그대로 둠(계좌번호는 숫자와 '-' 10~16자리, 예금주 1~30자, 링크는 https 주소만). 같은 요청 키로 다른 내용을 보냄(422 idempotency_key_reused): '다시 시도해 주세요'. 새 요청 키로 다시 보냄. 그 밖의 실패: '문제가 생겼어요. 다시 시도해 주세요'와 다시 시도 버튼, 추적 ID | API-024#default:internal, API-025#422:validation_failed, API-025#422:idempotency_key_reused, API-025#default:internal |
| SCR-040#permission | 로그인이 없거나 만료됨(401 unauthenticated): 로그인 화면으로 이동하고, 로그인하면 이 화면으로 돌아옴('다시 로그인해 주세요'). 로그인한 사장님에게 가게가 아직 없음(404 shop_not_registered): 가게가 없으면 가게 등록(SCR-015)으로 보냄('가게를 먼저 등록해 주세요') | API-024#401:unauthenticated, API-024#404:shop_not_registered, API-025#401:unauthenticated, API-025#404:shop_not_registered |
| SCR-040#stale | 다른 기기에서 먼저 저장함(409 version_conflict): '그 사이 바뀌었어요. 지금 상태를 확인해 주세요'와 다시 읽은 지금 상태 | API-025#409:version_conflict |
| SCR-040#submitting | 누른 버튼이 '처리하고 있어요'로 바뀌고 이 화면의 다른 액션과 함께 막힘. 첫 요청을 아직 처리하는 중이면(409 request_in_progress) 1초 뒤 같은 요청 키로 다시 보내고, 결과는 한 번만 보임 | API-025#409:request_in_progress |
| SCR-040#confirm | 저장하기 전에 사장님 확인이 필요함(409 confirmation_required, holder_mismatch): 확인 창에 '예금주가 상호·대표자와 달라요. 가게 명의 계좌가 맞나요?'. '가게 명의가 맞아요'를 누르면 confirm에 holder_mismatch를 넣고 새 요청 키로 다시 보냄. '취소'면 아무것도 바뀌지 않음. 답을 남기고 저장함(SPEC-006) | API-025#409:confirmation_required |
| SCR-040#done | 저장(created): '저장했어요. 이제부터 나가는 결제 안내에 이 계좌를 써요'. 바뀐 것 없음(unchanged): '바뀐 것이 없어요' | API-025#200:created, API-025#200:unchanged |

## 케이스 유형

| 케이스 유형 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 로그인한 사장님의 가게만. 401은 SCR-040#permission |
| 입력 | 계좌번호·예금주·https 링크 형식. 틀리면 SCR-040#error |
| 대상 | 가게가 없으면 SCR-040#permission, 등록 전이면 SCR-040#empty |
| 상태 변화 | 예금주가 다르면 SCR-040#confirm. 바꾼 계좌는 그 뒤 결제 안내부터 |
| 반복 | 저장을 두 번 눌러도 한 번(SCR-040#done의 unchanged) |
| 동시 변경 | 다른 기기의 저장과 동시에 일어나면 SCR-040#stale |
| 데이터 노출 | 계좌번호는 이 화면과 그 가게 손님의 결제 안내에만, AI 모델로는 마스킹해서(REQ-136, DEC-19) |
| 빈 응답·끊긴 응답 | 등록 전이면 SCR-040#empty |
| 화면 상태 | 상태마다 360·1280 와이어프레임(`wireframes.html#SCR-040`) |
