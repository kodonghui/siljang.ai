# SCR-021 주문 상세

- 경로: `/owner/orders/:orderId`
- 접근 권한: 사장님
- 상위 화면: SCR-020 주문 목록
- 화면 레이아웃: 사장님 화면(1280 왼쪽 메뉴, 360 위쪽 막대와 메뉴 버튼)
- 플로우: FL-007, FL-009
- 관련 SPEC: SPEC-045, SPEC-048, SPEC-068
- API: API-045, API-048
- 와이어프레임: `wireframes.html#SCR-021`(상태 8개, 360·1280)
- 목업: [`SCR-021-360`](../../research/cake-mockup-2026-11/canvas/project/SCR-021-360.dc.html)(normal·error·confirm), [`SCR-021-1280`](../../research/cake-mockup-2026-11/canvas/project/SCR-021-1280.dc.html)(normal). 캔버스의 '사장님 화면' 페이지([09단계 README](../09-mockup/README.md) 2절)

목적: 사장님이 주문 내용(버전)·결제·제작·변경·신고·환불을 한 화면에서 보고, 받기 전 주문을 가게 사정으로 취소합니다. (FL-007, FL-009)

| 참고 사진, 견적, 그날 자리(하루 최대 개수·잡힌 자리·남은 자리) | API-045 referencePhotos·quote·day |

## 액션

| 액션 | 결과 | 실패 |
| --- | --- | --- |
| 가게 사정 취소 | SCR-021#confirm에서 사유(1~200자)를 넣고 확인하면 주문을 '가게 사정으로 취소됨'으로 두고 자리를 풂. 받은 금액이 있으면 환불 결정(SCR-025)으로, 없으면 '취소했어요. 손님에게 알렸어요' | 받은 주문·이미 취소된 주문(409 invalid_state·already_decided)과 본 뒤 바뀜(409 version_conflict)은 SCR-021#stale, 사유가 비거나 넘음(422)은 SCR-021#error의 필드 옆 |
| 결제 안내·변경 요청·환불·문제 신고 누르기 | 입금 대조(SCR-029)·변경 요청(SCR-024)·환불 송금(SCR-026)·문제 신고(SCR-027) | 그 화면의 상태 |
| 이전 버전 보기 | 그 버전의 주문 내용, 바뀐 항목은 굵게 | 해당 없음(받은 데이터 안에서 바꿔 보임) |
| 상담 대화 보기 | 상담 대화(SCR-018) | 지운 상담이면 그 화면의 empty |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이 상태로 오는 응답 |
| --- | --- | --- |
| SCR-021#normal | 위에 주문번호·상태 라벨·픽업 일시·금액·버전. 구역 넷: 주문 내용(현재 버전, 알레르기 정보에 동의하지 않은 주문은 '알레르기: 동의 안 함(빼야 할 재료만 받음)', '이전 버전 보기'), 결제(안내마다 종류·금액·기한·상태와 확인된 결제), 제작(맞춤 재료 주문·제작 시작·완성 시각, 완성 사진마다 '게시 동의'·'동의 안 함'·'철회'), 변경·신고·환불. 받기 전 주문이면 맨 아래 '가게 사정 취소'. 재제작 주문은 '재제작 · 원래 주문 {orderNo}'와 0원 | API-045#200:custom_requested, API-045#200:confirmed, API-045#200:changed, API-045#200:remake |
| SCR-021#loading | 레이아웃은 그대로 두고 데이터 자리에 회색 막대를 보임. 액션 버튼은 누를 수 없음. 구역 넷의 제목은 바로 보이고 내용 자리에 회색 막대 | (데이터를 불러오는 동안) |
| SCR-021#error | 없거나 다른 가게의 주문(404 not_found): '찾을 수 없어요'와 '주문 목록으로' 링크(SCR-020). 다른 가게 기록이 있는지는 말하지 않음(G1). 입력이 한도나 형식에 맞지 않음(422 validation_failed): 필드 옆에 '입력한 내용을 확인해 주세요'와 필드마다의 사유. 넣은 값은 그대로 둠. 같은 요청 키로 다른 내용을 보냄(422 idempotency_key_reused): '다시 시도해 주세요'. 새 요청 키로 다시 보냄. 그 밖의 실패: '문제가 생겼어요. 다시 시도해 주세요'와 다시 시도 버튼, 추적 ID | API-045#404:not_found, API-045#default:internal, API-048#404:not_found, API-048#422:validation_failed, API-048#422:idempotency_key_reused, API-048#default:internal |
| SCR-021#permission | 로그인이 없거나 만료됨(401 unauthenticated): 로그인 화면으로 이동하고, 로그인하면 이 화면으로 돌아옴('다시 로그인해 주세요') | API-045#401:unauthenticated, API-048#401:unauthenticated |
| SCR-021#stale | 본 뒤 주문이 바뀜(409 version_conflict), 받은 주문이거나 취소할 수 없는 상태(409 invalid_state), 이미 다른 이유로 취소됨(409 already_decided): '그 사이 바뀌었어요. 지금 상태를 확인해 주세요'와 다시 읽은 지금 상태. 사진 주소(15분)가 지났으면 '다시 불러오기' | API-048#409:version_conflict, API-048#409:invalid_state, API-048#409:already_decided |
| SCR-021#confirm | 가게 사정 취소를 누르면 확인 창: 사유 필드(1~200자)와 '받은 금액 {n}원은 전액 환불 계산값으로 잡혀요'. '취소하기'를 눌러야 보냄 | (화면이 여는 확인 창) |
| SCR-021#submitting | 누른 버튼이 '처리하고 있어요'로 바뀌고 이 화면의 다른 액션과 함께 막힘. 첫 요청을 아직 처리하는 중이면(409 request_in_progress) 1초 뒤 같은 요청 키로 다시 보내고, 결과는 한 번만 보임 | API-048#409:request_in_progress |
| SCR-021#done | 취소 결과: 받은 금액이 있으면(cancelled_paid) '취소했어요. 받은 금액의 환불을 정해 주세요' 뒤 환불 결정(SCR-025)으로 이동, 없으면(cancelled_unpaid) '취소했어요. 손님에게 알렸어요'와 '가게 사정으로 취소됨' 상태로 읽기 전용. 이미 가게 사정으로 취소된 주문(unchanged)은 그 문구만 | API-048#200:cancelled_paid, API-048#200:cancelled_unpaid, API-048#200:unchanged |
| empty (해당 없음) | 주문은 손님이 주문 요청을 남겨야 생김. 빈 주문은 없음(구역마다 '아직 없어요'는 normal 안에서 보임) |  |

## 케이스 유형

| 케이스 유형 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 그 가게 주문만. 다른 가게 주문 ID는 '찾을 수 없어요'(SCR-021#error, G1) |
| 입력 | 취소 사유 1~200자. 틀리면 SCR-021#error의 필드 옆 |
| 대상 | 없는 주문과 끝나고 30일이 지나 보관 기록이 된 주문(SPEC-065, REQ-187)은 SCR-021#error와 주문 목록 링크 |
| 상태 변화 | 받은 주문·이미 취소된 주문은 '가게 사정 취소'가 없고, 그 사이 바뀌었으면 SCR-021#stale. 이미 가게 사정으로 취소됐으면 SCR-021#done |
| 반복 | 취소를 두 번 눌러도 한 번(같은 요청 키, SCR-021#submitting) |
| 동시 변경 | 손님 취소·결제 확인과 동시에 일어나면 먼저 남긴 것이 이기고 뒤는 SCR-021#stale(G3) |
| 데이터 노출 | 손님 연락처·알레르기 답은 이 가게 사장님에게만. 다른 가게 존재는 알리지 않음 |
| 화면 상태 | 상태마다 360·1280 와이어프레임(`wireframes.html#SCR-021`) |
