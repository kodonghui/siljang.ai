# SCR-034 가게 설정

- 경로: `/owner/shop`
- 접근 권한: 사장님
- 상위 화면: SCR-014 사장님 로그인
- 화면 레이아웃: 사장님 화면(1280 왼쪽 메뉴, 360 위쪽 막대와 메뉴 버튼)
- 플로우: FL-001, FL-002
- 관련 SPEC: SPEC-009, SPEC-017, SPEC-024, SPEC-025, SPEC-052, SPEC-077
- API: API-009, API-010, API-003
- 와이어프레임: `wireframes.html#SCR-034`(상태 7개, 360·1280)
- 목업: [`SCR-034-360`](../../research/cake-mockup-2026-11/canvas/project/SCR-034-360.dc.html)(normal·error), [`SCR-034-1280`](../../research/cake-mockup-2026-11/canvas/project/SCR-034-1280.dc.html)(normal). 캔버스의 '사장님 화면' 페이지([09단계 README](../09-mockup/README.md) 2절)

목적: 사장님이 가게 이름·연락처·사업장 주소·전자우편주소·픽업 장소·통신판매업 신고번호와 기관(또는 면제 사유), 완성 사진 보내기, 문의 끊김 시간, 사장님 답 기다리는 시간, 하루 AI 비용 한도를 바꾸고(상호·대표자·사업자등록번호는 영업 신고 화면의 변경 요청으로), 다른 설정 화면으로 가거나 로그아웃합니다. (FL-001, FL-002)

## 액션

| 액션 | 결과 | 실패 |
| --- | --- | --- |
| 저장 | 바꾼 필드만 보냄: '저장했어요'(바뀐 것이 없으면 '바뀐 것이 없어요'). 예약 링크 페이지와 그 뒤 나가는 안내가 바뀐 값을 씀(REQ-244) | 한도 밖·형식(422)은 SCR-034#error의 필드 옆(통신판매업 신고번호와 기관은 함께 있거나 함께 비어야 함), 본 뒤 바뀜(409 version_conflict)은 SCR-034#stale |
| 변경 요청(사업자 정보 옆) | 영업 신고(SCR-035)의 사업자 정보 변경 요청 | 그 화면의 상태 |
| 설정 목록(영업 신고·가격표와 도안·운영규정·결제 수단·카카오톡 채널 연결·장부 연결·예약 링크·포트폴리오·후기) | SCR-035·036·038·040·041·042·043·044·045 | 그 화면의 상태 |
| 로그아웃 | 로그인 화면(SCR-014)으로 이동. 두 번 눌러도 같음 | 실패(default)는 SCR-034#error |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이 상태로 오는 응답 |
| --- | --- | --- |
| SCR-034#normal | 1280: 가운데 위 설정 목록(9개, 화면마다 상태 한 줄: '확인 중'·'버전 3'·'연결됨' 등), 아래 가게 정보 필드(가게 이름·연락처·사업장 주소·전자우편주소·픽업 장소·통신판매업 신고번호와 기관)와 기능 필드, '저장'. 사업자 정보(상호·대표자·사업자등록번호)는 읽기 전용이고 옆에 '변경 요청'(SCR-035). 확인을 기다리는 변경 요청이 있으면 '변경 확인 기다림', 보류됐으면 '변경 요청 보류'. 기능 필드 아래 한 줄: 기다리는 시간은 '바꾸면 그 뒤 시작되는 기다림부터 써요', 문의 끊김 시간과 하루 AI 비용 한도는 '저장한 때부터 써요'(REQ-243). 영업 신고 번호·종류와 신고증은 영업 신고(SCR-035). 맨 아래 '로그아웃'. 360: 설정 목록을 한 행씩 | API-009#200:verified, API-009#200:pending, API-009#200:on_hold, API-009#200:identity_change_pending, API-009#200:identity_change_on_hold, API-003#204 |
| SCR-034#loading | 레이아웃은 그대로 두고 데이터 자리에 회색 막대를 보임. 액션 버튼은 누를 수 없음 | (데이터를 불러오는 동안) |
| SCR-034#error | 입력이 한도나 형식에 맞지 않음(422 validation_failed): 필드 옆에 '입력한 내용을 확인해 주세요'와 필드마다의 사유. 넣은 값은 그대로 둠. 같은 요청 키로 다른 내용을 보냄(422 idempotency_key_reused): '다시 시도해 주세요'. 새 요청 키로 다시 보냄. 그 밖의 실패(로그아웃 포함): '문제가 생겼어요. 다시 시도해 주세요'와 다시 시도 버튼, 추적 ID | API-009#default:internal, API-010#422:validation_failed, API-010#422:idempotency_key_reused, API-010#default:internal, API-003#default:internal |
| SCR-034#permission | 로그인이 없거나 만료됨(401 unauthenticated): 로그인 화면으로 이동하고, 로그인하면 이 화면으로 돌아옴('다시 로그인해 주세요'). 로그인한 사장님에게 가게가 아직 없음(404 shop_not_registered): 가게가 없으면 가게 등록(SCR-015)으로 보냄('가게를 먼저 등록해 주세요') | API-009#401:unauthenticated, API-009#404:shop_not_registered, API-010#401:unauthenticated, API-010#404:shop_not_registered |
| SCR-034#stale | 다른 기기에서 먼저 저장함(409 version_conflict): '그 사이 바뀌었어요. 지금 상태를 확인해 주세요'와 다시 읽은 지금 상태 | API-010#409:version_conflict |
| SCR-034#submitting | 누른 버튼이 '처리하고 있어요'로 바뀌고 이 화면의 다른 액션과 함께 막힘. 첫 요청을 아직 처리하는 중이면(409 request_in_progress) 1초 뒤 같은 요청 키로 다시 보내고, 결과는 한 번만 보임 | API-010#409:request_in_progress |
| SCR-034#done | 저장(updated): '저장했어요'. 바뀐 것 없음(unchanged): '바뀐 것이 없어요' | API-010#200:updated, API-010#200:unchanged |
| empty (해당 없음) | 가게가 있어야 이 화면이 열림(없으면 SCR-034#permission에서 가게 등록으로). 비어도 되는 필드(픽업 장소)는 normal 안에서 '비어 있음' |  |

## 케이스 유형

| 케이스 유형 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 로그인한 사장님의 가게만. 401은 SCR-034#permission |
| 입력 | 가게 이름 1~40자, 연락처 8~14자, 사업장 주소 1~200자, 전자우편주소 3~100자('@' 형식), 통신판매업 신고 기관 1~40자(신고번호와 함께, 신고번호와 면제 사유 가운데 하나는 늘 있음), 픽업 장소 1~200자, 문의 끊김 1~720시간, 기다리는 시간 10~1,440분, AI 비용 한도 0~100만 원. 틀리면 SCR-034#error |
| 대상 | 가게가 없으면 SCR-034#permission |
| 상태 변화 | 영업 신고 상태는 설정 목록의 영업 신고 카드에 보임(보류면 SCR-035#on-hold). 사업자 정보 변경 요청의 확인 기다림·보류는 사업자 정보 옆 글(SCR-034#normal). 바꾼 기다리는 시간은 그 뒤 시작되는 기다림부터, 문의 끊김 시간과 하루 AI 비용 한도는 저장한 때부터 씀(REQ-243) |
| 반복 | 저장을 두 번 눌러도 한 번(SCR-034#done의 unchanged). 로그아웃은 두 번 눌러도 같음 |
| 동시 변경 | 다른 기기의 저장과 동시에 일어나면 SCR-034#stale |
| 데이터 노출 | 이 화면은 그 가게 사장님에게만. 여기서 바꾼 사업장 주소·연락처·전자우편주소·통신판매업 신고는 예약 링크 페이지의 가게 신원 정보로 손님에게 보임(REQ-239) |
| 화면 상태 | 상태마다 360·1280 와이어프레임(`wireframes.html#SCR-034`) |
