# SCR-035 영업 신고

- 경로: `/owner/shop/license`
- 접근 권한: 사장님
- 상위 화면: SCR-034 가게 설정
- 화면 레이아웃: 사장님 화면(1280 왼쪽 메뉴, 360 위쪽 막대와 메뉴 버튼)
- 플로우: FL-001
- 관련 SPEC: SPEC-003
- API: API-009, API-011, API-007
- 와이어프레임: `wireframes.html#SCR-035`(상태 8개, 360·1280)
- 목업: [`SCR-035-360`](../../research/cake-mockup-2026-11/canvas/project/SCR-035-360.dc.html)(normal·error), [`SCR-035-1280`](../../research/cake-mockup-2026-11/canvas/project/SCR-035-1280.dc.html)(normal). 캔버스의 '사장님 화면' 페이지([09단계 README](../09-mockup/README.md) 2절)

목적: 사장님이 운영자의 영업 신고 확인 상태(확인 중·확인됨·보류)와 보류 사유를 보고, 보류면 신고증을 다시 올리거나 결제 계좌를 바꿉니다. (FL-001)

## 데이터

| 데이터 | 출처 |
| --- | --- |
| 영업 신고 상태와 보류 사유 | API-009 licenseStatus·licenseHoldReason |
| 영업 신고 번호·종류·신고증 사진 | API-009 foodLicenseNo·foodBusinessType·licensePhotoUrl |
| 다시 올릴 신고증 사진 | API-007 license_photo → API-011 요청 licensePhotoUploadId |
| 다시 올린 결과 | API-011 outcome·shop |

## 액션

| 액션 | 결과 | 실패 |
| --- | --- | --- |
| 신고증 다시 올리기(보류일 때) | 번호·종류·새 사진으로 다시 올림: '신고증을 다시 올렸어요. 운영자가 다시 확인해요'와 '확인 중' | 보류가 아닌 상태(409 invalid_state)·본 뒤 바뀜은 SCR-035#stale, 필드 오류(422)·사진 10MB 넘음(413)·저장소 장애(503)는 SCR-035#error |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이 상태로 오는 응답 |
| --- | --- | --- |
| SCR-035#normal | 상태 라벨 '확인 중'이나 '확인됨'(확인된 시각), 넣은 번호·종류·신고증 사진. 확인 중이면 '운영자가 확인하고 있어요. 확인되면 우리 서비스 채널로 알려 드려요' | API-009#200:verified, API-009#200:pending, API-007#201:license_photo |
| SCR-035#loading | 레이아웃은 그대로 두고 데이터 자리에 회색 막대를 보임. 액션 버튼은 누를 수 없음. 사진 자리는 신고증 비율의 회색 | (데이터를 불러오는 동안) |
| SCR-035#error | 입력이 한도나 형식에 맞지 않음(422 validation_failed): 필드 옆에 '입력한 내용을 확인해 주세요'와 필드마다의 사유. 넣은 값은 그대로 둠. 사진이 10MB를 넘음(413): '사진이 너무 커요. 10MB(완성 사진은 20MB)까지 올릴 수 있어요'. 저장소 장애(503): 06단계 storage_unavailable 문구와 '다시 올리기'. 같은 요청 키로 다른 내용을 보냄(422 idempotency_key_reused): '다시 시도해 주세요'. 새 요청 키로 다시 보냄. 그 밖의 실패: '문제가 생겼어요. 다시 시도해 주세요'와 다시 시도 버튼, 추적 ID | API-009#default:internal, API-011#422:validation_failed, API-011#422:idempotency_key_reused, API-011#default:internal, API-007#413:file_too_large, API-007#422:validation_failed, API-007#503:storage_unavailable, API-007#default:internal |
| SCR-035#permission | 로그인이 없거나 만료됨(401 unauthenticated): 로그인 화면으로 이동하고, 로그인하면 이 화면으로 돌아옴('다시 로그인해 주세요'). 로그인한 사장님에게 가게가 아직 없음(404 shop_not_registered): 가게가 없으면 가게 등록(SCR-015)으로 보냄('가게를 먼저 등록해 주세요') | API-009#401:unauthenticated, API-009#404:shop_not_registered, API-011#401:unauthenticated, API-011#404:shop_not_registered, API-007#401:unauthenticated |
| SCR-035#stale | 보류가 아닌 상태(409 invalid_state, 그 사이 운영자가 확인함 등): '지금 상태에서는 할 수 없어요'와 지금 상태. 본 뒤 바뀜(409 version_conflict): '그 사이 바뀌었어요. 지금 상태를 확인해 주세요'와 다시 읽은 지금 상태 | API-011#409:version_conflict, API-011#409:invalid_state |
| SCR-035#submitting | 누른 버튼이 '처리하고 있어요'로 바뀌고 이 화면의 다른 액션과 함께 막힘. 첫 요청을 아직 처리하는 중이면(409 request_in_progress) 1초 뒤 같은 요청 키로 다시 보내고, 결과는 한 번만 보임 | API-011#409:request_in_progress |
| SCR-035#on-hold | 보류(on_hold): '보류'와 보류 사유(운영자가 쓴 1~200자), 번호·종류·사진 필드와 '신고증 다시 올리기'. 할 일 목록의 '영업 신고 보류'와 배너도 이 화면으로 옴. 결제 계좌의 예금주 때문에 보류됐으면 결제 수단(SCR-040)에서 계좌를 바꿔도 다시 '확인 중'이 됨(SPEC-003) | API-009#200:on_hold |
| SCR-035#done | 다시 올림(resubmitted): '신고증을 다시 올렸어요. 운영자가 다시 확인해요'와 '확인 중' | API-011#200:resubmitted |
| empty (해당 없음) | 가게 등록 때 신고증을 올려야 가게가 생김(SPEC-002). 빈 영업 신고는 없음 |  |

## 케이스 유형

| 케이스 유형 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 로그인한 사장님의 가게만. 401은 SCR-035#permission |
| 입력 | 영업 신고 번호 1~30자, 사진 JPG·PNG·HEIC 10MB. 틀리면 SCR-035#error |
| 대상 | 가게가 없으면 SCR-035#permission |
| 상태 변화 | 보류는 SCR-035#on-hold에서만 다시 올림. 확인 중·확인됨에 다시 올리면 SCR-035#stale |
| 반복 | 다시 올리기를 두 번 눌러도 한 번(SCR-035#submitting) |
| 동시 변경 | 운영자 처리와 동시에 일어나면 SCR-035#stale |
| 한도 | 신고증 사진 10MB(SCR-035#error) |
| 외부 서비스 | 사진 저장 실패(503)는 SCR-035#error |
| 데이터 노출 | 신고증 사진은 그 가게 사장님과 운영자만(G1) |
| 화면 상태 | 상태마다 360·1280 와이어프레임(`wireframes.html#SCR-035`) |
