# SCR-035 영업 신고

- 경로: `/owner/shop/license`
- 접근 권한: 사장님
- 상위 화면: SCR-034 가게 설정
- 화면 레이아웃: 사장님 화면(1280 왼쪽 메뉴, 360 위쪽 막대와 메뉴 버튼)
- 플로우: FL-001, FL-002
- 관련 SPEC: SPEC-003, SPEC-078
- API: API-009, API-011, API-007, API-080
- 와이어프레임: `wireframes.html#SCR-035`(상태 8개, 360·1280)
- 목업: [`SCR-035-360`](../../research/cake-mockup-2026-11/canvas/project/SCR-035-360.dc.html)(normal·error), [`SCR-035-1280`](../../research/cake-mockup-2026-11/canvas/project/SCR-035-1280.dc.html)(normal). 캔버스의 '사장님 화면' 페이지([09단계 README](../09-mockup/README.md) 2절)

목적: 사장님이 운영자의 영업 신고 확인 상태(확인 중·확인됨·보류)와 보류 사유를 보고, 보류면 신고증을 다시 올리거나 결제 계좌를 바꾸며, 상호·대표자·사업자등록번호를 바꿀 때는 증빙 사진과 함께 변경을 요청합니다(운영자가 반영하기 전까지는 확인된 지금 값). (FL-001, FL-002)

## 액션

| 액션 | 결과 | 실패 |
| --- | --- | --- |
| 신고증 다시 올리기(보류일 때) | 번호·종류·새 사진으로 다시 올림: '신고증을 다시 올렸어요. 운영자가 다시 확인해요'와 '확인 중' | 보류가 아닌 상태(409 invalid_state)·본 뒤 바뀜은 SCR-035#stale, 필드 오류(422)·사진 10MB 넘음(413)·너무 자주 올림(429)·저장소 장애(503)는 SCR-035#error |
| 사업자 정보 변경 요청 | 새 값 셋(바꾸지 않는 값은 지금 값)과 증빙 사진을 넣고 '변경 요청': '변경을 요청했어요. 운영자가 확인하면 바뀌어요'와 '변경 확인 기다림'(SCR-035#done). 세 값이 지금과 같으면 '바뀐 것이 없어요' | 이미 확인을 기다리는 요청이 있음(409 identity_change_pending)·본 뒤 바뀜(409 version_conflict)은 SCR-035#stale, 필드 오류(422)·사진 10MB 넘음(413)·너무 자주 올림(429)·저장소 장애(503)는 SCR-035#error |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이 상태로 오는 응답 |
| --- | --- | --- |
| SCR-035#normal | 상태 라벨 '확인 중'이나 '확인됨'(확인된 시각), 넣은 번호·종류·신고증 사진. 확인 중이면 '운영자가 확인하고 있어요. 확인되면 우리 서비스 채널로 알려 드려요'. 아래 '사업자 정보' 표(상호·대표자·사업자등록번호, 운영자가 확인한 값)와 '변경 요청'. 누르면 새 값 셋과 증빙 사진 필드가 열림. 확인을 기다리는 변경 요청이 있으면(identity_change_pending) '변경 확인 기다림'과 새 값·요청 시각을 보이고 '변경 요청'은 막힘. 보류됐으면(identity_change_on_hold) '변경 요청 보류'와 보류 이유, '다시 요청'. 반영되면 표가 새 값이 됨 | API-009#200:verified, API-009#200:pending, API-009#200:identity_change_pending, API-009#200:identity_change_on_hold, API-007#201:license_photo |
| SCR-035#loading | 레이아웃은 그대로 두고 데이터 자리에 회색 막대를 보임. 액션 버튼은 누를 수 없음. 사진 자리는 신고증 비율의 회색 | (데이터를 불러오는 동안) |
| SCR-035#error | 입력이 한도나 형식에 맞지 않음(422 validation_failed): 필드 옆에 '입력한 내용을 확인해 주세요'와 필드마다의 사유. 넣은 값은 그대로 둠. 사진이 10MB를 넘음(413): '사진이 너무 커요. 10MB(완성 사진은 20MB)까지 올릴 수 있어요'. 저장소 장애(503): 06단계 storage_unavailable 문구와 '다시 올리기'. 같은 요청 키로 다른 내용을 보냄(422 idempotency_key_reused): '다시 시도해 주세요'. 새 요청 키로 다시 보냄. 그 밖의 실패: '문제가 생겼어요. 다시 시도해 주세요'와 다시 시도 버튼, 추적 ID | API-009#default:internal, API-011#422:validation_failed, API-011#422:idempotency_key_reused, API-011#default:internal, API-007#413:file_too_large, API-007#422:validation_failed, API-007#429:rate_limited, API-007#503:storage_unavailable, API-007#default:internal, API-080#422:validation_failed, API-080#422:idempotency_key_reused, API-080#503:storage_unavailable, API-080#default:internal |
| SCR-035#permission | 로그인이 없거나 만료됨(401 unauthenticated): 로그인 화면으로 이동하고, 로그인하면 이 화면으로 돌아옴('다시 로그인해 주세요'). 로그인한 사장님에게 가게가 아직 없음(404 shop_not_registered): 가게가 없으면 가게 등록(SCR-015)으로 보냄('가게를 먼저 등록해 주세요') | API-009#401:unauthenticated, API-009#404:shop_not_registered, API-011#401:unauthenticated, API-011#404:shop_not_registered, API-007#401:unauthenticated, API-080#401:unauthenticated, API-080#404:shop_not_registered |
| SCR-035#stale | 보류가 아닌 상태(409 invalid_state, 그 사이 운영자가 확인함 등): '지금 상태에서는 할 수 없어요'와 지금 상태. 확인을 기다리는 변경 요청이 이미 있음(409 identity_change_pending, 다른 기기에서 먼저 요청함): '이미 확인을 기다리는 변경 요청이 있어요'와 다시 읽은 그 요청. 본 뒤 바뀜(409 version_conflict): '그 사이 바뀌었어요. 지금 상태를 확인해 주세요'와 다시 읽은 지금 상태 | API-011#409:version_conflict, API-011#409:invalid_state, API-080#409:version_conflict, API-080#409:identity_change_pending |
| SCR-035#submitting | 누른 버튼이 '처리하고 있어요'로 바뀌고 이 화면의 다른 액션과 함께 막힘. 첫 요청을 아직 처리하는 중이면(409 request_in_progress) 1초 뒤 같은 요청 키로 다시 보내고, 결과는 한 번만 보임 | API-011#409:request_in_progress, API-080#409:request_in_progress |
| SCR-035#on-hold | 보류(on_hold): '보류'와 보류 사유(운영자가 쓴 1~200자), 번호·종류·사진 필드와 '신고증 다시 올리기'. 할 일 목록의 '영업 신고 보류'와 배너도 이 화면으로 옴. 결제 계좌의 예금주 때문에 보류됐으면 결제 수단(SCR-040)에서 계좌를 바꿔도 다시 '확인 중'이 됨(SPEC-003) | API-009#200:on_hold |
| SCR-035#done | 다시 올림(resubmitted): '신고증을 다시 올렸어요. 운영자가 다시 확인해요'와 '확인 중'. 변경 요청(requested): '변경을 요청했어요. 운영자가 확인하면 바뀌어요'와 '변경 확인 기다림'. 세 값이 지금과 같음(unchanged): '바뀐 것이 없어요' | API-011#200:resubmitted, API-080#201:requested, API-080#200:unchanged |
| empty (해당 없음) | 가게 등록 때 신고증을 올려야 가게가 생김(SPEC-002). 빈 영업 신고는 없음 |  |

## 케이스 유형

| 케이스 유형 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 로그인한 사장님의 가게만. 401은 SCR-035#permission |
| 입력 | 영업 신고 번호 1~30자, 사진 JPG·PNG·HEIC 10MB. 변경 요청의 상호 1~60자·대표자 1~30자·사업자등록번호 10자리와 검증 숫자, 증빙 사진 한 장. 틀리면 SCR-035#error |
| 대상 | 가게가 없으면 SCR-035#permission |
| 상태 변화 | 보류는 SCR-035#on-hold에서만 다시 올림. 확인 중·확인됨에 다시 올리면 SCR-035#stale. 확인을 기다리는 변경 요청이 있으면 새 요청을 받지 않음(SCR-035#stale). 운영자가 반영하기 전까지 예약 링크 페이지·확정 안내는 확인된 지금 값(REQ-245) |
| 반복 | 다시 올리기·변경 요청을 두 번 눌러도 한 번(SCR-035#submitting) |
| 동시 변경 | 운영자 처리(영업 신고 확인·변경 요청 반영·보류)와 동시에 일어나면 SCR-035#stale |
| 한도 | 신고증 사진 10MB(SCR-035#error) |
| 외부 서비스 | 사진 저장 실패(503)는 SCR-035#error. 변경 요청도 남기지 않음 |
| 데이터 노출 | 신고증 사진과 변경 요청의 증빙 사진은 그 가게 사장님과 운영자만(G1) |
| 화면 상태 | 상태마다 360·1280 와이어프레임(`wireframes.html#SCR-035`) |
