# SCR-004 주문 요청 카드

- 경로: `kakao:shop/card/order_request`
- 접근 권한: 손님
- 상위 화면: SCR-003 가게 채널 상담
- 화면 레이아웃: 카카오톡 채널 대화 화면(1280은 PC 카카오톡 창)
- 플로우: FL-006
- 관련 SPEC: SPEC-028, SPEC-029, SPEC-030, SPEC-069, SPEC-072
- API: API-071
- 와이어프레임: `wireframes.html#SCR-004`(상태 8개, 360·1280)
- 목업: [`SCR-004-360`](../../research/cake-mockup-2026-11/canvas/project/SCR-004-360.dc.html)(normal·expired·error), [`SCR-004-1280`](../../research/cake-mockup-2026-11/canvas/project/SCR-004-1280.dc.html)(normal). 캔버스의 '손님 화면' 페이지([09단계 README](../09-mockup/README.md) 2절)

목적: 손님이 주문 내용 요약과 그 버전의 취소·환불 규정을 따로 보고, 규정에 동의해 주문을 요청합니다. 요약이 다 찼는데 주문자 이름·연락처가 없으면 먼저 AI를 거치지 않는 '주문자 정보' 블록으로 받습니다(SPEC-072). 사진 게시 동의는 버튼으로 고르고 기본은 동의 안 함입니다. (FL-006)

## 데이터

| 데이터 | 출처 |
| --- | --- |
| 주문 내용 요약: 픽업 날짜·시간, 크기·맛·디자인, 문구(손님이 쓴 철자 그대로), 색, 주문자 이름·연락처, 금액 | API-071 카드(처음 카드는 SCR-003의 API-070 card_shown, 주문자 정보를 받은 뒤면 API-071 orderer_saved) |
| 주문자 이름·연락처: '주문자 정보' 블록이 받은 값. AI로 보내지 않음(REQ-175, REQ-178) | API-071 orderer_saved, input_invalid |
| 그 운영규정 버전의 취소·환불 규정과 '주문제작이라 청약철회가 제한될 수 있어요' | API-071 카드 |
| 카드 기한(보낸 뒤 30분) | API-071 카드 |
| 누른 결과(주문번호, 기본 디자인이면 결제 안내) | API-071 order_requested |

## 액션

| 액션 | 결과 | 실패 |
| --- | --- | --- |
| 이름·연락처 넣기(주문자 정보 카드) | AI를 거치지 않는 '주문자 정보' 블록이 이름(1~30자)과 연락처(숫자와 '-' 8~14자)를 차례로 묻고, 맞으면 초안에 남긴 뒤 이 주문 요청 카드를 보냄(SPEC-072) | 형식이 틀리면 아무것도 남기지 않고 SCR-004#orderer로 다시 물음(input_invalid). 30분이 지났으면 SCR-004#expired |
| 규정에 동의하고 주문 요청 | 한 트랜잭션으로 내용 확인·규정 동의(버전·시각)·사진 게시 동의(동의 안 함)·주문 요청을 남김. 기본 디자인이면 그날 자리를 결제 기한까지 잡고 결제 안내(SCR-005)까지(SPEC-029·030) | 다 찬 날은 SCR-004#day-full, 쓰기 실패는 SCR-004#error('다시 눌러 주세요'), 버전이 바뀌었으면 SCR-004#stale, 30분이 지났으면 SCR-004#expired. 어느 경우도 아무것도 남지 않음 |
| 사진 게시도 동의하고 요청 | 위와 같고 사진 게시 동의를 '동의'로 남김 | 위와 같음 |
| 안 할래요 | 아무것도 남기지 않고 '알겠어요. 더 궁금한 것이 있으면 말씀해 주세요' | 서버 오류면 SCR-004#error |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이 상태로 오는 응답 |
| --- | --- | --- |
| SCR-004#normal | 말풍선 3개(W6): ① 주문 내용 요약(주문자 이름·연락처 포함) ② '취소·환불 규정 (버전 n)'과 청약철회 제한 문장 ③ 버튼 카드('규정에 동의하고 주문 요청'·'사진 게시도 동의하고 요청'·'안 할래요', 'HH:MM까지 눌러 주세요') | API-071#200:orderer_saved |
| SCR-004#orderer | 주문서 초안이 다 찼는데 주문자 이름·연락처가 없음: 주문 요청 카드 앞에 '주문자 정보' 카드(버튼 '이름·연락처 넣기'). 누르면 AI를 거치지 않는 블록이 이름과 연락처를 차례로 묻고, 맞으면 주문 요청 카드가 나옴(orderer_saved). 형식이 틀리면(input_invalid) 아무것도 남기지 않고 '이름은 1~30자, 연락처는 숫자와 '-'로 8~14자로 넣어 주세요'와 같은 버튼으로 다시 물음 | API-071#200:input_invalid |
| SCR-004#done | 누른 결과: 기본 디자인은 '주문을 요청했어요(주문번호 {orderNo}). 결제가 확인되면 확정돼요'와 결제 안내(SCR-005), 맞춤 주문은 '주문을 요청했어요(주문번호 {orderNo}). 사장님이 보고 알려 드릴게요'. 채널 친구가 아니면 채널 추가 권유. '안 할래요'는 '알겠어요…'. 같은 카드를 다시 누르면 처음 결과를 다시 보냄(card_used) | API-071#200:order_requested, API-071#200:declined, API-071#200:card_used |
| SCR-004#stale | 카드를 보낸 뒤 초안·가격표·운영규정 버전이 바뀜(card_stale): '내용이 바뀌었어요. 새 카드를 확인해 주세요'와 새 금액의 새 카드. 지금 상태에서 받을 수 없음(not_allowed_now): '지금은 할 수 없어요: {지금 상태}'. 둘 다 아무것도 남지 않음 | API-071#200:card_stale, API-071#200:not_allowed_now |
| SCR-004#expired | 보낸 지 30분이 지난 카드를 누름(card_expired): '시간이 지나 새 카드를 보내 드려요'와 지금 값으로 만든 새 카드. 아무것도 남지 않음 | API-071#200:card_expired |
| SCR-004#day-full | 기본 디자인 주문의 자리를 같은 트랜잭션에서 잡지 못함(day_full, 주문 요청도 남지 않음): '그 사이 그날이 다 찼어요. 이날은 어떠세요?'와 가까운 날 최대 3개 바로가기. 없으면 '가까운 날에 자리가 없어요. 사장님께 확인을 요청할 수 있어요' | API-071#200:day_full |
| SCR-004#permission | 카드를 받은 사용자가 아님(card_not_yours): '이 버튼은 카드를 받은 분만 누를 수 있어요'. 아무것도 남지 않음. 그 사이 채널 연결이 끊긴 가게(not_accepting): '아직 상담을 받지 않아요. 가게로 연락해 주세요: {가게 연락처}' | API-071#200:card_not_yours, API-071#200:not_accepting |
| SCR-004#error | 쓰기 하나가 실패해 하나도 남기지 않음(retry_needed): '다시 눌러 주세요'. 서버 오류(server_error): '잠시 뒤 다시 말씀해 주세요'. 스킬 키가 틀리거나 형식이 아니거나 예상하지 못한 실패(401·422·default): 카카오톡이 자기 오류 말을 보임(우리 문구 없음, DEC-07). 서버 로그에 추적 ID | API-071#200:retry_needed, API-071#200:server_error, API-071#401:skill_key_invalid, API-071#422:validation_failed, API-071#default:internal |
| loading (해당 없음) | 버튼을 누른 뒤 답이 올 때까지는 카카오톡이 자기 표시를 함. 우리가 그릴 것이 없음 |  |
| empty (해당 없음) | 카드는 서버가 저장된 값이 있을 때만 만들어 보임(SPEC-069). 빈 카드는 없음 |  |

## 응답과 상태

06단계 계약(`api/openapi.yaml`)의 응답마다 화면 상태 하나입니다. 오류의 문구는 06단계 오류 코드 표의 '화면에 보이는 말'입니다.

| 응답 | 화면 상태 | 화면에 보이는 것 |
| --- | --- | --- |
| API-071#200:orderer_saved | SCR-004#normal | 주문자 정보 블록의 값을 남긴 뒤 이 카드가 나옴(SPEC-072) |
| API-071#200:order_requested | SCR-004#done | 기본 디자인: 주문을 요청했어요(주문번호 {orderNo}). 결제가 확인되면 확정돼요 + 결제 안내 / 맞춤 주문: 주문을 요청했어요(주문번호 {orderNo}). 사장님이 보고 알려 드릴게요 + (채널 친구가 아니면) 채널을 추가하시면 답을 바로 받아 보실 수 있어요 |
| API-071#200:payment_claimed | 나오지 않음 | 이 카드에서는 나오지 않음(SCR-006 결제 확인 요청 카드의 결과) |

| API-071#200:issue_reported | 나오지 않음 | 이 카드에서는 나오지 않음(SCR-010 문제 신고 카드의 결과) |
| API-071#200:consent_withdrawn | 나오지 않음 | 이 카드에서는 나오지 않음(SCR-013 사진 게시 동의 철회 카드의 결과) |

## 케이스 유형

| 케이스 유형 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 카드를 받은 같은 카카오 사용자만 누름. 다른 사람은 SCR-004#permission, 스킬 키가 틀리면 SCR-004#error |
| 입력 | 카드 값은 서버 기록에서만 옴. 주문자 이름·연락처는 AI를 거치지 않는 '주문자 정보' 블록으로만 받고, 이름 1~30자·연락처 숫자와 '-' 8~14자가 아니면 SCR-004#orderer로 다시 물음(input_invalid). 스킬 요청 형식이 아니면 SCR-004#error |
| 대상 | 지금 상태에서 받을 수 없는 명령은 '지금은 할 수 없어요: {지금 상태}'(SCR-004#stale) |
| 상태 변화 | 버전이 바뀐 카드는 SCR-004#stale, 30분이 지난 카드는 SCR-004#expired. 둘 다 새 카드를 보내고 아무것도 남기지 않음 |
| 반복 | 같은 카드를 다시 누르면 처음 결과를 다시 보냄(SCR-004#done, card_used). 명령은 한 번 |
| 동시 변경 | 같은 날 마지막 자리를 두 손님이 함께 누르면 하나만 잡히고 다른 쪽은 SCR-004#day-full(R11). 카드 뒤 버전이 바뀌면 SCR-004#stale |
| 외부 서비스 | 트랜잭션의 쓰기 하나가 실패하면 하나도 남기지 않고 '다시 눌러 주세요'(SCR-004#error) |
| 데이터 노출 | 카드와 결과에 다른 손님 정보·내부 ID(주문번호 밖)·오류 내용 없음(G6). 주문자 이름·연락처는 AI로 보내지 않음(REQ-178) |
| AI 답 | AI는 카드를 제안만 하고 카드의 값(금액·버전·환불)은 서버 기록에서 만듦(SPEC-069). AI 말로 카드 값을 바꿀 수 없음 |
| 화면 상태 | 상태마다 360·1280 와이어프레임(`wireframes.html#SCR-004`) |
