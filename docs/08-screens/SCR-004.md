# SCR-004 주문 요청 카드

- 경로: `kakao:shop/card/order_request`
- 접근 권한: 손님
- 상위 화면: SCR-003 가게 채널 상담
- 화면 레이아웃: 카카오톡 채널 대화 화면(1280은 PC 카카오톡 창)
- 플로우: FL-006
- 관련 SPEC: SPEC-028, SPEC-029, SPEC-030, SPEC-069, SPEC-072, SPEC-075
- API: API-071
- 와이어프레임: `wireframes.html#SCR-004`(상태 9개, 360·1280)
- 목업: [`SCR-004-360`](../../research/cake-mockup-2026-11/canvas/project/SCR-004-360.dc.html)(normal·expired·error), [`SCR-004-1280`](../../research/cake-mockup-2026-11/canvas/project/SCR-004-1280.dc.html)(normal). 캔버스의 '손님 화면' 페이지([09단계 README](../09-mockup/README.md) 2절)

목적: 손님이 알레르기 정보에 따로 동의할지 고르고(동의하면 AI를 거치지 않는 '알레르기 답' 블록으로 답함, SPEC-075), 그 버전의 취소·환불 규정 글과 주문 내용 요약 카드를 따로 보고, 규정에 동의해 주문을 요청합니다. 요약이 다 찼는데 주문자 이름·연락처가 없으면 먼저 AI를 거치지 않는 '주문자 정보' 블록으로 받습니다(SPEC-072). 사진 게시 동의는 주문 요청 때 묻지 않습니다(완성 사진은 SCR-011, 후기 사진은 SCR-012). (FL-006)

## 액션

| 액션 | 결과 | 실패 |
| --- | --- | --- |
| 동의하고 알려 주기(알레르기 정보 카드) | AI를 거치지 않는 '알레르기 답' 블록이 알레르기가 있는 재료(1~200자, '없음'도 답)를 묻고, 맞으면 동의(동의 글 버전·시각)와 답을 한 트랜잭션으로 초안에 남긴 뒤 주문자 이름·연락처가 없으면 주문자 정보 카드를, 있으면 주문 요청 카드를 보냄(SPEC-075) | 답이 비거나 200자를 넘으면 아무것도 남기지 않고 SCR-004#allergy로 다시 물음(input_invalid). 30분이 지났으면 SCR-004#expired |
| 동의 안 함(알레르기 정보 카드) | 거부와 동의 글 버전·시각을 초안에 남기고 알레르기는 묻지 않은 채 빼야 할 재료만으로 다음 카드(주문자 정보나 주문 요청)를 보냄(REQ-203) | 서버 오류면 SCR-004#error |
| 이름·연락처 넣기(주문자 정보 카드) | AI를 거치지 않는 '주문자 정보' 블록이 이름(1~30자)과 연락처(숫자와 '-' 8~14자)를 차례로 묻고, 맞으면 초안에 남긴 뒤 이 주문 요청 카드를 보냄(SPEC-072) | 형식이 틀리면 아무것도 남기지 않고 SCR-004#orderer로 다시 물음(input_invalid). 30분이 지났으면 SCR-004#expired |
| 규정에 동의하고 주문 요청 | 한 트랜잭션으로 내용 확인·규정 동의(버전·시각)·주문 요청을 남기고 초안의 알레르기 정보 동의(답·동의 글 버전·시각)와 알레르기 답을 주문 내용 버전에 옮김. 기본 디자인이면 그날 자리를 결제 기한까지 잡고 결제 안내(SCR-005)까지(SPEC-029·030) | 다 찬 날은 SCR-004#day-full, 쓰기 실패는 SCR-004#error('다시 눌러 주세요'), 버전이 바뀌었으면 SCR-004#stale, 30분이 지났으면 SCR-004#expired. 어느 경우도 아무것도 남지 않음 |
| 안 할래요 | 아무것도 남기지 않고 '알겠어요. 더 궁금한 것이 있으면 말씀해 주세요' | 서버 오류면 SCR-004#error |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이 상태로 오는 응답 |
| --- | --- | --- |
| SCR-004#normal | 한 응답의 출력(W6, DEC-22): ① 그 버전의 취소·환불 규정 글 '취소·환불 규정(운영규정 버전 n)'과 조문마다 '· 제목: 조건 → 효과' 한 줄, 끝에 청약철회 제한 문장과 미성년자 취소 고지(REQ-240). 1,000자를 넘으면 조문 사이에서 나눠 글 둘(1/2·2/2), 두 문장은 둘째 끝 ② 요약 카드 '주문 요청 확인': 주문 내용 요약(주문자 이름·연락처, 알레르기 답이나 '알레르기 정보 동의 안 함' 포함), 'HH:MM까지 눌러 주세요', 버튼 '규정에 동의하고 주문 요청'·'안 할래요'. 손님이 채널 친구가 아니면(REQ-219) 요약 카드 설명 끝에 '채널을 추가하면 결제 안내와 사장님 답을 바로 받아요' 한 줄(카드 400자 안에 들 때만). 채널 추가는 주문 요청의 조건이 아님(REQ-121). 사진 게시 동의는 묻지 않음(완성 사진은 SCR-011#photo-consent, 후기 사진은 SCR-012) | API-071#200:orderer_saved |
| SCR-004#allergy | 주문서 초안의 빈 항목과 금액 확인이 끝났는데 알레르기 정보 동의의 답이 없음(card_shown): 주문자 정보·주문 요청 카드 앞에 '알레르기 정보' 카드. 쓰는 목적(이 주문의 케이크 만들기)·받는 항목(알레르기가 있는 재료)·보는 사람(이 가게 사장님)·지우는 때(주문이 끝나고 30일 뒤)와 '동의하지 않아도 돼요. 그러면 알레르기는 묻지 않고 빼야 할 재료만으로 주문해요', 버튼 '동의하고 알려 주기'·'동의 안 함'. '동의하고 알려 주기'는 AI를 거치지 않는 '알레르기 답' 블록을 열어 답을 받고 동의와 함께 남긴 뒤 다음 카드(allergy_saved). '동의 안 함'은 거부를 남기고 '알겠어요. 알레르기는 묻지 않고 빼야 할 재료만으로 주문을 이어갈게요'와 다음 카드(allergy_declined). 답이 비거나 200자를 넘으면(input_invalid) 아무것도 남기지 않고 '알레르기가 있는 재료를 200자까지 알려 주세요(없으면 없음)'와 버튼 '알레르기 알려 주기'. 카드를 보낸 뒤 초안이 바뀌어도 받은 동의와 답은 남음. 동의 단계를 끈 배포는 동의를 묻지 않고 알레르기 답 블록 버튼만(REQ-205) | - |
| SCR-004#orderer | 주문서 초안이 다 찼는데 주문자 이름·연락처가 없음: 주문 요청 카드 앞에 '주문자 정보' 카드(버튼 '이름·연락처 넣기'). 누르면 AI를 거치지 않는 블록이 이름과 연락처를 차례로 묻고, 맞으면 주문 요청 카드가 나옴(orderer_saved). 형식이 틀리면(input_invalid) 아무것도 남기지 않고 '이름은 1~30자, 연락처는 숫자와 '-'로 8~14자로 넣어 주세요'와 같은 버튼으로 다시 물음 | API-071#200:allergy_saved, API-071#200:allergy_declined, API-071#200:input_invalid |
| SCR-004#done | 누른 결과: 기본 디자인은 '주문을 요청했어요(주문번호 {orderNo}). 결제가 확인되면 확정돼요'와 결제 안내(SCR-005), 맞춤 주문은 '주문을 요청했어요(주문번호 {orderNo}). 사장님이 보고 알려 드릴게요'. 채널 친구가 아니면 채널 추가 권유. '안 할래요'는 '알겠어요…'. 같은 카드를 다시 누르면 처음 결과를 다시 보냄(card_used) | API-071#200:order_requested, API-071#200:declined, API-071#200:card_used |
| SCR-004#stale | 카드를 보낸 뒤 초안·가격표·운영규정 버전이 바뀜(card_stale): 그 버전의 규정 글을 먼저 보내고, 새 요약 카드 맨 위에 '내용이 바뀌었어요. 새 카드를 확인해 주세요'와 새 금액(DEC-22). 지금 상태에서 받을 수 없음(not_allowed_now): '지금은 할 수 없어요: {지금 상태}'. 둘 다 아무것도 남지 않음 | API-071#200:card_stale, API-071#200:not_allowed_now |
| SCR-004#expired | 보낸 지 30분이 지난 카드를 누름(card_expired): '시간이 지나 새 카드를 보내 드려요'와 지금 값으로 만든 새 카드. 아무것도 남지 않음. 주문 요청 카드는 새 카드도 규정 글을 먼저 보내고, 요약 카드 맨 위에 그 말을 둠(DEC-22) | API-071#200:card_expired |
| SCR-004#day-full | 기본 디자인 주문의 자리를 같은 트랜잭션에서 잡지 못함(day_full, 주문 요청도 남지 않음): '그 사이 그날이 다 찼어요. 이날은 어떠세요?'와 가까운 날 최대 3개 바로가기. 없으면 '가까운 날에 자리가 없어요. 사장님께 확인을 요청할 수 있어요'. 그날 자리는 잡지 않고, 손님이 그래도 그날을 원하면 사장님께 에스컬레이션(SCR-003#handed-over, REQ-225) | API-071#200:day_full |
| SCR-004#permission | 카드를 받은 사용자가 아님(card_not_yours): '이 버튼은 카드를 받은 분만 누를 수 있어요'. 아무것도 남지 않음. 그 사이 채널 연결이 끊긴 가게(not_accepting): '아직 상담을 받지 않아요. 가게로 연락해 주세요: {가게 연락처}' | API-071#200:card_not_yours, API-071#200:not_accepting |
| SCR-004#error | 쓰기 하나가 실패해 하나도 남기지 않음(retry_needed): '다시 눌러 주세요'. 서버 오류(server_error): '잠시 뒤 다시 말씀해 주세요'. 스킬 키가 틀리거나 형식이 아니거나 예상하지 못한 실패(401·422·default): 카카오톡이 자기 오류 말을 보임(우리 문구 없음, DEC-07). 서버 로그에 추적 ID | API-071#200:retry_needed, API-071#200:server_error, API-071#401:skill_key_invalid, API-071#422:validation_failed, API-071#default:internal |
| loading (해당 없음) | 버튼을 누른 뒤 답이 올 때까지는 카카오톡이 자기 표시를 함. 우리가 그릴 것이 없음 |  |
| empty (해당 없음) | 카드는 서버가 저장된 값이 있을 때만 만들어 보임(SPEC-069). 빈 카드는 없음 |  |

## 케이스 유형

| 케이스 유형 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 카드를 받은 같은 카카오 사용자만 누름. 다른 사람은 SCR-004#permission, 스킬 키가 틀리면 SCR-004#error |
| 입력 | 카드 값은 서버 기록에서만 옴. 주문자 이름·연락처는 AI를 거치지 않는 '주문자 정보' 블록으로만 받고, 이름 1~30자·연락처 숫자와 '-' 8~14자가 아니면 SCR-004#orderer로 다시 물음(input_invalid). 알레르기 답은 알레르기 정보에 동의한 뒤 '알레르기 답' 블록으로만 받고 1~200자가 아니면 SCR-004#allergy로 다시 물음. 스킬 요청 형식이 아니면 SCR-004#error |
| 대상 | 지금 상태에서 받을 수 없는 명령은 '지금은 할 수 없어요: {지금 상태}'(SCR-004#stale) |
| 상태 변화 | 버전이 바뀐 카드는 SCR-004#stale, 30분이 지난 카드는 SCR-004#expired. 둘 다 새 카드를 보내고 아무것도 남기지 않음 |
| 반복 | 같은 카드를 다시 누르면 처음 결과를 다시 보냄(SCR-004#done, card_used). 명령은 한 번 |
| 동시 변경 | 같은 날 마지막 자리를 두 손님이 함께 누르면 하나만 잡히고 다른 쪽은 SCR-004#day-full(R11). 카드 뒤 버전이 바뀌면 SCR-004#stale. 알레르기 정보 카드는 그 뒤 초안이 바뀌어도 거절하지 않고 받은 동의와 답을 남김(SPEC-075) |
| 외부 서비스 | 트랜잭션의 쓰기 하나가 실패하면 하나도 남기지 않고 '다시 눌러 주세요'(SCR-004#error) |
| 데이터 노출 | 카드와 결과에 다른 손님 정보·내부 ID(주문번호 밖)·오류 내용 없음(G6). 주문자 이름·연락처와 알레르기 답은 AI로 보내지 않음(REQ-178, REQ-204). 알레르기 답은 로그·사장님 알림에도 없음 |
| AI 답 | AI는 카드를 제안만 하고 카드의 값(금액·버전·환불)은 서버 기록에서 만듦(SPEC-069). AI 말로 카드 값을 바꿀 수 없음 |
| 한도 | 한 응답의 출력 3개 안에서 규정 글은 1,000자 글 둘까지, 요약 카드는 제목과 설명을 합쳐 400자. 글 둘에 들어가지 않는 운영규정은 저장되지 않음(SCR-038#error, REQ-184) |
| 화면 상태 | 상태마다 360·1280 와이어프레임(`wireframes.html#SCR-004`) |
