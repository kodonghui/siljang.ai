# SCR-007 내 주문 보기

- 경로: `kakao:shop/my-order`
- 접근 권한: 주문한 손님
- 상위 화면: SCR-003 가게 채널 상담
- 화면 레이아웃: 카카오톡 채널 대화 화면(1280은 PC 카카오톡 창)
- 플로우: FL-008, FL-011
- 관련 SPEC: SPEC-040
- API: API-070
- 와이어프레임: `wireframes.html#SCR-007`(상태 8개, 360·1280)

목적: 주문한 손님이 상담에서 자기 주문의 상태·픽업 일시·변경 마감 시각·지금 취소하면 받는 환불을 보고 변경·취소·신고 카드로 이어 갑니다. (FL-008, FL-011)

## 데이터

| 데이터 | 출처 |
| --- | --- |
| 주문번호·상태·픽업 일시 | API-070 card_shown(SPEC-040) |
| 변경 마감 시각(그 주문이 받은 운영규정 버전) | API-070 card_shown |
| 지금 취소하면 받는 환불(가게 규칙 계산값)과 쓴 조문 이름 | API-070 card_shown(SPEC-016) |
| 주문이 여럿이면 고르는 바로가기 | API-070 answered |

## 액션

| 액션 | 결과 | 실패 |
| --- | --- | --- |
| 주문 고르기(여럿일 때) | 그 주문의 내 주문 카드 | 찾을 수 없는 주문이면 SCR-007#error |
| 바꾸고 싶어요·취소할래요·문제가 있어요(바로가기) | AI가 내용을 정리해 변경 요청(SCR-008)·취소(SCR-009)·문제 신고(SCR-010) 카드를 보임 | 결제 전 주문의 변경 같은 경우는 그 카드 화면의 stale 문구 |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이 상태로 오는 응답 |
| --- | --- | --- |
| SCR-007#normal | 카드 '내 주문 · {orderNo}': 상태, 픽업 일시, '변경 마감: M월 D일 HH:MM까지', '지금 취소하면 환불 {n}원({조문 이름})'. 바로가기 '바꾸고 싶어요'·'취소할래요'(받은 주문이면 '문제가 있어요') | API-070#200:answered, API-070#200:ai_output_rejected, API-070#200:card_shown, API-070#200:photo_received, API-070#200:duplicate |
| SCR-007#loading | 답이 4초 안에 준비되지 않음: '답을 준비하고 있어요' 뒤 콜백으로 카드가 옴 | API-070#200:callback_pending |
| SCR-007#empty | 이 대화의 사용자가 요청한 주문이 없음: '이 대화로 요청한 주문이 없어요'(SPEC-040) | API-070#200:answered(내용에 따라) |
| SCR-007#error | 주문번호가 없거나 그 가게 주문이 아님: '찾을 수 없는 주문이에요'(있는지 말하지 않음, G1). 서버 오류는 '잠시 뒤 다시 말씀해 주세요', 음성·파일·한도 넘은 사진은 SCR-003#error와 같은 말. 스킬 401·422·default: 카카오톡이 자기 오류 말을 보임(우리 문구 없음, DEC-07). 서버 로그에 추적 ID | API-070#200:answered(내용에 따라), API-070#200:photo_rejected, API-070#200:unsupported_message, API-070#200:server_error, API-070#401:skill_key_invalid, API-070#422:validation_failed, API-070#default:internal |
| SCR-007#permission | 그 주문을 요청한 사용자가 아님: 주문 내용·금액·상태를 하나도 보이지 않고 '사장님 확인 뒤 답드릴게요'(사장님께 에스컬레이션, SPEC-040). 채널 연결이 끊긴 가게는 '아직 상담을 받지 않아요. 가게로 연락해 주세요: {가게 연락처}' | API-070#200:handed_over(내용에 따라), API-070#200:not_accepting |
| SCR-007#stale | 카드는 보인 때 기준. 그 뒤 결제 확인·변경 반영·제작 시작으로 환불 금액이나 마감이 달라질 수 있어, 이어서 누른 카드는 서버가 지금 값으로 다시 확인함(SCR-008#stale·SCR-009#stale). 다시 물으면 새 카드 | API-070#200:card_shown(내용에 따라) |
| SCR-007#handed-over | AI 모델 실패·시간 초과 같은 이유로 답하지 못함: '사장님 확인 뒤 답드릴게요'. 채널 친구가 아니면 채널 추가 권유 | API-070#200:handed_over, API-070#200:ai_unavailable, API-070#200:ai_timeout, API-070#200:ai_key_missing, API-070#200:ai_limit_reached, API-070#200:ai_cost_limit_reached, API-070#200:masking_failed |
| SCR-007#rate-limited | 1분에 20개를 넘게 보냄: 첫 번째에만 '잠시 뒤 다시 말씀해 주세요' | API-070#200:rate_limited |

## 케이스 유형

| 케이스 유형 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 그 주문을 요청한 같은 카카오 사용자만 내 주문 카드를 봄. 다른 사용자는 SCR-007#permission(SPEC-040, G1) |
| 입력 | 주문번호를 잘못 말하면 SCR-007#error의 '찾을 수 없는 주문이에요' |
| 대상 | 없는 주문·다른 가게 주문은 같은 '찾을 수 없는 주문이에요'(있는지 말하지 않음) |
| 상태 변화 | 보인 뒤 상태가 바뀌면 SCR-007#stale. 받은 주문에만 '문제가 있어요'가 보임 |
| 반복 | 같은 요청이 다시 오면 처음 카드를 다시 보냄(duplicate) |
| 동시 변경 | 카드를 보는 동안 사장님이 표시를 바꾸면 이어서 누른 카드가 SCR-008·009의 stale |
| 한도 | 1분 20개를 넘으면 SCR-007#rate-limited |
| 외부 서비스 | AI 모델 실패는 SCR-007#handed-over |
| 데이터 노출 | 다른 사용자에게는 주문 내용·금액·상태를 하나도 보이지 않음(SPEC-040). 환불은 금액과 조문 이름만(근거 시각은 사장님께만, SPEC-016) |
| 빈 응답·끊긴 응답 | 주문이 없으면 SCR-007#empty, 콜백을 기다리는 동안은 SCR-007#loading |
| AI 답 | AI는 환불 금액·마감을 스스로 말하지 않고 카드의 계산값만 말함(SPEC-046). 서버 확인을 지나지 못한 답은 정해진 문장 |
| 화면 상태 | 상태마다 360·1280 와이어프레임(`wireframes.html#SCR-007`) |
