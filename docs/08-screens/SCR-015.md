# SCR-015 가게 등록

- 경로: `/owner/shop/new`
- 접근 권한: 가게 미등록 사장님
- 상위 화면: SCR-014 사장님 로그인
- 화면 레이아웃: 가게 등록 전 사장님 화면(메뉴 없음)
- 플로우: FL-001
- 관련 SPEC: SPEC-002, SPEC-068
- API: API-007, API-008
- 와이어프레임: `wireframes.html#SCR-015`(상태 5개, 360·1280)
- 목업: [`SCR-015-360`](../../research/cake-mockup-2026-11/canvas/project/SCR-015-360.dc.html)(normal·error), [`SCR-015-1280`](../../research/cake-mockup-2026-11/canvas/project/SCR-015-1280.dc.html)(normal). 캔버스의 '사장님 화면' 페이지([09단계 README](../09-mockup/README.md) 2절)

목적: 로그인했지만 가게가 없는 사장님이 가게 정보·사업자 정보·영업 신고 번호와 종류·신고증 사진을 넣고 개인정보 처리 위탁·재위탁 조건에 동의해 가게를 등록합니다. 등록한 가게는 운영자의 영업 신고 확인을 기다립니다. (FL-001)

## 데이터

| 데이터 | 출처 |
| --- | --- |
| 가게 이름(1~40자)·연락처·사업장 주소(1~200자)·전자우편주소·상호·대표자·사업자등록번호(10자리)·통신판매업 신고번호와 그 신고를 받은 기관(1~40자)이나 면제 사유. 예약 링크 페이지의 가게 신원 정보가 됨(REQ-239) | API-008 요청 name·contactPhone·businessAddress·contactEmail·businessName·representativeName·businessRegNo·mailOrderRegNo·mailOrderAuthority·mailOrderExemption |
| 영업 신고 번호(1~30자)와 영업 종류(즉석판매제조·가공업, 제과점영업) | API-008 요청 foodLicenseNo·foodBusinessType |
| 신고증 사진(JPG·PNG·HEIC 한 장, 10MB) | API-007 license_photo → API-008 요청 licensePhotoUploadId |
| 개인정보 처리 위탁·재위탁 조건의 버전과 동의 | API-008 요청 entrustmentTermsVersion·entrustmentConsent |
| 등록 결과: 영업 신고 상태 '확인 중' | API-008 licenseStatus |

## 액션

| 액션 | 결과 | 실패 |
| --- | --- | --- |
| 신고증 사진 올리기 | 사진 미리보기와 '올렸어요'. 1시간 안에 등록해야 씀 | 10MB를 넘음(413 file_too_large)·사진이 아님(422)·너무 자주 올림(429 rate_limited)·저장소 장애(503)는 SCR-015#error의 사진 필드 옆 사유 |
| 등록 | '가게를 등록했어요. 운영자가 영업 신고를 확인하고 있어요' 뒤 할 일 목록(SCR-016)으로 이동 | 필드 오류(422 validation_failed)와 동의하지 않음(422 consent_required)은 SCR-015#error, 이미 가게가 있음(409 already_registered)은 SCR-015#stale, 사진 저장 실패(503)는 등록 전체를 남기지 않고 SCR-015#error |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이 상태로 오는 응답 |
| --- | --- | --- |
| SCR-015#normal | 필드를 한 행에 하나씩: 가게 이름·연락처·사업장 주소·전자우편주소·상호·대표자·사업자등록번호·통신판매업 신고번호와 신고 기관(신고번호가 없으면 '면제 사유' 필드로 바꿈)·영업 신고 번호·영업 종류(라디오 둘)·신고증 사진. 상호·대표자·사업자등록번호 아래 한 줄 '등록 뒤에 바꾸려면 증빙 사진과 함께 변경을 요청해요(운영자가 확인한 뒤 바뀜)'. 아래에 개인정보 처리 위탁·재위탁 조건(버전, 펼쳐 읽음)과 동의 체크(기본 비어 있음), '등록'. 영업 종류가 둘 밖이면 '첫 버전은 영업 신고한 가게만 받아요' | API-007#201:license_photo, API-008#201:registered |
| SCR-015#error | 입력이 한도나 형식에 맞지 않음(422 validation_failed): 필드 옆에 '입력한 내용을 확인해 주세요'와 필드마다의 사유. 넣은 값은 그대로 둠. 동의하지 않음(422 consent_required): 동의 체크박스 옆 '개인정보 처리 위탁 조건에 동의해야 가게를 등록할 수 있어요', 넣은 값은 서버에 남기지 않음(REQ-107). 사진이 10MB를 넘음(413): '사진이 너무 커요. 10MB(완성 사진은 20MB)까지 올릴 수 있어요'. 저장소 장애(503): 06단계 storage_unavailable 문구와 '다시 올리기'. 같은 요청 키로 다른 내용을 보냄(422 idempotency_key_reused): '다시 시도해 주세요'. 새 요청 키로 다시 보냄. 그 밖의 실패: '문제가 생겼어요. 다시 시도해 주세요'와 다시 시도 버튼, 추적 ID | API-007#413:file_too_large, API-007#422:validation_failed, API-007#429:rate_limited, API-007#503:storage_unavailable, API-007#default:internal, API-008#422:validation_failed, API-008#422:consent_required, API-008#422:idempotency_key_reused, API-008#503:storage_unavailable, API-008#default:internal |
| SCR-015#permission | 로그인이 없거나 만료됨(401 unauthenticated): 로그인 화면으로 이동하고, 로그인하면 이 화면으로 돌아옴('다시 로그인해 주세요'). 넣던 글 값(사진과 동의 체크는 빼고)은 이 탭의 세션 저장소에만 남기고, 같은 카카오 계정으로 로그인해 돌아왔을 때만 되살림(남길 때의 사장님 계정과 견주고 다르면 지움). 등록에 성공하거나 로그아웃하거나 1시간이 지나면 지움 | API-007#401:unauthenticated, API-008#401:unauthenticated |
| SCR-015#stale | 그 사이 같은 카카오 계정으로 가게가 등록됨(409 already_registered): '이미 등록한 가게가 있어요'와 할 일 목록(SCR-016)으로 이동. 두 번째 가게는 만들지 않음(SPEC-002) | API-008#409:already_registered |
| SCR-015#submitting | 누른 버튼이 '처리하고 있어요'로 바뀌고 이 화면의 다른 액션과 함께 막힘. 첫 요청을 아직 처리하는 중이면(409 request_in_progress) 1초 뒤 같은 요청 키로 다시 보내고, 결과는 한 번만 보임 | API-008#409:request_in_progress |
| loading (해당 없음) | 불러올 데이터가 없는 입력 화면. 사진을 올리거나 등록하는 동안은 SCR-015#submitting |  |
| empty (해당 없음) | 처음부터 빈 필드인 모습이 SCR-015#normal |  |

## 케이스 유형

| 케이스 유형 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 로그인한 사장님만. 401은 SCR-015#permission |
| 입력 | 가게 이름 1~40자, 연락처는 전화번호 형식, 사업장 주소 1~200자, 전자우편주소는 '@'가 있는 3~100자, 사업자등록번호는 10자리와 검증 숫자, 통신판매업 신고번호를 넣으면 신고 기관 1~40자(비면 /mailOrderAuthority required), 영업 신고 번호 1~30자. 틀린 필드는 SCR-015#error에서 필드 옆에 사유, 넣은 값은 그대로 |
| 한도 | 신고증 사진 한 장 10MB(SCR-015#error의 file_too_large 문구) |
| 상태 변화 | 동의하지 않으면 등록하지 않고 넣은 값도 서버에 남기지 않음(SCR-015#error, REQ-107). 이미 가게가 있으면 SCR-015#stale |
| 반복 | 등록을 두 번 눌러도 가게는 하나(같은 요청 키, SCR-015#submitting) |
| 동시 변경 | 같은 사업자등록번호로 다른 계정이 등록해도 받고, 운영자 확인 화면에 중복으로 표시(SCR-048) |
| 외부 서비스 | 사진 저장 실패(503)는 등록 전체를 남기지 않고 SCR-015#error에서 다시 올리게 함 |
| 데이터 노출 | 신고증 사진은 그 가게 사장님과 운영자만 봄(G1, G6) |
| 화면 상태 | 상태마다 360·1280 와이어프레임(`wireframes.html#SCR-015`) |
