# SCR-020 주문 목록

- 경로: `/owner/orders`
- 접근 권한: 사장님
- 상위 화면: SCR-014 사장님 로그인
- 화면 레이아웃: 사장님 화면(1280 왼쪽 메뉴, 360 위쪽 막대와 메뉴 버튼)
- 플로우: 플로우 노드 없음(주문 상세로 이동하는 목록이고, 플로우 노드는 주문 상세와 그 하위 화면에 있음)
- 관련 SPEC: SPEC-031, SPEC-037, SPEC-068
- API: API-044
- 와이어프레임: `wireframes.html#SCR-020`(상태 6개, 360·1280)
- 목업: [`SCR-020-360`](../../research/cake-mockup-2026-11/canvas/project/SCR-020-360.dc.html)(normal·empty·error), [`SCR-020-1280`](../../research/cake-mockup-2026-11/canvas/project/SCR-020-1280.dc.html)(normal). 캔버스의 '사장님 화면' 페이지([09단계 README](../09-mockup/README.md) 2절)

목적: 사장님이 주문을 상태·종류·픽업 날짜로 걸러 보고 눌러 주문 상세를 엽니다. 결제 기한 지난 주문과 답할 맞춤 주문도 이 필터로 봅니다. (플로우 노드 없음: 주문 상세로 이동하는 목록이고, 플로우 노드는 주문 상세와 그 하위 화면에 있음)

## 데이터

| 데이터 | 출처 |
| --- | --- |
| 주문: 주문번호·종류(기본 디자인·맞춤)·상태·버전·픽업 일시·퀵 여부·금액·손님 이름·요청 시각·재제작 여부 | API-044 items |
| 다음 페이지 | API-044 nextCursor |

## 액션

| 액션 | 결과 | 실패 |
| --- | --- | --- |
| 필터(상태·종류·픽업 날짜 범위) | 조건에 맞는 주문을 다시 불러옴. 필터는 주소에 남아 새로 고쳐도 유지 | 날짜 범위가 틀리면(422) SCR-020#error의 필터 필드 옆 사유 |
| 주문 누르기 | 주문 상세(SCR-021) | 그 화면의 상태 |
| 더 보기 | 다음 페이지를 목록 아래에 추가로 불러옴 | 실패하면 목록 끝에 '다시 시도' |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이 상태로 오는 응답 |
| --- | --- | --- |
| SCR-020#normal | 위에 필터(상태·종류·픽업 날짜). 1280: 표(주문번호·종류·상태·픽업 일시·손님·금액), 360: 주문마다 카드. 재제작 주문은 '재제작'과 0원, 퀵은 '퀵' 라벨 | API-044#200:orders, API-044#200:overdue |
| SCR-020#loading | 레이아웃은 그대로 두고 데이터 자리에 회색 막대를 보임. 액션 버튼은 누를 수 없음 | (데이터를 불러오는 동안) |
| SCR-020#empty | '조건에 맞는 주문이 없어요'와 '필터 지우기'. 주문이 하나도 없는 가게도 같은 문구 | API-044#200:empty |
| SCR-020#error | 주소의 필터·페이지 값이 틀림(422 validation_failed): '입력한 내용을 확인해 주세요'와 '처음부터 보기'. 그 밖의 실패: '문제가 생겼어요. 다시 시도해 주세요'와 다시 시도 버튼, 추적 ID | API-044#422:validation_failed, API-044#default:internal |
| SCR-020#permission | 로그인이 없거나 만료됨(401 unauthenticated): 로그인 화면으로 이동하고, 로그인하면 이 화면으로 돌아옴('다시 로그인해 주세요'). 로그인한 사장님에게 가게가 아직 없음(404 shop_not_registered): 가게가 없으면 가게 등록(SCR-015)으로 보냄('가게를 먼저 등록해 주세요') | API-044#401:unauthenticated, API-044#404:shop_not_registered |
| SCR-020#stale | 목록은 연 시각 기준이라 그 뒤 바뀐 것이 안 보일 수 있음: 맨 위에 'HH:MM 기준'과 '새로 고침'. 다른 화면에서 처리하고 돌아오면 다시 불러옴 | - |

## 응답과 상태

06단계 계약(`api/openapi.yaml`)의 응답마다 화면 상태 하나입니다. 오류의 문구는 06단계 오류 코드 표의 '화면에 보이는 말'입니다.

| 응답 | 화면 상태 | 화면에 보이는 것 |
| --- | --- | --- |
| API-044#200:orders | SCR-020#normal | 주문 목록 |
| API-044#200:overdue | SCR-020#normal | 결제 기한 지난 주문만 걸러 본 목록 |
| API-044#200:empty | SCR-020#empty | '조건에 맞는 주문이 없어요' |
| API-044#401:unauthenticated | SCR-020#permission | '다시 로그인해 주세요' |
| API-044#404:shop_not_registered | SCR-020#permission | '가게를 먼저 등록해 주세요' |
| API-044#422:validation_failed | SCR-020#error | '입력한 내용을 확인해 주세요' |
| API-044#default:internal | SCR-020#error | '문제가 생겼어요. 다시 시도해 주세요' |

## 케이스 유형

| 케이스 유형 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 로그인한 사장님의 가게 주문만(SPEC-068). 401은 SCR-020#permission |
| 입력 | 필터 값이 틀리면 SCR-020#error |
| 대상 | 가게가 없으면 SCR-020#permission에서 가게 등록으로 |
| 데이터 노출 | 목록에는 손님 이름만. 연락처·알레르기는 주문 상세에서 |
| 빈 응답·끊긴 응답 | 조건에 맞는 주문이 없으면 SCR-020#empty |
| 화면 상태 | 상태마다 360·1280 와이어프레임(`wireframes.html#SCR-020`) |
