# SCR-010 문제 신고 카드

- 경로: `kakao:shop/card/issue_report`
- 접근 권한: 주문한 손님
- 상위 화면: SCR-007 내 주문 보기
- 화면 레이아웃: 카카오톡 채널 대화 화면(1280은 PC 카카오톡 창)
- 플로우: FL-011
- 관련 SPEC: SPEC-057, SPEC-058, SPEC-069
- API: API-071
- 와이어프레임: `wireframes.html#SCR-010`(상태 6개, 360·1280)
- 목업: [`SCR-010-360`](../../research/cake-mockup-2026-11/canvas/project/SCR-010-360.dc.html)(normal·expired·error), [`SCR-010-1280`](../../research/cake-mockup-2026-11/canvas/project/SCR-010-1280.dc.html)(normal). 캔버스의 '손님 화면' 페이지([09단계 README](../09-mockup/README.md) 2절)

목적: 받은 주문의 손님이 AI 상담이 모은 신고 내용(사진·설명·주문번호)을 확인하고 문제 신고 버튼을 누릅니다. (FL-011)

## 데이터

| 데이터 | 출처 |
| --- | --- |
| 신고 내용: 사진(5장까지)·설명(1~1,000자)·주문번호 | API-071 카드(처음 카드는 SCR-003의 API-070 card_shown) |
| 몸이 불편하다는 말이 있으면 '몸이 불편하시면 병원 진료를 먼저 받으세요' | API-071 카드(SPEC-057) |

## 액션

| 액션 | 결과 | 실패 |
| --- | --- | --- |
| 문제 신고 | 그 주문에 문제 신고를 남기고 사장님께 알림. 신고 기한(기본 받은 뒤 24시간) 뒤면 받되 '기한 뒤'로 남김(SPEC-058) | 받은 주문이 아니면 SCR-010#stale(받기 전 문제는 에스컬레이션 건, SPEC-056), 30분이 지났으면 SCR-010#expired |
| 안 할래요 | 아무것도 남기지 않고 '알겠어요. 더 궁금한 것이 있으면 말씀해 주세요' | 서버 오류면 SCR-010#error |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이 상태로 오는 응답 |
| --- | --- | --- |
| SCR-010#normal | 카드 하나: '문제 신고', 주문번호·받은 날, 사진 수와 설명 앞부분, 'HH:MM까지 눌러 주세요', 버튼 '문제 신고'·'안 할래요'. 원인·책임·보상은 말하지 않음 | - |
| SCR-010#done | '신고를 받았어요. 사장님이 보시고 정하실 거예요'. 기한 뒤여도 같은 말. 같은 카드를 다시 누르면 같은 말(card_used). 같은 주문의 두 번째 신고는 첫 신고에 이어짐 | API-071#200:issue_reported, API-071#200:declined, API-071#200:card_used |
| SCR-010#stale | 카드 뒤 주문 상태가 바뀜(card_stale): 새 카드. 받은 주문이 아님(not_allowed_now): '지금은 할 수 없어요: 아직 받지 않은 주문이에요'(그 문제는 사장님께 에스컬레이션 건으로 감) | API-071#200:card_stale, API-071#200:not_allowed_now |
| SCR-010#expired | 보낸 지 30분이 지난 카드를 누름(card_expired): '시간이 지나 새 카드를 보내 드려요'와 지금 값으로 만든 새 카드. 아무것도 남지 않음 | API-071#200:card_expired |
| SCR-010#permission | 카드를 받은 사용자가 아님(card_not_yours): '이 버튼은 카드를 받은 분만 누를 수 있어요'. 아무것도 남지 않음. 그 사이 채널 연결이 끊긴 가게(not_accepting): '아직 상담을 받지 않아요. 가게로 연락해 주세요: {가게 연락처}' | API-071#200:card_not_yours, API-071#200:not_accepting |
| SCR-010#error | 쓰기 하나가 실패해 하나도 남기지 않음(retry_needed): '다시 눌러 주세요'. 서버 오류(server_error): '잠시 뒤 다시 말씀해 주세요'. 스킬 키가 틀리거나 형식이 아니거나 예상하지 못한 실패(401·422·default): 카카오톡이 자기 오류 말을 보임(우리 문구 없음, DEC-07). 서버 로그에 추적 ID | API-071#200:retry_needed, API-071#200:server_error, API-071#401:skill_key_invalid, API-071#422:validation_failed, API-071#default:internal |
| loading (해당 없음) | 버튼을 누른 뒤 답이 올 때까지는 카카오톡이 자기 표시를 함. 우리가 그릴 것이 없음 |  |
| empty (해당 없음) | 카드는 서버가 저장된 값이 있을 때만 만들어 보임(SPEC-069). 빈 카드는 없음 |  |

## 케이스 유형

| 케이스 유형 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 카드를 받은 같은 카카오 사용자만 누름. 다른 사람은 SCR-010#permission, 스킬 키가 틀리면 SCR-010#error |
| 입력 | 카드 값은 서버 기록에서만 오고 손님 말로 바꿀 수 없음. 스킬 요청 형식이 아니면 SCR-010#error |
| 대상 | 지금 상태에서 받을 수 없는 명령은 '지금은 할 수 없어요: {지금 상태}'(SCR-010#stale) |
| 상태 변화 | 버전이 바뀐 카드는 SCR-010#stale, 30분이 지난 카드는 SCR-010#expired. 둘 다 새 카드를 보내고 아무것도 남기지 않음 |
| 반복 | 같은 카드를 다시 누르면 처음 결과를 다시 보냄(SCR-010#done, card_used). 명령은 한 번 |
| 동시 변경 | 카드를 보낸 뒤 다른 쓰기가 먼저 이기면 SCR-010#stale |
| 외부 서비스 | 트랜잭션의 쓰기 하나가 실패하면 하나도 남기지 않고 '다시 눌러 주세요'(SCR-010#error) |
| 데이터 노출 | 카드와 결과에 다른 손님 정보·내부 ID(주문번호 밖)·오류 내용 없음(G6). 서버 오류도 '잠시 뒤 다시 말씀해 주세요'만 |
| AI 답 | AI는 원인·책임·보상을 말하지 않음. 그런 답은 서버가 버리고 '사장님이 보시고 정하실 거예요'(SPEC-057) |
| 화면 상태 | 상태마다 360·1280 와이어프레임(`wireframes.html#SCR-010`) |
