# SCR-025 환불 결정

- 경로: `/owner/orders/:orderId/refund-decision`
- 접근 권한: 사장님
- 상위 화면: SCR-021 주문 상세
- 화면 레이아웃: 사장님 화면(1280 왼쪽 메뉴, 360 위쪽 막대와 메뉴 버튼)
- 플로우: FL-008, FL-009
- 관련 SPEC: SPEC-047, SPEC-016
- API: API-049, API-050
- 와이어프레임: `wireframes.html#SCR-025`(상태 7개, 360·1280)

목적: 사장님이 가게 규칙이 계산한 환불 금액과 근거(운영규정 버전·조문·취소 시각·맞춤 재료 주문 시각·제작 시작 시각)를 보고 전액 환불·일부 환불·환불 없음 가운데 하나로 환불을 정합니다. (FL-008, FL-009)

## 데이터

| 데이터 | 출처 |
| --- | --- |
| 주문번호와 환불 원인(손님 취소·가게 사정 취소·변경으로 금액 내려감·취소된 주문에 들어온 입금) | API-049 order·cause |
| 받은 금액·이미 정한 환불·환불 계산값·정할 수 있는 최대 금액 | API-049 receivedAmount·refundedAmount·calculatedAmount·maxAmount |
| 근거: 운영규정 버전·조문 이름·취소 시각·맞춤 재료 주문 시각·제작 시작 시각·단계별 환불 비율·취소 수수료 | API-049 basis |

## 액션

| 액션 | 결과 | 실패 |
| --- | --- | --- |
| 환불 결정(전액·일부·없음) | '환불을 정했어요. 가게 계좌에서 보낸 뒤 보냄을 눌러 주세요' 뒤 환불 송금(SCR-026). 손님이 채널 친구가 아니면 '안내는 다음 대화 때 전해요'를 덧붙임 | 금액이 최대 금액을 넘음(422)·계산값과 다른데 사유가 없음(422)은 SCR-025#error의 필드 옆, 이미 정함(already_decided)·지금 상태에서 할 수 없음(invalid_state)·본 뒤 바뀜은 SCR-025#stale |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이 상태로 오는 응답 |
| --- | --- | --- |
| SCR-025#normal | 위에 '환불 계산값 31,000원'(크게)과 근거(운영규정 버전·조문·취소 시각·맞춤 재료 주문 시각·제작 시작 시각·취소 수수료·받은 금액). 아래 '전액 환불'·'일부 환불(금액)'·'환불 없음', 계산값과 다른 금액이면 사유 필드(1~200자)가 나타남, '환불 결정'. '우리는 돈을 옮기지 않아요. 가게 계좌에서 보내 주세요'(REQ-079) | API-049#200:customer_cancel, API-049#200:shop_cancel |
| SCR-025#loading | 레이아웃은 그대로 두고 데이터 자리에 회색 막대를 보임. 액션 버튼은 누를 수 없음. 계산값 자리는 큰 글자 높이의 회색 막대 | (데이터를 불러오는 동안) |
| SCR-025#error | 없거나 다른 가게의 주문(404 not_found): '찾을 수 없어요'와 '주문 목록으로' 링크(SCR-020). 다른 가게 기록이 있는지는 말하지 않음(G1). 입력이 한도나 형식에 맞지 않음(422 validation_failed): 필드 옆에 '입력한 내용을 확인해 주세요'와 필드마다의 사유. 넣은 값은 그대로 둠(최대 금액은 필드 아래 '최대 {maxAmount}원까지'). 같은 요청 키로 다른 내용을 보냄(422 idempotency_key_reused): '다시 시도해 주세요'. 새 요청 키로 다시 보냄. 그 밖의 실패: '문제가 생겼어요. 다시 시도해 주세요'와 다시 시도 버튼, 추적 ID | API-049#404:not_found, API-049#422:validation_failed, API-049#default:internal, API-050#404:not_found, API-050#422:validation_failed, API-050#422:idempotency_key_reused, API-050#default:internal |
| SCR-025#permission | 로그인이 없거나 만료됨(401 unauthenticated): 로그인 화면으로 이동하고, 로그인하면 이 화면으로 돌아옴('다시 로그인해 주세요') | API-049#401:unauthenticated, API-050#401:unauthenticated |
| SCR-025#stale | 이미 정한 환불(already_decided): '이미 처리됐어요'와 환불 송금(SCR-026) 링크. 지금 상태에서 할 수 없음(invalid_state): '지금 상태에서는 할 수 없어요'. 본 뒤 바뀜(version_conflict, 제작 시작 표시 등으로 계산값이 바뀜): '그 사이 바뀌었어요. 지금 상태를 확인해 주세요'와 다시 읽은 지금 상태와 새 계산값 | API-050#409:version_conflict, API-050#409:already_decided, API-050#409:invalid_state |
| SCR-025#submitting | 누른 버튼이 '처리하고 있어요'로 바뀌고 이 화면의 다른 액션과 함께 막힘. 첫 요청을 아직 처리하는 중이면(409 request_in_progress) 1초 뒤 같은 요청 키로 다시 보내고, 결과는 한 번만 보임 | API-050#409:request_in_progress |
| SCR-025#done | 정함(decided)·안내는 다음 대화 때(deferred_notice): 결과 문구 뒤 환불 송금(SCR-026)으로 이동 | API-050#201:decided, API-050#201:deferred_notice |
| empty (해당 없음) | 환불 결정은 받은 금액이 있는 주문에만 열림. 결제 전 취소는 환불 할 일이 생기지 않음(SPEC-046) |  |

## 케이스 유형

| 케이스 유형 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 그 가게 주문만(SCR-025#error, G1) |
| 입력 | 환불 금액은 0원 넘고 받은 금액 - 이미 정한 환불 이하(REQ-086). 넘으면 SCR-025#error |
| 대상 | 없는 주문은 SCR-025#error |
| 상태 변화 | 계산값과 다른 금액은 사유를 받고 남김(SPEC-047). 이미 정했으면 SCR-025#stale |
| 반복 | 같은 환불을 두 번 정하지 않음(같은 요청 키, SCR-025#submitting) |
| 동시 변경 | 보는 사이 제작 시작 표시로 계산값이 바뀌면 SCR-025#stale에서 새 계산값 |
| 외부 서비스 | 손님이 채널 친구가 아니면 환불 안내는 다음 대화 때(SCR-025#done) |
| 데이터 노출 | 근거는 사장님께 전부, 손님에게는 금액과 조문 이름만(SPEC-016). 우리는 돈을 옮기지 않음(REQ-079) |
| 화면 상태 | 상태마다 360·1280 와이어프레임(`wireframes.html#SCR-025`) |
