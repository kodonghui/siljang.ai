# SCR-022 맞춤 주문 검토

- 경로: `/owner/orders/:orderId/custom-decision`
- 접근 권한: 사장님
- 상위 화면: SCR-021 주문 상세
- 화면 레이아웃: 사장님 화면(1280 왼쪽 메뉴, 360 위쪽 막대와 메뉴 버튼)
- 플로우: FL-006
- 관련 SPEC: SPEC-031
- API: API-045, API-046
- 와이어프레임: `wireframes.html#SCR-022`(상태 8개, 360·1280)
- 목업: [`SCR-022-360`](../../research/cake-mockup-2026-11/canvas/project/SCR-022-360.dc.html)(normal·error·confirm), [`SCR-022-1280`](../../research/cake-mockup-2026-11/canvas/project/SCR-022-1280.dc.html)(normal). 캔버스의 '사장님 화면' 페이지([09단계 README](../09-mockup/README.md) 2절)

목적: 사장님이 맞춤 주문 요청의 참고 사진·견적 계산값·그날 남은 자리를 보고 수락·금액 변경 수락·거절 가운데 하나를 고릅니다. (FL-006)

## 데이터

| 데이터 | 출처 |
| --- | --- |
| 요청 내용(픽업 일시·크기·맛·디자인·문구·색·도안 메모·알레르기 답)과 요청 시각 | API-045 details·requestedAt |
| 참고 사진(10장까지) | API-045 referencePhotos |
| 견적 계산값(가게 규칙) | API-045 quote |
| 그날 하루 최대 개수·잡힌 자리·남은 자리 | API-045 day |

## 액션

| 액션 | 결과 | 실패 |
| --- | --- | --- |
| 수락 | '수락했어요. 손님에게 결제 안내를 보냈어요'. 그날 자리를 결제 기한까지 잡음 | 그날 남은 자리가 없거나 휴무일이면 SCR-022#confirm, 손님이 그 사이 취소함(409 order_cancelled)·이미 답함(already_decided)·맞춤 주문 요청이 아니거나 답 없어 닫힘(invalid_state)·본 뒤 바뀜(version_conflict)은 SCR-022#stale |
| 금액 변경 수락 | 금액(1원~1,000만 원)과 사유(1~200자)를 넣고 수락. 손님에게 '요청 금액 → 바뀐 금액'이 담긴 결제 안내. 같은 금액이면 수락으로 봄 | 금액·사유가 한도 밖(422)은 SCR-022#error의 필드 옆. 그 밖은 수락과 같음 |
| 거절 | 사유(0~200자)를 넣고 거절: '거절했어요. 손님에게 알렸어요' | 이미 답함·취소됨은 SCR-022#stale |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이 상태로 오는 응답 |
| --- | --- | --- |
| SCR-022#normal | 1280: 왼쪽 참고 사진, 오른쪽 요청 내용·견적 계산값·그날 자리('남은 자리 2 / 하루 최대 5'). 아래 '수락'·'금액 변경 수락'·'거절'. 금액 변경과 거절은 누르면 금액·사유 필드가 펼쳐짐. 남은 자리가 0이면 '남은 자리 0'을 굵게. 그 픽업 날짜의 주문 마감(요청 때 이미 지났으면 픽업 일시)까지 답하지 않으면 요청이 '답 없어 닫힘'으로 닫힘(REQ-213) | API-045#200:custom_requested |
| SCR-022#loading | 레이아웃은 그대로 두고 데이터 자리에 회색 막대를 보임. 액션 버튼은 누를 수 없음. 사진 영역은 정사각형 회색 | (데이터를 불러오는 동안) |
| SCR-022#error | 없거나 다른 가게의 주문(404 not_found): '찾을 수 없어요'와 '주문 목록으로' 링크(SCR-020). 다른 가게 기록이 있는지는 말하지 않음(G1). 입력이 한도나 형식에 맞지 않음(422 validation_failed): 필드 옆에 '입력한 내용을 확인해 주세요'와 필드마다의 사유. 넣은 값은 그대로 둠. 같은 요청 키로 다른 내용을 보냄(422 idempotency_key_reused): '다시 시도해 주세요'. 새 요청 키로 다시 보냄. 그 밖의 실패: '문제가 생겼어요. 다시 시도해 주세요'와 다시 시도 버튼, 추적 ID | API-045#404:not_found, API-045#default:internal, API-046#404:not_found, API-046#422:validation_failed, API-046#422:idempotency_key_reused, API-046#default:internal |
| SCR-022#permission | 로그인이 없거나 만료됨(401 unauthenticated): 로그인 화면으로 이동하고, 로그인하면 이 화면으로 돌아옴('다시 로그인해 주세요') | API-045#401:unauthenticated, API-046#401:unauthenticated |
| SCR-022#stale | 손님이 그 사이 취소함(order_cancelled): '그 사이 주문이 취소됐어요'. 이미 답함(already_decided): '이미 처리됐어요'와 고른 답. 맞춤 주문 요청이 아님(invalid_state): '지금 상태에서는 할 수 없어요'. 주문 마감까지 답이 없어 닫힌 요청(custom_no_answer, 수락·거절하면 409 invalid_state): '답이 없어 닫혔어요. 손님에게 알렸어요'와 주문 상세(SCR-021) 링크. 본 뒤 바뀜(version_conflict): '그 사이 바뀌었어요. 지금 상태를 확인해 주세요'와 다시 읽은 지금 상태. 맞춤 주문 요청이 아닌 주문(이미 답했거나 기본 디자인 주문): '이미 처리됐어요'와 주문 상세(SCR-021) 링크 | API-045#200:confirmed, API-045#200:changed, API-045#200:remake, API-045#200:custom_no_answer, API-046#409:version_conflict, API-046#409:already_decided, API-046#409:order_cancelled, API-046#409:invalid_state |
| SCR-022#submitting | 누른 버튼이 '처리하고 있어요'로 바뀌고 이 화면의 다른 액션과 함께 막힘. 첫 요청을 아직 처리하는 중이면(409 request_in_progress) 1초 뒤 같은 요청 키로 다시 보내고, 결과는 한 번만 보임 | API-046#409:request_in_progress |
| SCR-022#confirm | 저장하기 전에 사장님 확인이 필요함(409 confirmation_required, overbooking): 확인 창에 '그날 남은 자리가 없어요. 추가로 받을까요?'. '추가로 받기'를 누르면 confirm에 overbooking를 넣고 새 요청 키로 다시 보냄. '취소'면 아무것도 바뀌지 않음. 추가로 받으면 하루 최대 개수를 초과해 그날 자리를 잡고(마감 후 추가 수락), 그날은 다른 손님에게 계속 마감(R10). 요청한 날이 휴무일이면(closed_day) 같은 창에 '휴무일이에요. 이날로 정할까요?'를 보이고, 확인하면 마감 후 추가 수락으로 잡음(REQ-221) | API-046#409:confirmation_required |
| SCR-022#done | 수락·금액 변경 수락·거절 결과 문구 뒤 주문 상세(SCR-021)로 돌아감 | API-046#200:accepted, API-046#200:rejected |
| empty (해당 없음) | 맞춤 주문 요청은 요청 내용이 있을 때만 생김. 참고 사진이 없으면 사진 자리에 '참고 사진 없음'(normal 안에서) |  |

## 케이스 유형

| 케이스 유형 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 그 가게 주문만(SCR-022#error, G1) |
| 입력 | 바꾼 금액 1원~1,000만 원, 사유 1~200자, 거절 사유 0~200자. 틀리면 SCR-022#error의 필드 옆 |
| 대상 | 없는 주문은 SCR-022#error |
| 상태 변화 | 이미 답함·손님 취소는 SCR-022#stale, 남은 자리가 없거나 휴무일이면 SCR-022#confirm에서 추가 수락을 확인받음(SPEC-031, REQ-221). 주문 마감까지 답이 없어 닫힌 요청은 SCR-022#stale(REQ-213) |
| 반복 | 버튼을 두 번 눌러도 한 번(같은 요청 키, SCR-022#submitting) |
| 동시 변경 | 손님 취소와 동시에 일어나면 먼저 남긴 것이 이기고 뒤는 SCR-022#stale(G3) |
| 데이터 노출 | 참고 사진은 그 가게 사장님 화면에만(SPEC-019) |
| 화면 상태 | 상태마다 360·1280 와이어프레임(`wireframes.html#SCR-022`) |
