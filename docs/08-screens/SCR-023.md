# SCR-023 결제 기한 지난 주문

- 경로: `/owner/orders/:orderId/overdue-decision`
- 접근 권한: 사장님
- 상위 화면: SCR-021 주문 상세
- 화면 레이아웃: 사장님 화면(1280 왼쪽 메뉴, 360 위쪽 막대와 메뉴 버튼)
- 플로우: FL-007
- 관련 SPEC: SPEC-037, SPEC-038, SPEC-039
- API: API-045, API-047
- 와이어프레임: `wireframes.html#SCR-023`(상태 9개, 360·1280)
- 목업: [`SCR-023-360`](../../research/cake-mockup-2026-11/canvas/project/SCR-023-360.dc.html)(normal·error·confirm-notify·confirm), [`SCR-023-1280`](../../research/cake-mockup-2026-11/canvas/project/SCR-023-1280.dc.html)(normal). 캔버스의 '사장님 화면' 페이지([09단계 README](../09-mockup/README.md) 2절)

목적: 사장님이 결제 기한이 지나 자리가 풀린 주문과 그날 남은 자리를 보고 결제 기한 연장이나 취소를 고릅니다. (FL-007)

## 데이터

| 데이터 | 출처 |
| --- | --- |
| 주문 요약·픽업 일시·금액·손님 이름 | API-045 details |
| 결제 안내(종류·금액·손님에게 전해진 시각이나 '아직 못 전함'·결제 기한·상태·손님 확인 기다림) | API-045 paymentRequests(deliveredAt·needsAmountConfirm·amountConfirmedAt) |
| 그날 하루 최대 개수·잡힌 자리·남은 자리 | API-045 day |

## 액션

| 액션 | 결과 | 실패 |
| --- | --- | --- |
| 결제 기한 연장 | 그날 자리를 새 결제 기한까지 다시 잡고 새 결제 안내를 보냄: '결제 기한을 연장했어요. 새 결제 안내를 보냈어요'. 손님이 새 금액을 확인하지 않은 채 기한이 지난 맞춤 주문이면 새 결제 안내도 새 금액 확인 카드부터 감(SPEC-076) | 남은 자리가 없거나 휴무일이거나 그 픽업 날짜의 주문 마감이 지났으면 SCR-023#confirm, 픽업 일시가 지남(409 invalid_state)이면 SCR-023#stale에서 취소만 보임, 그 사이 결제가 확인됨(already_decided)·본 뒤 바뀜(version_conflict)은 SCR-023#stale |
| 주문 취소 | 확인 창(SCR-023#confirm-notify)을 거쳐 주문을 '결제 없어 취소됨'으로 두고 손님에게 알림: '취소했어요. 손님에게 알렸어요' | 그 사이 결제가 확인됨은 SCR-023#stale |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이 상태로 오는 응답 |
| --- | --- | --- |
| SCR-023#normal | '결제 기한 M월 D일 HH:MM에 지나 자리가 풀렸어요', 주문 요약, 그날 자리('남은 자리 1 / 하루 최대 5'), '결제 기한 연장'·'주문 취소'. 결제 안내가 손님에게 전해진 시각이나 '아직 못 전함'(SPEC-037). 픽업 일시가 지났으면 연장 버튼 대신 '연장할 수 없어요(픽업 일시 지남)'와 '주문 취소'만. 사장님이 픽업 일시까지 고르지 않으면 서버가 결제 없어 취소로 두고 손님에게 알림(REQ-217) | API-045#200:status=payment_overdue |
| SCR-023#loading | 레이아웃은 그대로 두고 데이터 자리에 회색 막대를 보임. 액션 버튼은 누를 수 없음 | (데이터를 불러오는 동안) |
| SCR-023#error | 없거나 다른 가게의 주문(404 not_found): '찾을 수 없어요'와 '주문 목록으로' 링크(SCR-020). 다른 가게 기록이 있는지는 말하지 않음(G1). 같은 요청 키로 다른 내용을 보냄(422 idempotency_key_reused): '다시 시도해 주세요'. 새 요청 키로 다시 보냄. 그 밖의 실패: '문제가 생겼어요. 다시 시도해 주세요'와 다시 시도 버튼, 추적 ID | API-045#404:not_found, API-045#default:internal, API-047#404:not_found, API-047#422:validation_failed, API-047#422:idempotency_key_reused, API-047#default:internal |
| SCR-023#permission | 로그인이 없거나 만료됨(401 unauthenticated): 로그인 화면으로 이동하고, 로그인하면 이 화면으로 돌아옴('다시 로그인해 주세요') | API-045#401:unauthenticated, API-047#401:unauthenticated |
| SCR-023#stale | 그 사이 결제가 확인됨(already_decided): '이미 처리됐어요'와 지금 상태. 픽업 일시가 지남(invalid_state): '지금 상태에서는 할 수 없어요'와 '주문 취소'만. 픽업 일시까지 고르지 않아 서버가 결제 없어 취소한 주문: '이미 처리됐어요'. 본 뒤 바뀜(version_conflict): '그 사이 바뀌었어요. 지금 상태를 확인해 주세요'와 다시 읽은 지금 상태. 결제 기한 지난 주문이 아님(그 사이 결제가 확인됐거나 다른 상태): '이미 처리됐어요'와 주문 상세(SCR-021) 링크 | API-045#200:custom_requested, API-045#200:confirmed, API-045#200:changed, API-045#200:remake, API-045#200:custom_no_answer, API-047#409:version_conflict, API-047#409:already_decided, API-047#409:invalid_state |
| SCR-023#submitting | 누른 버튼이 '처리하고 있어요'로 바뀌고 이 화면의 다른 액션과 함께 막힘. 첫 요청을 아직 처리하는 중이면(409 request_in_progress) 1초 뒤 같은 요청 키로 다시 보내고, 결과는 한 번만 보임 | API-047#409:request_in_progress |
| SCR-023#confirm-notify | '주문 취소'를 누르면 서버로 보내기 전에 화면이 확인 창을 엶: '손님에게 주문 취소 안내가 가요. 취소한 주문은 되돌릴 수 없어요'. '주문 취소하기'를 눌러야 보내고 '돌아가기'면 아무것도 바뀌지 않음 | (화면이 여는 확인 창) |
| SCR-023#confirm | 저장하기 전에 사장님 확인이 필요함(409 confirmation_required, overbooking): 확인 창에 '그날 남은 자리가 없어요. 추가로 받을까요?'. '추가로 받기'를 누르면 confirm에 overbooking를 넣고 새 요청 키로 다시 보냄. '돌아가기'면 아무것도 바뀌지 않음. 추가로 받지 않으면 결제 기한을 연장하지 않고 이 화면으로 돌아옴(SPEC-038). 그날이 휴무일이면(closed_day) '휴무일이에요. 이날로 정할까요?', 그 픽업 날짜의 주문 마감이 지났으면(past_cutoff) '주문 마감이 지난 날이에요(새 결제 기한은 픽업 일시까지). 결제 기한을 연장할까요?'를 같은 창에 보이고, 확인한 것을 모두 confirm에 넣어 다시 보냄(REQ-218, REQ-221) | API-047#409:confirmation_required |
| SCR-023#done | 연장(waited)이나 취소(cancelled) 결과 문구 뒤 주문 상세(SCR-021)로 | API-047#200:waited, API-047#200:cancelled |
| empty (해당 없음) | 결제 기한 지난 주문만 이 화면에 옴. 빈 경우는 없음 |  |

## 케이스 유형

| 케이스 유형 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 그 가게 주문만(SCR-023#error, G1) |
| 입력 | 결정 값이 틀리면 SCR-023#error |
| 대상 | 없는 주문은 SCR-023#error |
| 상태 변화 | 픽업 일시가 지났으면 연장 대신 취소만(SCR-023#stale). 남은 자리가 없거나 휴무일이거나 주문 마감이 지났으면 SCR-023#confirm(REQ-218, REQ-221). 픽업 일시까지 고르지 않으면 결제 없어 취소(REQ-217) |
| 반복 | 연장을 두 번 눌러도 결제 안내는 하나(SPEC-038, SCR-023#submitting) |
| 동시 변경 | 사장님 확인과 기한 처리가 동시에 일어나면 확인이 이김. 이미 결제가 확인됐으면 SCR-023#stale |
| 데이터 노출 | 손님에게는 사장님이 고른 결과만 알림(SPEC-037) |
| 화면 상태 | 상태마다 360·1280 와이어프레임(`wireframes.html#SCR-023`) |
