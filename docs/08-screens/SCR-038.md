# SCR-038 운영규정

- 경로: `/owner/operating-rules`
- 접근 권한: 사장님
- 상위 화면: SCR-034 가게 설정
- 화면 레이아웃: 사장님 화면(1280 왼쪽 메뉴, 360 위쪽 막대와 메뉴 버튼)
- 플로우: FL-001, FL-002
- 관련 SPEC: SPEC-005
- API: API-020, API-021
- 와이어프레임: `wireframes.html#SCR-038`(상태 9개, 360·1280)
- 목업: [`SCR-038-360`](../../research/cake-mockup-2026-11/canvas/project/SCR-038-360.dc.html)(normal·empty·error·confirm), [`SCR-038-1280`](../../research/cake-mockup-2026-11/canvas/project/SCR-038-1280.dc.html)(normal). 캔버스의 '사장님 화면' 페이지([09단계 README](../09-mockup/README.md) 2절)

목적: 사장님이 운영규정 템플릿의 조문(제작 전 취소·단계별 환불·취소 수수료·날짜를 바꾼 주문의 환불 기준·가게 사정 취소 보상·문제 신고 기한·견적 유효 기한·결제 기한·변경 마감)을 채우고 확정하면 새 버전이 됩니다. (FL-001, FL-002)

## 액션

| 액션 | 결과 | 실패 |
| --- | --- | --- |
| 확정 | 새 버전: '확정했어요. 운영규정 버전 {n}'. 바꾼 것이 없으면 '바뀐 것이 없어 새 버전을 만들지 않았어요'. 이미 받은 주문은 받은 버전으로 계속 계산 | 제작 전 취소 환불을 전액보다 낮추면 SCR-038#confirm, 한도 밖·단계별 환불이 0시간부터 끝없음까지 이어지지 않음(겹침·빈 구간)·단계별 환불 조문과 행 가운데 하나만 있음·주문 요청 카드의 규정 글을 넘는 조문(422)은 SCR-038#error의 필드·행 옆, 다른 기기에서 먼저 확정함은 SCR-038#stale |
| 조문 추가(직접 쓰는 조문) | 조건·효과 필드가 생김 | 50개가 차면 버튼이 막힘 |
| 버전 이력 | 운영규정 버전 이력(SCR-039) | 그 화면의 상태 |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이 상태로 오는 응답 |
| --- | --- | --- |
| SCR-038#normal | 위에 '운영규정 버전 n · 확정 시각'과 '버전 이력'. 조문마다 카드(이름·조건·효과)와 숫자 필드(기한 시간·수수료·환불 비율), 단계별 환불 표와 그 아래 '맞춤 재료 주문·제작 시작 뒤 취소는 이 표로, 그 전은 제작 전 취소 비율로 계산해요. 취소 수수료를 먼저 빼고 비율을 곱해요(원 미만 버림)'. 단계별 환불 행이 없으면 표 자리에 '단계별 환불이 없으면 제작을 시작한 뒤의 취소도 제작 전 취소 비율로 계산돼요'(막지 않음, SPEC-005). 맨 아래 '확정' | API-020#200:current |
| SCR-038#loading | 레이아웃은 그대로 두고 데이터 자리에 회색 막대를 보임. 액션 버튼은 누를 수 없음. 조문 카드 자리는 회색 막대 세 줄씩 | (데이터를 불러오는 동안) |
| SCR-038#empty | 아직 확정한 운영규정이 없음(template): 기본값이 채워진 템플릿과 위에 '아직 확정 전이에요. 기본값을 확인하고 확정해 주세요'. 제작 전 취소 조문의 기본값은 '취소 수수료만 빼고 전액 환불' | API-020#200:template |
| SCR-038#error | 입력이 한도나 형식에 맞지 않음(422 validation_failed): 필드 옆에 '입력한 내용을 확인해 주세요'와 필드마다의 사유. 넣은 값은 그대로 둠(기한 1~720시간, 수수료 0원~1,000만 원, 환불 비율 0~100%). 단계별 환불의 기간이 중복되거나 빈 구간이 있음(422 overlaps·gap, 0시간부터 끝없음까지 이어져야 함): 그 행을 굵게. 단계별 환불 조문과 행 가운데 하나만 있음(422 required): 단계별 환불 표 위에 '단계별 환불 조문과 표를 함께 채워 주세요'. 취소·환불 조문이 주문 요청 카드의 규정 글 둘(1,000자씩)에 들어가지 않음(422 exceeds_card_limit): 조문 목록 위에 '주문 요청 카드에 다 들어가지 않아요. 조문을 줄여 주세요'와 넘친 조문을 굵게(REQ-184). 같은 요청 키로 다른 내용을 보냄(422 idempotency_key_reused): '다시 시도해 주세요'. 새 요청 키로 다시 보냄. 그 밖의 실패: '문제가 생겼어요. 다시 시도해 주세요'와 다시 시도 버튼, 추적 ID | API-020#default:internal, API-021#422:validation_failed, API-021#422:idempotency_key_reused, API-021#default:internal |
| SCR-038#permission | 로그인이 없거나 만료됨(401 unauthenticated): 로그인 화면으로 이동하고, 로그인하면 이 화면으로 돌아옴('다시 로그인해 주세요'). 로그인한 사장님에게 가게가 아직 없음(404 shop_not_registered): 가게가 없으면 가게 등록(SCR-015)으로 보냄('가게를 먼저 등록해 주세요') | API-020#401:unauthenticated, API-020#404:shop_not_registered, API-021#401:unauthenticated, API-021#404:shop_not_registered |
| SCR-038#stale | 다른 기기에서 먼저 저장함(409 version_conflict): '그 사이 바뀌었어요. 지금 상태를 확인해 주세요'와 다시 읽은 지금 상태. 고치던 값은 버리지 않고 '내 변경 다시 적용'으로 지금 버전 위에 다시 얹을 수 있음(G3) | API-021#409:version_conflict |
| SCR-038#submitting | 누른 버튼이 '처리하고 있어요'로 바뀌고 이 화면의 다른 액션과 함께 막힘. 첫 요청을 아직 처리하는 중이면(409 request_in_progress) 1초 뒤 같은 요청 키로 다시 보내고, 결과는 한 번만 보임 | API-021#409:request_in_progress |
| SCR-038#confirm | 저장하기 전에 사장님 확인이 필요함(409 confirmation_required, lowered_refund): 확인 창에 '제작 전 취소 환불을 전액보다 낮추면 분쟁 때 가게에 불리할 수 있어요(약관법 제8조, 한국소비자원 조정 사례). 그래도 저장할까요?'. '그래도 저장'를 누르면 confirm에 lowered_refund를 넣고 새 요청 키로 다시 보냄. '취소'면 아무것도 바뀌지 않음. 그 선택을 그 버전에 남김(REQ-032) | API-021#409:confirmation_required |
| SCR-038#done | 확정(created): '확정했어요. 운영규정 버전 {n}'. 바뀐 것 없음(unchanged): '바뀐 것이 없어 새 버전을 만들지 않았어요' | API-021#201:created, API-021#200:unchanged |

## 케이스 유형

| 케이스 유형 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 로그인한 사장님의 가게만. 401은 SCR-038#permission |
| 입력 | 기한 1~720시간, 수수료 0원~1,000만 원(주문 금액과는 환불을 계산할 때 견주고 바탕보다 크면 환불 0원, SPEC-016), 비율 0~100%, 단계별 환불은 0시간부터 끝없음까지 중복·빈 구간 없이 조문과 함께. 틀리면 SCR-038#error |
| 대상 | 가게가 없으면 SCR-038#permission. 이전 버전은 SCR-039에서 읽기만 |
| 상태 변화 | 제작 전 취소 환불을 낮추면 SCR-038#confirm. 바꾼 것이 없으면 새 버전 없음. 단계별 환불이 없으면 저장 전에 알리고 막지 않음(SPEC-005) |
| 한도 | 취소·환불 조문은 주문 요청 카드의 규정 글 둘(1,000자씩, 끝의 청약철회 문장과 미성년자 취소 고지까지)에 들어가야 저장됨. 넘치면 SCR-038#error(REQ-184, REQ-240, DEC-22) |
| 반복 | 확정을 두 번 눌러도 버전은 하나 오름(G2) |
| 동시 변경 | 다른 기기에서 먼저 확정했으면 SCR-038#stale(G3) |
| 데이터 노출 | 사장님 화면에만. 손님에게는 주문 요청 카드에 그 버전의 취소·환불 규정이 나감(SCR-004) |
| 빈 응답·끊긴 응답 | 확정 전이면 템플릿(SCR-038#empty) |
| 화면 상태 | 상태마다 360·1280 와이어프레임(`wireframes.html#SCR-038`) |
