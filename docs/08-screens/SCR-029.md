# SCR-029 입금 대조

- 경로: `/owner/payment-requests/:paymentRequestId`
- 접근 권한: 사장님
- 상위 화면: SCR-028 입금 대조 목록
- 화면 레이아웃: 사장님 화면(1280 왼쪽 메뉴, 360 위쪽 막대와 메뉴 버튼)
- 플로우: FL-007
- 관련 SPEC: SPEC-034, SPEC-035, SPEC-036
- API: API-058, API-059
- 와이어프레임: `wireframes.html#SCR-029`(상태 9개, 360·1280)
- 목업: [`SCR-029-360`](../../research/cake-mockup-2026-11/canvas/project/SCR-029-360.dc.html)(normal·error·expired), [`SCR-029-1280`](../../research/cake-mockup-2026-11/canvas/project/SCR-029-1280.dc.html)(normal). 캔버스의 '사장님 화면' 페이지([09단계 README](../09-mockup/README.md) 2절)

목적: 사장님이 결제 안내의 금액·입금자 이름·결제 기한을 은행 앱과 맞춰 보고 입금됨·미입금·금액 불일치를 고르고, 맞추는 중인 안내는 대조 완료로 닫습니다. (FL-007)

## 데이터

| 데이터 | 출처 |
| --- | --- |
| 주문번호·종류·상태·안내 금액·요청 금액·입금자 이름·결제 기한·확인 요청 시각·확인 요청을 지운 시각 | API-058 |
| 들어온 금액(금액 불일치) | API-058 mismatchAmount |
| 입금됨 시각·닫힌 사유(새 안내로 바뀜·주문 취소·변경 닫힘) | API-058 paidAt·closeReason |

## 액션

| 액션 | 결과 | 실패 |
| --- | --- | --- |
| 입금됨 | '입금됨을 남겼어요. 주문이 확정됐어요'(차액 결제면 '차액을 확인해 변경을 반영했어요'). 결제 안내 하나에 확인된 결제는 하나 | 기한이 지나 자리가 풀린 안내(409 slot_released)·이미 처리함(already_decided)·본 뒤 바뀜은 SCR-029#stale, 취소된 주문에 들어온 입금(paid_after_cancel)은 SCR-029#done에서 환불 결정 링크 |
| 미입금 | 확인 요청을 지움. 기한이 지났으면 결제 기한 지난 주문(SCR-023)으로 넘어감 | 이미 처리함은 SCR-029#stale |
| 금액 불일치 | 들어온 금액(1원~안내 금액의 10배)을 넣고 남김: '금액 불일치를 남겼어요. 결제 기한을 멈추고 자리를 지켜요'. 손님에게 '보내신 금액이 안내와 달라 사장님이 연락드릴게요' | 금액이 한도 밖(422)은 SCR-029#error의 필드 옆 |
| 대조 완료 | 맞추는 중인 안내에서 '모자란 금액이 마저 들어옴'·'더 들어온 금액을 반환함' 가운데 하나를 고르고 확인: '입금됨을 남겼어요. 주문이 확정됐어요' | 이미 처리함은 SCR-029#stale |
| 가게 사정 취소 | 맞추는 중인 주문을 이어가지 않을 때 주문 상세(SCR-021)의 가게 사정 취소로 | 그 화면의 상태 |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이 상태로 오는 응답 |
| --- | --- | --- |
| SCR-029#normal | 안내 금액(크게)·입금자 이름·결제 기한·확인 요청 시각, '은행 앱에서 이 금액이 들어왔는지 확인해 주세요', 버튼 '입금됨'·'미입금'·'금액 불일치'. 확인 요청 전 열린 안내도 같은 모습 | API-058#200:claimed |
| SCR-029#loading | 레이아웃은 그대로 두고 데이터 자리에 회색 막대를 보임. 액션 버튼은 누를 수 없음 | (데이터를 불러오는 동안) |
| SCR-029#error | 없거나 다른 가게의 결제 안내(404 not_found): '찾을 수 없어요'와 '입금 대조 목록으로' 링크(SCR-028). 다른 가게 기록이 있는지는 말하지 않음(G1). 입력이 한도나 형식에 맞지 않음(422 validation_failed): 필드 옆에 '입력한 내용을 확인해 주세요'와 필드마다의 사유. 넣은 값은 그대로 둠. 같은 요청 키로 다른 내용을 보냄(422 idempotency_key_reused): '다시 시도해 주세요'. 새 요청 키로 다시 보냄. 그 밖의 실패: '문제가 생겼어요. 다시 시도해 주세요'와 다시 시도 버튼, 추적 ID | API-058#404:not_found, API-058#default:internal, API-059#404:not_found, API-059#422:validation_failed, API-059#422:idempotency_key_reused, API-059#default:internal |
| SCR-029#permission | 로그인이 없거나 만료됨(401 unauthenticated): 로그인 화면으로 이동하고, 로그인하면 이 화면으로 돌아옴('다시 로그인해 주세요') | API-058#401:unauthenticated, API-059#401:unauthenticated |
| SCR-029#stale | 자리가 풀린 안내에 입금됨을 누름(409 slot_released): 06단계 slot_released 문구와 결제 기한 지난 주문(SCR-023) 링크. 이미 처리함(already_decided): '이미 처리됐어요'. 지금 상태에서 할 수 없음(invalid_state): '지금 상태에서는 할 수 없어요'. 본 뒤 바뀜(version_conflict): '그 사이 바뀌었어요. 지금 상태를 확인해 주세요'와 다시 읽은 지금 상태 | API-059#409:version_conflict, API-059#409:slot_released, API-059#409:already_decided, API-059#409:invalid_state |
| SCR-029#submitting | 누른 버튼이 '처리하고 있어요'로 바뀌고 이 화면의 다른 액션과 함께 막힘. 첫 요청을 아직 처리하는 중이면(409 request_in_progress) 1초 뒤 같은 요청 키로 다시 보내고, 결과는 한 번만 보임 | API-059#409:request_in_progress |
| SCR-029#mismatch | 맞추는 중(mismatch): '맞추는 중'과 들어온 금액·안내 금액·차이, 결제 기한이 멈췄다는 표시. '대조 완료'(모자란 금액이 마저 들어옴·더 들어온 금액을 반환함)와 '가게 사정 취소'(주문 상세로) | API-058#200:mismatch, API-059#200:mismatch |
| SCR-029#expired | 결제 기한이 지나 자리가 풀린 안내(expired): '결제 기한이 지나 자리가 풀린 안내예요'와 결제 기한 지난 주문(SCR-023) 링크. '입금됨'을 막고 먼저 결제 기한 연장으로 자리를 다시 잡게 함(R14) | API-058#200:expired |
| SCR-029#done | 남긴 결과 문구와 읽기 전용 안내(입금됨 시각). 취소된 주문에 들어온 입금(paid_after_cancel): '취소된 주문에 들어온 입금이에요. 환불을 정해 주세요'와 환불 결정(SCR-025) 링크. 이미 입금됨(unchanged): '이미 입금됨으로 남긴 안내예요' | API-059#200:confirmed, API-059#200:difference_applied, API-059#200:paid_after_cancel, API-059#200:unchanged |
| empty (해당 없음) | 결제 안내는 금액과 가게 계좌가 있을 때만 생김. 빈 안내는 없음 |  |

## 케이스 유형

| 케이스 유형 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 그 가게 안내만(SCR-029#error, G1) |
| 입력 | 들어온 금액은 1원~안내 금액의 10배. 틀리면 SCR-029#error |
| 대상 | 없는 안내는 SCR-029#error |
| 상태 변화 | 맞추는 중은 SCR-029#mismatch, 자리가 풀린 안내는 SCR-029#expired, 취소된 주문에 들어온 입금은 SCR-029#done의 환불 결정 링크 |
| 반복 | 입금됨을 두 번 눌러도 확인된 결제는 하나(REQ-132, SCR-029#done의 unchanged) |
| 동시 변경 | 사장님 확인과 결제 기한 처리가 동시에 일어나면 확인이 이김(SPEC-034). 그 밖에 본 뒤 바뀌면 SCR-029#stale |
| 데이터 노출 | 손님에게 금액 불일치 안내에는 들어온 금액을 적지 않음(SPEC-035) |
| 화면 상태 | 상태마다 360·1280 와이어프레임(`wireframes.html#SCR-029`) |
