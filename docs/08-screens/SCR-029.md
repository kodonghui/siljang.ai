# SCR-029 입금 대조

- 경로: `/owner/payment-requests/:paymentRequestId`
- 접근 권한: 사장님
- 상위 화면: SCR-028 입금 대조 목록
- 화면 레이아웃: 사장님 화면(1280 왼쪽 메뉴, 360 위쪽 막대와 메뉴 버튼)
- 플로우: FL-007, FL-008, FL-009
- 관련 SPEC: SPEC-034, SPEC-035, SPEC-036, SPEC-070, SPEC-071
- API: API-058, API-059
- 와이어프레임: `wireframes.html#SCR-029`(상태 10개, 360·1280)
- 목업: [`SCR-029-360`](../../research/cake-mockup-2026-11/canvas/project/SCR-029-360.dc.html)(normal·error·confirm-notify·expired), [`SCR-029-1280`](../../research/cake-mockup-2026-11/canvas/project/SCR-029-1280.dc.html)(normal). 캔버스의 '사장님 화면' 페이지([09단계 README](../09-mockup/README.md) 2절)

목적: 사장님이 결제 안내의 금액·입금자 이름·결제 기한을 은행 앱과 맞춰 보고 입금됨·미입금·금액 불일치를 고르고, 맞추는 중인 안내는 대조 완료로 닫습니다. 맞추는 중인 차액 결제는 변경을 반영하지 않고 변경 닫기로 끝낼 수도 있습니다. 닫힌·기한 지난 안내에 들어온 입금은 들어옴(금액)으로 남기고, 잘못 누른 결제 확인은 제작 전에 취소합니다. (FL-007, FL-008, FL-009)

## 액션

| 액션 | 결과 | 실패 |
| --- | --- | --- |
| 입금됨 | '입금됨을 남겼어요. 주문이 확정됐어요'(차액 결제면 '차액을 확인해 변경을 반영했어요'). 결제 안내 하나에 확인된 결제는 하나. 손님이 새 금액을 아직 확인하지 않은 안내면 그 시각을 손님의 확인으로 함께 남김(SPEC-076) | 기한이 지나 자리가 풀린 안내(409 slot_released)·이미 처리함(already_decided)·본 뒤 바뀜은 SCR-029#stale, 취소된 주문에 들어온 입금(paid_after_cancel)은 SCR-029#done에서 환불 결정 링크 |
| 미입금 | 확인 요청을 지움. 기한이 지났으면 결제 기한 지난 주문(SCR-023)으로 넘어감 | 이미 처리함은 SCR-029#stale |
| 금액 불일치 | 들어온 금액(1원~안내 금액의 10배)을 넣고 남김: '금액 불일치를 남겼어요. 결제 기한을 멈추고 자리를 지켜요'. 손님에게 '보내신 금액이 안내와 달라 사장님이 연락드릴게요' | 금액이 한도 밖(422)은 SCR-029#error의 필드 옆 |
| 대조 완료 | 맞추는 중인 안내에서 '모자란 금액이 마저 들어옴'·'더 들어온 금액을 반환함' 가운데 하나를 고르고 확인: '입금됨을 남겼어요. 주문이 확정됐어요'(차액 결제면 '차액을 확인해 변경을 반영했어요'). 손님이 새 금액을 아직 확인하지 않은 안내면 그 시각을 손님의 확인으로 함께 남김 | 이미 처리함은 SCR-029#stale |
| 변경 닫기 | 맞추는 중인 차액 결제에서만: 변경 요청을 '차액 없어 닫힘'으로 두고 주문 내용·버전은 그대로, 차액을 기다리며 잡아 둔 새 날 자리를 풂. 들어온 금액은 '더 들어온 금액'으로 돌려줄 환불을 정할 일로 남김: '변경을 닫았어요. 들어온 금액은 환불을 정해 주세요'와 환불 결정(SCR-025) 링크(SPEC-035, REQ-235) | 맞추는 중인 차액 결제가 아님(409 invalid_state)·이미 처리함·본 뒤 바뀜은 SCR-029#stale |
| 가게 사정 취소 | 맞추는 중인 주문을 이어가지 않을 때 주문 상세(SCR-021)의 가게 사정 취소로 | 그 화면의 상태 |
| 들어옴(금액) | 닫힘·기한 지남 안내(취소된 주문, 새 안내로 바뀜, 기한 뒤 차액)에 들어온 금액(1원~안내 금액의 10배)을 넣고 남김: '들어온 입금을 남겼어요. 환불을 정해 주세요'와 환불 결정(SCR-025) 링크(SPEC-071). 들어온 입금 대조 할 일에서 들어오지 않았으면 '미입금'으로 할 일을 닫음(REQ-167) | 금액이 한도 밖(422)은 SCR-029#error의 필드 옆, 이미 남김(already_decided)·본 뒤 바뀜은 SCR-029#stale |
| 결제 확인 취소 | 확인됨이고 제작을 시작하지 않은 안내에서 사유(1~200자)를 넣고 확인: '결제 확인을 취소했어요. 주문을 결제 기다림으로 되돌리고 손님에게 정정 안내를 보냈어요'(SPEC-070, REQ-169) | 사유 없음(422)은 SCR-029#error의 필드 옆, 제작을 시작함(invalid_state)·본 뒤 바뀜은 SCR-029#stale |

## 케이스 유형

| 케이스 유형 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 그 가게 안내만(SCR-029#error, G1) |
| 입력 | 들어온 금액은 1원~안내 금액의 10배, 결제 확인 취소 사유는 1~200자. 틀리면 SCR-029#error |
| 대상 | 없는 안내는 SCR-029#error |
| 상태 변화 | 맞추는 중은 SCR-029#mismatch, 자리가 풀린 안내는 SCR-029#expired, 취소된 주문에 들어온 입금은 SCR-029#done의 환불 결정 링크. 제작을 시작한 주문의 결제 확인 취소는 SCR-029#stale(SPEC-070). 맞추는 중인 차액 결제의 변경 닫기는 SCR-029#done, 맞추는 중이 아닌 안내의 변경 닫기는 SCR-029#stale(REQ-235). 새 금액 확인 전의 안내를 결제로 확인하면 손님의 확인으로 남김(SPEC-076) |
| 반복 | 입금됨을 두 번 눌러도 확인된 결제는 하나(REQ-132, SCR-029#done의 unchanged) |
| 동시 변경 | 사장님 확인과 결제 기한 처리가 동시에 일어나면 확인이 이김(SPEC-034). 그 밖에 본 뒤 바뀌면 SCR-029#stale |
| 데이터 노출 | 손님에게 금액 불일치 안내에는 들어온 금액을 적지 않음(SPEC-035) |
| 화면 상태 | 상태마다 360·1280 와이어프레임(`wireframes.html#SCR-029`) |
