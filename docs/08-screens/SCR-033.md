# SCR-033 영업 캘린더 설정

- 경로: `/owner/calendar/settings`
- 접근 권한: 사장님
- 상위 화면: SCR-032 영업 캘린더
- 화면 레이아웃: 사장님 화면(1280 왼쪽 메뉴, 360 위쪽 막대와 메뉴 버튼)
- 플로우: FL-001, FL-002
- 관련 SPEC: SPEC-007
- API: API-026, API-027
- 와이어프레임: `wireframes.html#SCR-033`(상태 10개, 360·1280)
- 목업: [`SCR-033-360`](../../research/cake-mockup-2026-11/canvas/project/SCR-033-360.dc.html)(normal·empty·error·confirm), [`SCR-033-1280`](../../research/cake-mockup-2026-11/canvas/project/SCR-033-1280.dc.html)(normal). 캔버스의 '사장님 화면' 페이지([09단계 README](../09-mockup/README.md) 2절)

목적: 사장님이 쉬는 요일·하루 최대 개수·주문 마감·답하는 시간·전날 안내 시각·후기 부탁 시각을 정합니다. 바꾼 기준을 넘는 날이 있으면 그 날과 주문을 보여 줍니다. (FL-001, FL-002)

## 데이터

| 데이터 | 출처 |
| --- | --- |
| 쉬는 요일·하루 최대 개수(0~100)·주문 마감(픽업일 0~30일 전과 시각) | API-026 closedWeekdays·dailyCapacity·orderCutoffDays·orderCutoffTime |
| 답하는 시간(기본 09:00~21:00)·전날 안내 시각(08:00~20:50, 기본 18:00)·후기 부탁 시각(08:00~20:50, 기본 11:00, REQ-243) | API-026 replyStart·replyEnd·dayBeforeNoticeTime·reviewRequestTime |
| 저장 결과와 새 기준을 넘는 날·주문 | API-027 outcome·conflicts |

## 액션

| 액션 | 결과 | 실패 |
| --- | --- | --- |
| 저장 | '저장했어요'. 새 기준을 넘는 날이 있으면 '저장했어요. 새 기준을 넘는 날이 있어요'와 그 날·주문(주문은 그대로, SCR-033#done). 바꾼 기준은 그 뒤 잡는 자리에만 씀 | 한도 밖(422)은 SCR-033#error의 필드 옆, 확정 주문이 있는 요일을 휴무로 바꾸면 SCR-033#confirm, 본 뒤 바뀜은 SCR-033#stale |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이 상태로 오는 응답 |
| --- | --- | --- |
| SCR-033#normal | 필드: 쉬는 요일(요일 7개 토글)·하루 최대 개수·주문 마감(픽업일 n일 전 HH:MM)·답하는 시간(시작~끝)·전날 안내 시각·후기 부탁 시각, '저장'. 필드마다 한 줄 설명(예: '바꾼 기준은 그 뒤 잡는 자리에만 써요', 전날 안내 시각과 후기 부탁 시각은 '아직 보내지 않은 안내부터 써요'(REQ-243)) | API-026#200:settings |
| SCR-033#loading | 레이아웃은 그대로 두고 데이터 자리에 회색 막대를 보임. 액션 버튼은 누를 수 없음 | (데이터를 불러오는 동안) |
| SCR-033#empty | 처음 정함(404 not_set): 기본값(답하는 시간 09:00~21:00, 전날 안내 18:00, 후기 부탁 11:00)을 채운 입력 화면과 위에 '처음 정해요. 기본값을 확인하고 저장해 주세요' | API-026#404:not_set |
| SCR-033#error | 입력이 한도나 형식에 맞지 않음(422 validation_failed): 필드 옆에 '입력한 내용을 확인해 주세요'와 필드마다의 사유. 넣은 값은 그대로 둠(답하는 시간은 시작이 끝보다 앞서야 함, 안내 시각은 08:00~20:50). 같은 요청 키로 다른 내용을 보냄(422 idempotency_key_reused): '다시 시도해 주세요'. 새 요청 키로 다시 보냄. 그 밖의 저장 실패: 넣은 값은 그대로 두고 폼 위에 '문제가 생겼어요. 다시 시도해 주세요'와 다시 시도 버튼, 추적 ID | API-027#422:validation_failed, API-027#422:idempotency_key_reused, API-027#default:internal |
| SCR-033#load-failed | 불러오기 실패: 폼을 보일 수 없어 '문제가 생겼어요. 다시 시도해 주세요'와 다시 시도 버튼, 추적 ID. 입력 오류와 저장 실패는 error(폼과 넣은 값은 그대로) | API-026#default:internal |
| SCR-033#permission | 로그인이 없거나 만료됨(401 unauthenticated): 로그인 화면으로 이동하고, 로그인하면 이 화면으로 돌아옴('다시 로그인해 주세요'). 로그인한 사장님에게 가게가 아직 없음(404 shop_not_registered): 가게가 없으면 가게 등록(SCR-015)으로 보냄('가게를 먼저 등록해 주세요') | API-026#401:unauthenticated, API-026#404:shop_not_registered, API-027#401:unauthenticated, API-027#404:shop_not_registered |
| SCR-033#stale | 다른 기기에서 먼저 저장함(409 version_conflict): '그 사이 바뀌었어요. 지금 상태를 확인해 주세요'와 다시 읽은 지금 상태 | API-027#409:version_conflict |
| SCR-033#submitting | 누른 버튼이 '처리하고 있어요'로 바뀌고 이 화면의 다른 액션과 함께 막힘. 첫 요청을 아직 처리하는 중이면(409 request_in_progress) 1초 뒤 같은 요청 키로 다시 보내고, 결과는 한 번만 보임 | API-027#409:request_in_progress |
| SCR-033#confirm | 저장하기 전에 사장님 확인이 필요함(409 confirmation_required, closed_day_with_orders): 확인 창에 '이날 확정 주문 {count}건은 그대로 남아요. 휴무로 바꿀까요?'. '휴무로 바꾸기'를 누르면 confirm에 closed_day_with_orders를 넣고 새 요청 키로 다시 보냄. '돌아가기'면 아무것도 바뀌지 않음. 주문과 자리는 픽업 일시까지 그대로 남음(REQ-041) | API-027#409:confirmation_required |
| SCR-033#done | 저장(created): '저장했어요'. 새 기준을 넘는 날(updated_with_conflicts): '저장했어요. 새 기준을 넘는 날이 있어요'와 날짜·잡힌 자리·하루 최대·주문 목록, 주문은 그대로(R4). 바뀐 것 없음(unchanged): '바뀐 것이 없어요' | API-027#200:created, API-027#200:updated_with_conflicts, API-027#200:unchanged |

## 케이스 유형

| 케이스 유형 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 로그인한 사장님의 가게만. 401은 SCR-033#permission |
| 입력 | 하루 최대 0~100, 주문 마감 0~30일, 답하는 시간 시작<끝, 전날 안내 시각과 후기 부탁 시각 08:00~20:50(SPEC-052, REQ-243). 틀리면 SCR-033#error |
| 대상 | 처음 정할 때는 SCR-033#empty |
| 상태 변화 | 확정 주문이 있는 요일을 휴무로 바꾸면 SCR-033#confirm, 새 기준을 넘는 날은 SCR-033#done에 목록. 바꾼 전날 안내 시각과 후기 부탁 시각은 아직 보내지 않은 안내부터 쓰고 이미 보낸 것은 다시 보내지 않음(SPEC-007, REQ-243) |
| 반복 | 저장을 두 번 눌러도 한 번(SCR-033#submitting) |
| 동시 변경 | 가예약과는 날짜 행 잠금 순서(G3). 본 뒤 바뀌면 SCR-033#stale |
| 데이터 노출 | 사장님 화면에만 |
| 화면 상태 | 상태마다 360·1280 와이어프레임(`wireframes.html#SCR-033`) |
