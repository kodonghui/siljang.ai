# SCR-027 문제 신고

- 경로: `/owner/issue-reports/:issueReportId`
- 접근 권한: 사장님
- 상위 화면: SCR-021 주문 상세
- 화면 레이아웃: 사장님 화면(1280 왼쪽 메뉴, 360 위쪽 막대와 메뉴 버튼)
- 플로우: FL-011
- 관련 SPEC: SPEC-058, SPEC-059, SPEC-060, SPEC-079
- API: API-064, API-065
- 와이어프레임: `wireframes.html#SCR-027`(상태 8개, 360·1280)
- 목업: [`SCR-027-360`](../../research/cake-mockup-2026-11/canvas/project/SCR-027-360.dc.html)(normal·error·confirm), [`SCR-027-1280`](../../research/cake-mockup-2026-11/canvas/project/SCR-027-1280.dc.html)(normal). 캔버스의 '사장님 화면' 페이지([09단계 README](../09-mockup/README.md) 2절)

목적: 사장님이 신고 사진·설명과 주문 내용 버전·결제 금액을 보고 문제 종류(상함·변질·이물·그 밖)를 고르고 재제작·일부 환불·전액 환불·그 밖의 보상·보상 없음 가운데 하나로 보상을 정합니다. 재제작 주문에 들어온 신고(다시 신고)는 원래 주문의 받은 금액으로 한도를 보고 환불을 원래 주문에 남깁니다. (FL-011)

## 액션

| 액션 | 결과 | 실패 |
| --- | --- | --- |
| 재제작 | 손님과 정한 새 픽업 일시(지금 뒤 60일 안)를 넣고 정함: '재제작 주문을 만들었어요'와 그 주문 링크. 결제 없는 재제작 주문이 확정된 상태로 제작 목록에 오름(R13). 재제작 주문에 들어온 신고의 다시 재제작도 원래 주문에 이음(SPEC-059) | 휴무일이거나 그날 남은 자리가 없으면 SCR-027#confirm(확인하면 마감 후 추가 수락으로 잡음, REQ-221, REQ-226), 60일 밖·지난 시각(422)은 SCR-027#error의 필드 옆, 이미 정함(already_decided)·본 뒤 바뀜은 SCR-027#stale |
| 일부 환불 | 금액(1원 이상, 받은 금액 - 이미 정한 환불 이하)을 넣고 정함. 보상은 고른 금액이 계산값이라 사유를 받지 않음(SPEC-059). '일부 환불을 정했어요' 뒤 환불 송금(SCR-026). 재제작 주문에 들어온 신고면 원래 주문의 돈으로 한도를 보고 환불은 원래 주문에 남음 | 한도 밖(422)은 SCR-027#error의 필드 옆 |
| 전액 환불 | 받은 금액에서 이미 정한 환불을 뺀 금액 전액으로 정한 뒤 환불 송금(SCR-026) | 이미 정함은 SCR-027#stale |
| 그 밖의 보상 | 사장님이 직접 처리한 보상(예: 다른 상품, 진료비)의 한 일(1~200자)과 금액(선택, 0원~1억 원)을 남기고 닫음: '그 밖의 보상을 남겼어요'. 환불·장부 쓰기는 만들지 않고 손님에게 '사장님이 직접 연락해 보상을 처리해 드려요'(REQ-249) | 한 일이 없거나 200자 넘음(422)은 SCR-027#error의 필드 옆, 이미 정함은 SCR-027#stale |
| 보상 없음 | 보상 없이 신고를 닫고 손님에게 안내. 문제 종류가 상함·변질이나 이물이면 저장 전에 SCR-027#confirm에서 소비자분쟁해결기준과 위험을 보고 사유(1~200자)를 넣어야 닫힘(REQ-248) | 사유가 없거나 200자 넘음(422)은 SCR-027#error의 필드 옆, 이미 정함은 SCR-027#stale |

| --- | --- | --- |

| SCR-027#stale | 이미 정한 보상(already_decided): '이미 처리됐어요'와 정한 보상. 본 뒤 바뀜(version_conflict, 같은 주문에 이어진 신고가 옴 등): '그 사이 바뀌었어요. 지금 상태를 확인해 주세요'와 다시 읽은 지금 상태 | API-065#409:version_conflict, API-065#409:already_decided |

| SCR-027#confirm | 저장하기 전에 사장님 확인이 필요함(409 confirmation_required, closed_day): 확인 창에 '휴무일이에요. 이날로 정할까요?'. '이날로 정하기'를 누르면 confirm에 closed_day를 넣고 새 요청 키로 다시 보냄. '취소'면 아무것도 바뀌지 않음. 그날 남은 자리가 없으면(overbooking) 같은 창에 '그날 남은 자리가 없어요. 추가로 받을까요?'를 보임. 확인하면 재제작 주문의 자리를 마감 후 추가 수락으로 잡음(REQ-221, REQ-226). 상함·변질이나 이물에 보상 없음(no_compensation_standard)이면 같은 창에 '상함·변질이나 이물은 소비자분쟁해결기준(공정위 고시 제2025-14호 별표, 제빵류)이 교환이나 환급을 정해요. 보상 없이 닫으면 분쟁 때 가게에 불리할 수 있어요. 사유를 남기고 그래도 보상 없이 닫을까요?'와 사유 필드(1~200자, 사장님 화면에만)를 보이고 '그래도 보상 없이 닫기'를 누르면 confirm과 사유를 함께 보냄(REQ-248) | API-065#409:confirmation_required |
| SCR-027#done | 정한 보상과 재제작 주문 링크(remake_decided)나 환불 송금 링크를 읽기 전용으로. 그 밖의 보상은 한 일·금액, 상함·변질·이물의 보상 없음은 사유를 함께. 이미 정한 보상은 고치지 않음(SPEC-059) | API-064#200:remake_decided, API-064#200:other_compensation, API-065#200:remake, API-065#200:partial_refund, API-065#200:none_with_reason, API-065#200:other_compensation |
| empty (해당 없음) | 문제 신고는 설명이 있을 때만 생김. 사진이 없으면 사진 자리에 '사진 없음'(normal 안에서) |  |

## 케이스 유형

| 케이스 유형 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 그 가게 신고만(SCR-027#error, G1). AI·손님은 보상을 정할 수 없음(AI 도구에 없음) |
| 입력 | 문제 종류는 꼭 고름. 새 픽업 일시는 지금 뒤 60일 안, 일부 환불은 1원 이상이고 SPEC-047과 같은 한도(재제작 주문에 들어온 신고면 원래 주문의 것), 환불에는 다르게 정한 사유를 받지 않음. 보상 없음의 사유와 그 밖의 보상의 한 일은 1~200자, 금액은 0원~1억 원. 틀리면 SCR-027#error |
| 대상 | 없는 신고는 SCR-027#error. 재제작 주문에 들어온 신고는 원래 주문의 돈으로 정함(SPEC-059, SPEC-060) |
| 상태 변화 | 이미 정한 보상은 SCR-027#done·SCR-027#stale. 휴무일·다 찬 날의 재제작과 상함·변질·이물의 보상 없음은 SCR-027#confirm |
| 반복 | 보상 하나에 재제작 주문 하나(같은 요청 키, SCR-027#submitting) |
| 동시 변경 | 같은 주문의 두 번째 신고는 첫 신고에 이어짐. 본 뒤 바뀌면 SCR-027#stale |
| 데이터 노출 | 신고 사진은 그 가게 사장님 화면에만. 보상 없음의 사유·그 밖의 보상의 한 일과 '기한 뒤'는 사장님 화면에만 보이고 손님 안내에 쓰지 않음(REQ-250). 에스컬레이션 건에서 남긴 신고는 보상 안내를 보내지 않음(DEC-24) |
| 화면 상태 | 상태마다 360·1280 와이어프레임(`wireframes.html#SCR-027`) |
