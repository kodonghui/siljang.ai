# SCR-006 결제 확인 요청 카드

- 경로: `kakao:shop/card/payment_claim`
- 접근 권한: 주문한 손님
- 상위 화면: SCR-003 가게 채널 상담
- 화면 레이아웃: 카카오톡 채널 대화 화면(1280은 PC 카카오톡 창)
- 플로우: FL-007
- 관련 SPEC: SPEC-033, SPEC-069
- API: API-071
- 와이어프레임: `wireframes.html#SCR-006`(상태 7개, 360·1280)
- 목업: [`SCR-006-360`](../../research/cake-mockup-2026-11/canvas/project/SCR-006-360.dc.html)(normal·expired·error), [`SCR-006-1280`](../../research/cake-mockup-2026-11/canvas/project/SCR-006-1280.dc.html)(normal). 캔버스의 '손님 화면' 페이지([09단계 README](../09-mockup/README.md) 2절)

목적: 결제한 손님이 AI 상담이 보인 카드를 눌러 사장님께 결제 확인을 요청합니다. (FL-007)

## 데이터

| 데이터 | 출처 |
| --- | --- |
| 결제 안내 요약: 주문번호·금액·결제 기한 | API-071 카드(처음 카드는 SCR-003의 API-070 card_shown) |
| 입금자 이름: 따로 넣지 않으면 주문자 이름. '입금자 이름 블록'으로 넣은 값은 AI로 보내지 않음(REQ-176, REQ-178) | API-071 카드, input_invalid |
| 누른 결과 | API-071 payment_claimed |

## 액션

| 액션 | 결과 | 실패 |
| --- | --- | --- |
| 결제 확인 요청 | 주문자 이름을 입금자 이름으로 하여 결제 안내를 '확인 요청됨'으로 두고 사장님께 결제 확인을 요청함. 결제 기한 전이면 기한이 지나도 사장님이 정할 때까지 자리를 지킴(SPEC-033, R14) | 열린 결제 안내가 없으면(이미 확인됨·취소됨·이미 요청함) SCR-006#stale, 30분이 지났으면 SCR-006#expired |
| 입금자 이름이 달라요 | AI를 거치지 않는 '입금자 이름' 블록이 입금자 이름(1~30자)을 묻고, 그 이름으로 결제 확인을 요청함(SPEC-033, REQ-176) | 1~30자가 아니면 아무것도 남기지 않고 SCR-006#depositor로 다시 물음(input_invalid). 30분이 지났으면 SCR-006#expired |
| 안 할래요 | 아무것도 남기지 않고 '알겠어요. 더 궁금한 것이 있으면 말씀해 주세요' | 서버 오류면 SCR-006#error |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이 상태로 오는 응답 |
| --- | --- | --- |
| SCR-006#normal | 카드 하나: '결제 확인 요청', 주문번호·금액·결제 기한, '입금자 {주문자 이름}(주문자 이름)', 'HH:MM까지 눌러 주세요', 버튼 '결제 확인 요청'·'입금자 이름이 달라요'·'안 할래요'. AI는 결제를 확인하지 않음(TERM-045) | - |
| SCR-006#depositor | '입금자 이름이 달라요'를 누름: AI를 거치지 않는 블록이 입금자 이름을 묻고, 맞으면 그 이름으로 결제 확인을 요청해 '사장님께 알렸어요. 확인되면 알려 드릴게요'(payment_claimed). 1~30자가 아니면(input_invalid) 아무것도 남기지 않고 '입금자 이름은 1~30자로 넣어 주세요'와 '입금자 이름 넣기' 버튼으로 다시 물음 | API-071#200:input_invalid |
| SCR-006#done | '사장님께 알렸어요. 확인되면 알려 드릴게요'. 같은 카드를 다시 누르면 같은 말(card_used). 결제 기한 뒤에 눌렀어도 요청은 남고, 자리는 사장님이 결제 기한 연장으로 다시 잡음(SPEC-033) | API-071#200:payment_claimed, API-071#200:declined, API-071#200:card_used |
| SCR-006#stale | 카드 뒤에 결제 안내가 바뀜(card_stale, 결제 기한 연장 등): 새 카드. 열린 결제 안내가 없음(not_allowed_now): '지금은 할 수 없어요: 이미 결제가 확인됐어요' 같은 지금 상태 | API-071#200:card_stale, API-071#200:not_allowed_now |
| SCR-006#expired | 보낸 지 30분이 지난 카드를 누름(card_expired): '시간이 지나 새 카드를 보내 드려요'와 지금 값으로 만든 새 카드. 아무것도 남지 않음 | API-071#200:card_expired |
| SCR-006#permission | 카드를 받은 사용자가 아님(card_not_yours): '이 버튼은 카드를 받은 분만 누를 수 있어요'. 아무것도 남지 않음. 그 사이 채널 연결이 끊긴 가게(not_accepting): '아직 상담을 받지 않아요. 가게로 연락해 주세요: {가게 연락처}' | API-071#200:card_not_yours, API-071#200:not_accepting |
| SCR-006#error | 쓰기 하나가 실패해 하나도 남기지 않음(retry_needed): '다시 눌러 주세요'. 서버 오류(server_error): '잠시 뒤 다시 말씀해 주세요'. 스킬 키가 틀리거나 형식이 아니거나 예상하지 못한 실패(401·422·default): 카카오톡이 자기 오류 말을 보임(우리 문구 없음, DEC-07). 서버 로그에 추적 ID | API-071#200:retry_needed, API-071#200:server_error, API-071#401:skill_key_invalid, API-071#422:validation_failed, API-071#default:internal |
| loading (해당 없음) | 버튼을 누른 뒤 답이 올 때까지는 카카오톡이 자기 표시를 함. 우리가 그릴 것이 없음 |  |
| empty (해당 없음) | 카드는 서버가 저장된 값이 있을 때만 만들어 보임(SPEC-069). 빈 카드는 없음 |  |

| API-071#200:order_cancelled | 나오지 않음 | 이 카드에서는 나오지 않음(SCR-009 취소 카드의 결과) |

| API-071#200:card_used | SCR-006#done | (처음 결과와 같은 말) |
| API-071#200:day_full | 나오지 않음 | 주문 요청 카드(SCR-004)에서만 나옴 |

## 케이스 유형

| 케이스 유형 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 카드를 받은 같은 카카오 사용자만 누름. 다른 사람은 SCR-006#permission, 스킬 키가 틀리면 SCR-006#error |
| 입력 | 카드 값은 서버 기록에서만 옴. 입금자 이름은 AI를 거치지 않는 '입금자 이름' 블록으로만 받고 1~30자가 아니면 SCR-006#depositor로 다시 물음(input_invalid). 스킬 요청 형식이 아니면 SCR-006#error |
| 대상 | 지금 상태에서 받을 수 없는 명령은 '지금은 할 수 없어요: {지금 상태}'(SCR-006#stale) |
| 상태 변화 | 열린 결제 안내가 없으면 버튼 대신 지금 상태(SCR-006#stale). 버전이 바뀐 카드는 SCR-006#stale, 30분이 지난 카드는 SCR-006#expired |
| 반복 | 같은 카드를 다시 누르면 처음 결과를 다시 보냄(SCR-006#done, card_used). 명령은 한 번 |
| 동시 변경 | 카드를 보낸 뒤 다른 쓰기가 먼저 이기면 SCR-006#stale |
| 외부 서비스 | 트랜잭션의 쓰기 하나가 실패하면 하나도 남기지 않고 '다시 눌러 주세요'(SCR-006#error) |
| 데이터 노출 | 카드와 결과에 다른 손님 정보·내부 ID(주문번호 밖)·오류 내용 없음(G6). 입금자 이름은 AI로 보내지 않음(REQ-178) |
| AI 답 | AI는 카드를 제안만 하고 카드의 값(금액·버전·환불)은 서버 기록에서 만듦(SPEC-069). AI 말로 카드 값을 바꿀 수 없음 |
| 화면 상태 | 상태마다 360·1280 와이어프레임(`wireframes.html#SCR-006`) |
