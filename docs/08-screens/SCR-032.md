# SCR-032 영업 캘린더

- 경로: `/owner/calendar`
- 접근 권한: 사장님
- 상위 화면: SCR-014 사장님 로그인
- 화면 레이아웃: 사장님 화면(1280 왼쪽 메뉴, 360 위쪽 막대와 메뉴 버튼)
- 플로우: FL-001, FL-002, FL-006, FL-007
- 관련 SPEC: SPEC-007, SPEC-012, SPEC-015
- API: API-028, API-029
- 와이어프레임: `wireframes.html#SCR-032`(상태 10개, 360·1280)
- 목업: [`SCR-032-360`](../../research/cake-mockup-2026-11/canvas/project/SCR-032-360.dc.html)(normal·empty·error·confirm), [`SCR-032-1280`](../../research/cake-mockup-2026-11/canvas/project/SCR-032-1280.dc.html)(normal). 캔버스의 '사장님 화면' 페이지([09단계 README](../09-mockup/README.md) 2절)

목적: 사장님이 날짜별 하루 최대 개수·잡힌 자리·남은 자리·마감 여부를 보고 그날의 휴무·하루 최대 개수·주문 마감을 바꿉니다. (FL-001, FL-002, FL-006, FL-007)

## 데이터

| 데이터 | 출처 |
| --- | --- |
| 날짜마다 요일 휴무·그날 휴무·그날 하루 최대 개수·잡힌 자리·남은 자리·다 참·사장님 마감·추가 수락 | API-028 items |
| 보는 기간(최대 62일) | API-028 요청 from·to |
| 저장한 그날 값 | API-029 day |

## 액션

| 액션 | 결과 | 실패 |
| --- | --- | --- |
| 날짜 누르기 | 그날 패널: 휴무·하루 최대 개수(0~100)·주문 마감과 '저장' | 지난 날짜는 패널이 읽기 전용 |
| 저장(그날) | '그날 주문을 마감했어요'(풀면 '다시 받아요'). 이미 그렇게 되어 있으면 '이미 그렇게 되어 있어요' | 확정 주문이 있는 날을 휴무로 바꾸면 SCR-032#confirm, 지난 날짜·한도 밖(422)은 SCR-032#error, 본 뒤 바뀜(409 version_conflict)은 SCR-032#stale |
| 이전 달·다음 달 | 그 기간을 다시 불러옴 | 기간 값이 틀리면(422) SCR-032#error |
| 영업 캘린더 설정 | 영업 캘린더 설정(SCR-033) | 그 화면의 상태 |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이 상태로 오는 응답 |
| --- | --- | --- |
| SCR-032#normal | 캘린더(1280: 두 달, 360: 한 달). 날마다 '잡힌 자리/하루 최대'(예: 3/5)와 라벨 하나: 휴무, 다 참, 마감(사장님이 누름), 추가 수락. 색만으로 구분하지 않고 글자 라벨. 날짜를 누르면 1280은 오른쪽, 360은 아래 패널 | API-028#200:days |
| SCR-032#loading | 레이아웃은 그대로 두고 데이터 자리에 회색 막대를 보임. 액션 버튼은 누를 수 없음. 캘린더 셀 자리는 그대로 | (데이터를 불러오는 동안) |
| SCR-032#empty | 영업 캘린더 설정을 아직 하지 않음(404 not_set): '아직 정하지 않았어요'와 '영업 캘린더 설정하기'(SCR-033) | API-028#404:not_set, API-029#404:not_set |
| SCR-032#error | 주소의 필터·페이지 값이 틀림(422 validation_failed): '입력한 내용을 확인해 주세요'와 '처음부터 보기'. 지난 날짜를 바꾸려 함·하루 최대 개수가 0~100 밖(422 validation_failed): 패널 필드 옆 '입력한 내용을 확인해 주세요'와 사유, 넣은 값은 그대로 둠. 같은 요청 키로 다른 내용을 보냄(422 idempotency_key_reused): '다시 시도해 주세요'. 새 요청 키로 다시 보냄. 그 밖의 저장 실패: 넣은 값은 그대로 두고 폼 위에 '문제가 생겼어요. 다시 시도해 주세요'와 다시 시도 버튼, 추적 ID | API-028#422:validation_failed, API-029#422:validation_failed, API-029#422:idempotency_key_reused, API-029#default:internal |
| SCR-032#load-failed | 불러오기 실패: 폼을 보일 수 없어 '문제가 생겼어요. 다시 시도해 주세요'와 다시 시도 버튼, 추적 ID. 입력 오류와 저장 실패는 error(폼과 넣은 값은 그대로) | API-028#default:internal |
| SCR-032#permission | 로그인이 없거나 만료됨(401 unauthenticated): 로그인 화면으로 이동하고, 로그인하면 이 화면으로 돌아옴('다시 로그인해 주세요'). 로그인한 사장님에게 가게가 아직 없음(404 shop_not_registered): 가게가 없으면 가게 등록(SCR-015)으로 보냄('가게를 먼저 등록해 주세요') | API-028#401:unauthenticated, API-028#404:shop_not_registered, API-029#401:unauthenticated, API-029#404:shop_not_registered |
| SCR-032#stale | 본 뒤 그날이 바뀜(409 version_conflict, 그 사이 자리가 잡히거나 풀림): '그 사이 바뀌었어요. 지금 상태를 확인해 주세요'와 다시 읽은 지금 상태. 캘린더는 연 시각 기준이라 'HH:MM 기준'과 '새로 고침' | API-029#409:version_conflict |
| SCR-032#submitting | 누른 버튼이 '처리하고 있어요'로 바뀌고 이 화면의 다른 액션과 함께 막힘. 첫 요청을 아직 처리하는 중이면(409 request_in_progress) 1초 뒤 같은 요청 키로 다시 보내고, 결과는 한 번만 보임 | API-029#409:request_in_progress |
| SCR-032#confirm | 저장하기 전에 사장님 확인이 필요함(409 confirmation_required, closed_day_with_orders): 확인 창에 '이날 확정 주문 {count}건은 그대로 남아요. 휴무로 바꿀까요?'. '휴무로 바꾸기'를 누르면 confirm에 closed_day_with_orders를 넣고 새 요청 키로 다시 보냄. '돌아가기'면 아무것도 바뀌지 않음. 주문과 자리는 그대로 남음(REQ-041) | API-029#409:confirmation_required |
| SCR-032#done | 저장(closed_orders 등): 결과 문구와 바뀐 그날 셀. 바뀐 것 없음(unchanged): '이미 그렇게 되어 있어요' | API-029#200:closed_orders, API-029#200:unchanged |

## 케이스 유형

| 케이스 유형 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 로그인한 사장님의 가게 캘린더만. 401은 SCR-032#permission |
| 입력 | 하루 최대 개수 0~100, 기간 62일 안. 틀리면 SCR-032#error |
| 대상 | 지난 날짜는 바꿀 수 없음(SCR-032#error). 설정 전이면 SCR-032#empty |
| 상태 변화 | 확정 주문이 있는 날을 휴무로 바꾸면 SCR-032#confirm. 이미 그렇게 되어 있으면 SCR-032#done |
| 반복 | 저장을 두 번 눌러도 한 번(같은 요청 키, SCR-032#submitting) |
| 동시 변경 | 바꾸는 순간 그날 자리를 잡는 요청이 오면 날짜 행 잠금 순서대로(G3). 본 뒤 바뀌면 SCR-032#stale |
| 데이터 노출 | 남은 자리 수는 사장님에게만(G6). 손님 화면에는 '받음·마감·휴무'만 |
| 빈 응답·끊긴 응답 | 기간의 날마다 셀이 하나라 빈 캘린더는 없음. 설정 전은 SCR-032#empty |
| 화면 상태 | 상태마다 360·1280 와이어프레임(`wireframes.html#SCR-032`) |
