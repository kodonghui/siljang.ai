# SCR-041 카카오톡 채널 연결

- 경로: `/owner/kakao-channel`
- 접근 권한: 사장님
- 상위 화면: SCR-034 가게 설정
- 화면 레이아웃: 사장님 화면(1280 왼쪽 메뉴, 360 위쪽 막대와 메뉴 버튼)
- 플로우: FL-001
- 관련 SPEC: SPEC-008
- API: API-030, API-031, API-032
- 와이어프레임: `wireframes.html#SCR-041`(상태 9개, 360·1280)
- 목업: [`SCR-041-360`](../../research/cake-mockup-2026-11/canvas/project/SCR-041-360.dc.html)(normal·empty·error), [`SCR-041-1280`](../../research/cake-mockup-2026-11/canvas/project/SCR-041-1280.dc.html)(normal). 캔버스의 '사장님 화면' 페이지([09단계 README](../09-mockup/README.md) 2절)

목적: 사장님이 연결할 가게 카카오톡 채널(오픈빌더 봇)을 정하고, 우리 스킬 설정 값을 오픈빌더에 옮긴 뒤 연결 확인(10분)을 합니다. 봇 ID 찾는 법도 여기서 봅니다(OPEN-8). (FL-001)

| 저장·확인 시작 결과 | API-031 outcome·kakaoChannel, API-032 outcome·kakaoChannel |

## 액션

| 액션 | 결과 | 실패 |
| --- | --- | --- |
| 봇 ID·채널 공개 ID 저장 | '저장했어요. 아래 스킬 설정 값을 오픈빌더에 넣어 주세요'와 스킬 설정 값 | 이미 다른 가게에 연결된 채널(409 channel_linked_elsewhere)은 SCR-041#error(운영자에게도 알림), 형식(422)은 필드 옆, 본 뒤 바뀜은 SCR-041#stale |
| 값 복사(스킬 주소·헤더 값) | 클립보드에 복사하고 '복사했어요' | 복사가 막힌 브라우저면 값을 선택해 둠 |
| 연결 확인 | 10분 동안 SCR-041#checking: 가게 채널에 아무 메시지나 보내 달라는 안내. 몇 초마다 다시 읽음 | 봇·채널을 정하기 전(404 not_set)은 SCR-041#empty, 이미 확인 중이거나 연결됨(200 unchanged)은 지금 상태 그대로 |
| 봇 ID 찾는 법(펼치기) | 오픈빌더에서 봇을 열었을 때 주소의 /bot/ 다음 값이라는 안내와 예시(W7, 개발 전 실제 화면으로 확인) | 해당 없음(화면 안 안내) |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이 상태로 오는 응답 |
| --- | --- | --- |
| SCR-041#normal | 연결됨(linked): '연결됨'과 연결된 시각, 봇 ID·채널 공개 ID, 스킬 설정 값(접어 둠), '채널 바꾸기'. 바꾸면 새 채널이 연결될 때 옛 채널은 그만 받고, 예약 링크의 문의 버튼은 새 채널을 엶(SPEC-008) | API-030#200:linked |
| SCR-041#loading | 레이아웃은 그대로 두고 데이터 자리에 회색 막대를 보임. 액션 버튼은 누를 수 없음 | (데이터를 불러오는 동안) |
| SCR-041#empty | 아직 채널을 정하지 않음(404 not_set): 연결 순서 1~4단계(① 오픈빌더에서 봇 열기 ② 봇 ID·채널 공개 ID 넣기 ③ 스킬 설정 값 옮기고 배포 ④ 연결 확인), 봇 ID·채널 공개 ID 필드, '봇 ID 찾는 법'(펼쳐 둠), '저장' | API-030#404:not_set, API-032#404:not_set |
| SCR-041#error | 연결 안 됨(failed): '연결 안 됨'과 사유 후보(스킬 주소·스킬 키 헤더·오픈빌더 배포·테스트 메시지가 오지 않음)마다 확인할 곳. '테스트 메시지가 오지 않음'에는 '봇 ID가 오픈빌더 주소의 값과 같은지 확인해 주세요'(W7)와 '다시 확인'. 이미 다른 가게에 연결된 채널(409 channel_linked_elsewhere): '이미 다른 가게에 연결된 채널이에요'와 다른 채널 고르기. 입력이 한도나 형식에 맞지 않음(422 validation_failed): 필드 옆에 '입력한 내용을 확인해 주세요'와 필드마다의 사유. 넣은 값은 그대로 둠. 같은 요청 키로 다른 내용을 보냄(422 idempotency_key_reused): '다시 시도해 주세요'. 새 요청 키로 다시 보냄. 그 밖의 실패: '문제가 생겼어요. 다시 시도해 주세요'와 다시 시도 버튼, 추적 ID | API-030#200:failed, API-030#default:internal, API-031#409:channel_linked_elsewhere, API-031#422:validation_failed, API-031#422:idempotency_key_reused, API-031#default:internal, API-032#422:validation_failed, API-032#422:idempotency_key_reused, API-032#default:internal |
| SCR-041#permission | 로그인이 없거나 만료됨(401 unauthenticated): 로그인 화면으로 이동하고, 로그인하면 이 화면으로 돌아옴('다시 로그인해 주세요'). 로그인한 사장님에게 가게가 아직 없음(404 shop_not_registered): 가게가 없으면 가게 등록(SCR-015)으로 보냄('가게를 먼저 등록해 주세요') | API-030#401:unauthenticated, API-030#404:shop_not_registered, API-031#401:unauthenticated, API-031#404:shop_not_registered, API-032#401:unauthenticated, API-032#404:shop_not_registered |
| SCR-041#stale | 다른 기기에서 먼저 바꿈(409 version_conflict): '그 사이 바뀌었어요. 지금 상태를 확인해 주세요'와 다시 읽은 지금 상태 | API-031#409:version_conflict |
| SCR-041#submitting | 누른 버튼이 '처리하고 있어요'로 바뀌고 이 화면의 다른 액션과 함께 막힘. 첫 요청을 아직 처리하는 중이면(409 request_in_progress) 1초 뒤 같은 요청 키로 다시 보내고, 결과는 한 번만 보임 | API-031#409:request_in_progress, API-032#409:request_in_progress |
| SCR-041#checking | 연결 확인 중(pending): '연결 확인 중'과 남은 시간(최대 10분), '가게 채널에 아무 메시지나 보내 주세요'. 몇 초마다 다시 읽고 테스트 메시지가 오면 SCR-041#normal로(손님 쪽은 SCR-003#link-test). 10분이 지나면 SCR-041#error | API-030#200:pending, API-032#200:started, API-032#200:unchanged |
| SCR-041#done | 저장(created): '저장했어요. 아래 스킬 설정 값을 오픈빌더에 넣어 주세요'와 스킬 설정 값을 펼침, '연결 확인'. 바뀐 것 없음(unchanged): '바뀐 것이 없어요' | API-031#200:created, API-031#200:unchanged |

## 케이스 유형

| 케이스 유형 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 로그인한 사장님의 가게만. 401은 SCR-041#permission |
| 입력 | 봇 ID 1~64자, 채널 공개 ID 2~40자. 틀리면 SCR-041#error |
| 대상 | 다른 가게에 연결된 채널은 SCR-041#error(운영자 알림, SCR-049). 정하기 전이면 SCR-041#empty |
| 상태 변화 | 채널을 바꾸면 새 채널이 연결될 때 옛 채널은 그만 받음 |
| 반복 | 연결 확인을 여러 번 눌러도 연결은 하나(G2, SCR-041#checking) |
| 동시 변경 | 다른 기기의 저장과 동시에 일어나면 SCR-041#stale |
| 외부 서비스 | 10분 안에 테스트 메시지가 없으면 SCR-041#error와 사유 후보 |
| 데이터 노출 | 스킬 키(헤더 값)는 이 화면에만(DEC-08). 처음엔 마스킹하고 '보기'를 눌러야 보임 |
| 빈 응답·끊긴 응답 | 정하기 전이면 SCR-041#empty |
| 화면 상태 | 상태마다 360·1280 와이어프레임(`wireframes.html#SCR-041`) |
