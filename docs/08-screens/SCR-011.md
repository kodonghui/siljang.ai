# SCR-011 손님 알림

- 경로: `kakao:shop/notice`
- 접근 권한: 손님
- 상위 화면: SCR-003 가게 채널 상담
- 화면 레이아웃: 카카오톡 채널 대화 화면(1280은 PC 카카오톡 창)
- 플로우: FL-004, FL-005, FL-006, FL-007, FL-008, FL-009, FL-010, FL-011, FL-012
- 관련 SPEC: SPEC-066, SPEC-023, SPEC-024, SPEC-036, SPEC-039, SPEC-044, SPEC-045, SPEC-047, SPEC-052, SPEC-053, SPEC-059, SPEC-061
- API: API-073
- 와이어프레임: `wireframes.html#SCR-011`(상태 4개, 360·1280)
- 목업: [`SCR-011-360`](../../research/cake-mockup-2026-11/canvas/project/SCR-011-360.dc.html)(normal·deferred·error), [`SCR-011-1280`](../../research/cake-mockup-2026-11/canvas/project/SCR-011-1280.dc.html)(normal). 캔버스의 '손님 화면' 페이지([09단계 README](../09-mockup/README.md) 2절)

목적: 손님이 서비스가 먼저 보내는 안내(주문 확정·전날·완성 사진·지연·에스컬레이션 건의 답·결과·후기 부탁)를 가게 채널에서 받습니다. (FL-004, FL-005, FL-006, FL-007, FL-008, FL-009, FL-010, FL-011, FL-012)

| 먼저 보낼 때: 가게 봇의 안내 블록이 안내 키로 부르는 안내 스킬이 그 안내의 글과 버튼을 보임 | API-073 notice_shown(SPEC-066) |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이 상태로 오는 응답 |
| --- | --- | --- |
| SCR-011#normal | 말풍선 하나(필요하면 사진·버튼). 안내마다 서버의 정해진 템플릿이고 AI가 쓰지 않으며 광고가 없음. 대화 중이 아니면 우리 서버가 가게 봇의 Event API를 부르고 안내 블록이 안내 스킬(API-073)로 그 글을 보임. 정해진 시각 안내(전날·후기)는 08:00~20:50에만 | API-073#200:notice_shown |
| SCR-011#deferred | 손님이 채널 친구가 아니거나, 그 가게의 먼저 보내기가 안 되거나(SCR-041#event-off), 카카오가 전하지 못했다고 알림(발송 결과, REQ-181): 이벤트마다 '못 보냄'으로 두었다가 손님이 다음에 말을 걸면 그 답보다 먼저 이 안내들이 감(일어난 순서로). 사장님 화면에는 '다음 대화 때 전함'(SCR-017 등) | - |
| SCR-011#stale | 보내기 전에 그 이벤트가 의미 없어지면 보내지 않음(전날 안내 전에 취소·날짜 변경, 후기 부탁 전에 문제 신고). 이미 보낸 안내는 대화에 남고 뒤의 안내가 바뀐 상태를 알림. 안내 블록이 부를 때 그 안내를 찾을 수 없으면(notice_gone) '지금은 전할 안내가 없어요'만 | API-073#200:notice_gone |
| SCR-011#error | 카카오 보내기 실패: 카카오가 요청을 받지 않거나 발송 결과가 스킬·카카오 오류면 1분·5분·30분 뒤 다시 보내고 그래도 안 되면 다음 대화 때 먼저 전함(G4). 닿았는지는 발송 결과로 확인한 뒤에만 '보냄'(REQ-182). 손님에게 오류는 보이지 않음 | API-073#401:skill_key_invalid, API-073#422:validation_failed, API-073#default:internal |
| loading (해당 없음) | 서버가 먼저 보내는 말풍선이라 불러오는 동안이 없음 |  |
| empty (해당 없음) | 보낼 이벤트가 있을 때만 생김 |  |
| permission (해당 없음) | 카카오톡 1:1 대화라 그 손님에게만 보임. 안내에 다른 손님 정보가 없음 |  |

## 케이스 유형

| 케이스 유형 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 안내 스킬은 그 가게의 안내만 보임(G1). 스킬 키가 틀리면 카카오가 보내지 않음(SCR-011#error) |
| 상태 변화 | 보내기 전에 의미 없어진 안내는 보내지 않음(SCR-011#stale) |
| 반복 | 같은 주문·같은 이벤트의 안내는 한 번(REQ-154). 안내 스킬이 같은 안내 키로 다시 불려도 같은 글 |
| 외부 서비스 | 카카오가 받지 않거나 발송 결과가 스킬·카카오 오류면 1분·5분·30분 뒤 다시, 그래도 안 되면 SCR-011#deferred(G4). 먼저 보내기가 안 되는 가게는 처음부터 SCR-011#deferred(REQ-181) |
| 데이터 노출 | 다른 손님 정보·내부 ID 없음. 금액 불일치 안내에는 들어온 금액을 적지 않음(SPEC-035). 광고 0(SPEC-066) |
| 빈 응답·끊긴 응답 | 보낼 이벤트가 없으면 아무것도 가지 않음 |
| AI 답 | 안내 글은 서버의 정해진 템플릿이고 AI가 쓰지 않음(SPEC-066). 사장님 답은 고치지 않고 그대로(SPEC-023) |
| 화면 상태 | 상태마다 360·1280 와이어프레임(`wireframes.html#SCR-011`) |
