# SCR-005 결제 안내

- 경로: `kakao:shop/payment-request`
- 접근 권한: 주문한 손님
- 상위 화면: SCR-003 가게 채널 상담
- 화면 레이아웃: 카카오톡 채널 대화 화면(1280은 PC 카카오톡 창)
- 플로우: FL-004, FL-007, FL-008
- 관련 SPEC: SPEC-032, SPEC-066
- API: 없음(서버가 보내는 안내만 보임)
- 와이어프레임: `wireframes.html#SCR-005`(상태 4개, 360·1280)

목적: 주문한 손님이 결제할 금액·가게 명의 계좌(있으면 카드 결제 링크)·결제 기한을 받고, 결제한 뒤 '결제했어요'로 결제 확인을 요청합니다. (FL-004, FL-007, FL-008)

## 데이터

| 데이터 | 출처 |
| --- | --- |
| 종류(첫 결제·다시 낸 결제·차액 결제)와 주문번호 | 서버 안내 SPEC-032 |
| 금액. 사장님이 금액을 바꿔 수락했으면 요청 금액과 바뀐 금액을 함께 | 서버 안내 SPEC-032 |
| 가게 명의 계좌(은행·계좌번호·예금주)와 카드 결제 링크(있으면) | 서버 안내 SPEC-032, SPEC-006 |
| 결제 기한: 결제 안내를 낸 시각부터 운영규정의 결제 기한(기본 12시간). 차액 결제는 결제 기한과 변경 마감 가운데 이른 때 | 서버 안내 SPEC-032, SPEC-043 |

## 액션

| 액션 | 결과 | 실패 |
| --- | --- | --- |
| 계좌번호 복사 | 카카오톡의 길게 눌러 복사 | 해당 없음(카카오톡 기능) |
| 카드 결제 링크 | 가게가 등록한 카드 결제 페이지가 열림(우리가 만든 결제 수단이 아님) | 링크가 열리지 않으면 계좌로 결제. 가게 페이지의 문제는 가게에 문의 |
| 결제했어요(바로가기, W8) | 그 말이 상담으로 가서 결제 확인 요청 카드(SCR-006)가 나옴 | 상담의 상태(SCR-003) |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이 상태로 오는 응답 |
| --- | --- | --- |
| SCR-005#normal | 말풍선 하나: '결제 안내 · 주문번호 {orderNo}', 금액, 가게 계좌, (있으면) '카드로 결제' 버튼, '{기한}까지 보내 주세요', 바로가기 '결제했어요'. 다시 낸 결제는 '결제 기한을 연장했어요'와 새 기한, 차액 결제는 '변경 차액'과 그 기한, 금액을 바꿔 수락했으면 '요청 금액 50,000원 → 55,000원'. 대화 중이면 답으로, 아니면 친구에게 먼저 보냄 | - |
| SCR-005#deferred | 손님이 채널 친구가 아님: 바로 보내지 못하고 손님이 다음에 말을 걸 때 그 답보다 먼저 이 안내가 감. 결제 기한은 보낸 시각이 아니라 안내를 낸 시각부터 세므로 늦게 받은 만큼 남은 시간이 짧음(R12). 주문 요청 결과에 채널 추가 권유가 함께 감(SPEC-029) | - |
| SCR-005#stale | 새 결제 안내가 나가면(결제 기한 연장) 옛 안내는 닫힘. 대화에 남은 옛 안내의 계좌·기한은 그대로 보이지만, 손님이 결제했다고 하면 열린 안내로 카드가 나오고 닫힌 안내로는 결제 확인을 요청할 수 없음(SCR-006#stale) | - |
| SCR-005#error | 카카오 보내기 실패: 1분·5분·30분 뒤 다시 보내고 그래도 안 되면 다음 대화 때 먼저 전함(SCR-005#deferred와 같은 모습). 손님에게 오류는 보이지 않음(G4) | - |
| loading (해당 없음) | 서버가 먼저 보내는 말풍선이라 불러오는 동안이 없음 |  |
| empty (해당 없음) | 결제 안내는 금액과 가게 계좌가 있을 때만 만들어짐(결제 수단이 없으면 예약 링크가 없음, REQ-164) |  |
| permission (해당 없음) | 카카오톡 1:1 대화라 그 주문을 요청한 손님에게만 보임 |  |

## 케이스 유형
