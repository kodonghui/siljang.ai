# SCR-005 결제 안내

- 경로: `kakao:shop/payment-request`
- 접근 권한: 주문한 손님
- 상위 화면: SCR-003 가게 채널 상담
- 화면 레이아웃: 카카오톡 채널 대화 화면(1280은 PC 카카오톡 창)
- 플로우: FL-004, FL-007, FL-008
- 관련 SPEC: SPEC-032, SPEC-066, SPEC-076
- API: API-073, API-071
- 와이어프레임: `wireframes.html#SCR-005`(상태 7개, 360·1280)
- 목업: [`SCR-005-360`](../../research/cake-mockup-2026-11/canvas/project/SCR-005-360.dc.html)(normal·deferred·error), [`SCR-005-1280`](../../research/cake-mockup-2026-11/canvas/project/SCR-005-1280.dc.html)(normal). 캔버스의 '손님 화면' 페이지([09단계 README](../09-mockup/README.md) 2절)

목적: 주문한 손님이 결제할 금액·가게 명의 계좌(있으면 카드 결제 링크)·결제 기한을 받고, 결제한 뒤 '결제했어요'로 결제 확인을 요청합니다. 사장님이 손님이 본 금액보다 높게 정한 맞춤 주문과 금액이 오르는 변경은 계좌 전에 새 금액 확인 카드에서 그 금액을 확인하거나 받지 않습니다. (FL-004, FL-007, FL-008)

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이 상태로 오는 응답 |
| --- | --- | --- |
| SCR-005#normal | 말풍선 하나: '결제 안내 · 주문번호 {orderNo}', 금액, 가게 계좌, (있으면) '카드로 결제' 버튼, '{기한}까지 보내 주세요', 바로가기 '결제했어요'. 다시 낸 결제는 '결제 기한을 연장했어요'와 새 기한, 차액 결제는 '변경 차액'과 그 기한. 사장님이 금액을 정하거나 바꿔 수락했으면 '요청하신 견적 70,000원부터 → 75,000원'과 사유(REQ-231). 새 금액 확인 카드에서 확인했으면(amount_confirmed) 위에 '새 금액을 확인했어요'(결제 기한은 확인한 때부터). 대화 중이면 답으로, 아니면 그 가게의 먼저 보내기로 보냄(우리 서버가 가게 봇의 Event API를 부르고 안내 블록이 안내 스킬 API-073으로 이 글을 보임) | API-073#200:notice_shown, API-071#200:amount_confirmed |
| SCR-005#amount-confirm | 새 금액 확인이 필요한 결제 안내(사장님이 손님이 본 금액보다 높게 정한 맞춤 주문의 첫 결제와 확인받기 전에 다시 낸 결제, 금액이 오르는 변경의 차액 결제)를 전할 때: 계좌 대신 카드 '새 금액 확인'. 맞춤 주문은 '요청하신 견적 {견적의 표시}'·'사장님이 정한 금액 {n}원'·'사유: {사유}', 변경은 바뀌는 내용과 '지금 36,000원 → 새 금액 56,000원'·'차액 20,000원'·'변경 마감 M월 D일 HH:MM까지'. 'HH:MM까지 눌러 주세요'와 버튼 '이 금액으로 할게요'·'안 할래요'(변경은 '바꿀게요'·'그대로 둘래요'). 확인 전에는 계좌·카드 결제 링크가 없고 결제 기한은 상한(그날 주문 마감, 변경은 변경 마감). 손님이 '결제했어요'라고 해도 이 카드를 다시 보임(SPEC-033). 30분이 지난 카드를 누르면(card_expired) '시간이 지나 새 카드를 보내 드려요'와 지금 값으로 만든 새 카드. 사유는 사장님이 쓴 글 그대로(AI가 바꾸지 않음) | API-071#200:card_expired |
| SCR-005#done | 받지 않음(amount_declined): 맞춤 주문은 '알겠어요. 주문을 취소했어요', 변경은 '알겠어요. 바꾸지 않고 원래 주문대로 할게요'. 계좌는 보이지 않고 사장님께 알림이 감(REQ-233). 같은 카드를 다시 누르면 처음 결과를 다시 보냄(card_used) | API-071#200:amount_declined, API-071#200:card_used |
| SCR-005#deferred | 손님이 채널 친구가 아니거나, 그 가게의 먼저 보내기가 안 되거나(SCR-041#event-off), 카카오가 전하지 못했다고 알림(발송 결과, REQ-181): 바로 보내지 못하고 손님이 다음에 말을 걸 때 그 답보다 먼저 이 안내가 감. 결제 기한은 손님에게 전해진 때부터 세므로(REQ-218) 다음 대화 때 받으면 그때부터 결제 기한이 시작되고 말풍선의 기한도 그때 정함. 다만 결제 기한 상한(그날 주문 마감, 이미 지났으면 픽업 일시)을 넘지 않아 상한이 가까우면 남은 시간이 짧고, 상한이 지난 뒤 전하게 되면 계좌 없이 '결제 기한이 지나 사장님이 확인하고 있어요'만 보임(SCR-005#stale). 새 금액 확인 카드도 같은 길로 전하고, 전하지 못한 동안 결제 기한은 상한까지(SPEC-076). 주문 요청 카드와 결과에 채널 추가 권유가 함께 감(SPEC-028, SPEC-029) | - |
| SCR-005#stale | 새 결제 안내가 나가면(결제 기한 연장) 옛 안내는 닫힘. 대화에 남은 옛 안내의 계좌·기한은 그대로 보이지만, 손님이 결제했다고 하면 열린 안내로 카드가 나오고 닫힌 안내로는 결제 확인을 요청할 수 없음(SCR-006#stale). 안내 블록이 부를 때 그 안내를 찾을 수 없으면(notice_gone) '지금은 전할 안내가 없어요'만 보이고 계좌·금액은 보이지 않음. 결제 기한 상한이 지난 결제 안내(상한이 지난 뒤에야 다음 대화 때 전하게 됨)는 계좌·금액 없이 '결제 기한이 지나 사장님이 확인하고 있어요'만 보임(SPEC-037, SPEC-066). 새 금액 확인 카드를 보낸 뒤 결제 안내가 바뀌었으면(card_stale) '내용이 바뀌었어요. 새 카드를 확인해 주세요'와 새 카드. 그 사이 주문이 취소됐거나 변경 요청이 닫혔거나 결제 기한 상한이 지났거나 사장님이 들어온 돈을 먼저 결제로 확인했으면(not_allowed_now) '지금은 할 수 없어요: {지금 상태}'(SPEC-076) | API-073#200:notice_gone, API-071#200:card_stale, API-071#200:not_allowed_now |
| SCR-005#permission | 카드를 받은 사용자가 아님(card_not_yours): '이 버튼은 카드를 받은 분만 누를 수 있어요'. 아무것도 남지 않음. 그 사이 채널 연결이 끊긴 가게(not_accepting): '아직 상담을 받지 않아요. 가게로 연락해 주세요: {가게 연락처}'. 결제 안내는 카카오톡 1:1 대화라 그 주문을 요청한 손님에게만 보임 | API-071#200:card_not_yours, API-071#200:not_accepting |
| SCR-005#error | 카카오 보내기 실패: 카카오가 요청을 받지 않거나 발송 결과가 스킬·카카오 오류면 1분·5분·30분 뒤 다시 보내고 그래도 안 되면 다음 대화 때 먼저 전함(SCR-005#deferred와 같은 모습). 닿았는지는 발송 결과로 확인한 뒤에만 '보냄'(REQ-182). 손님에게 오류는 보이지 않음(G4). 새 금액 확인 카드의 버튼: 쓰기 하나가 실패해 하나도 남기지 않음(retry_needed) '다시 눌러 주세요', 서버 오류(server_error) '잠시 뒤 다시 말씀해 주세요', 스킬 키가 틀리거나 형식이 아니거나 예상하지 못한 실패(401·422·default) 카카오톡이 자기 오류 말을 보임(우리 문구 없음, DEC-07). 서버 로그에 추적 ID | API-073#401:skill_key_invalid, API-073#422:validation_failed, API-073#default:internal, API-071#200:retry_needed, API-071#200:server_error, API-071#401:skill_key_invalid, API-071#422:validation_failed, API-071#default:internal |
| loading (해당 없음) | 서버가 먼저 보내는 말풍선이라 불러오는 동안이 없음. 새 금액 확인 카드의 버튼을 누른 뒤 답이 올 때까지는 카카오톡이 자기 표시를 함 |  |
| empty (해당 없음) | 결제 안내는 금액과 가게 계좌가 있을 때만 만들어짐(결제 수단이 없으면 예약 링크가 없음, REQ-164) |  |

## 케이스 유형

| 케이스 유형 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 안내 스킬은 그 가게의 안내만 보임(G1). 스킬 키가 틀리면 카카오가 보내지 않음(SCR-005#error). 새 금액 확인 카드는 주문을 요청한 같은 카카오 사용자만 누름(SCR-005#permission, REQ-062) |
| 입력 | 새 금액 확인 카드의 값(요청한 견적·정한 금액·사유·차액)은 서버 기록에서만 오고 손님 말로 바꿀 수 없음(SPEC-076) |
| 상태 변화 | 결제 기한 연장으로 새 안내가 나가면 옛 안내는 닫힘(SCR-005#stale). 사장님이 계좌를 바꿔도 이미 나간 안내의 계좌는 그대로, 그 뒤 낸 안내부터 새 계좌(REQ-198). 결제 기한은 손님에게 전해진 때부터 세고 결제 기한 상한을 넘지 않음(REQ-218). 상한이 지난 안내는 SCR-005#stale의 짧은 글. 새 금액 확인이 필요한 결제 안내는 손님이 확인하기 전에는 계좌 없이 SCR-005#amount-confirm, 받지 않으면 SCR-005#done(REQ-232, REQ-233). 확인 전에 사장님이 들어온 돈을 결제로 확인하면 그 시각이 손님의 확인이 되고 카드 버튼은 SCR-005#stale |
| 반복 | 같은 이벤트의 결제 안내는 한 번(REQ-154). 결제 기한 연장의 새 안내는 다른 이벤트라 따로 감. 안내 스킬이 같은 안내 키로 다시 불려도 같은 글. 새 금액 확인 카드를 두 번 눌러도 확인·받지 않음은 한 번(card_used, SCR-005#done) |
| 외부 서비스 | 카카오가 받지 않거나 발송 결과가 스킬·카카오 오류면 1분·5분·30분 뒤 다시, 그래도 안 되면 SCR-005#deferred(G4). 먼저 보내기가 안 되는 가게는 처음부터 SCR-005#deferred(REQ-181) |
| 한도 | 새 금액 확인 카드의 버튼은 보인 뒤 30분까지. 지나면 새 카드(SCR-005#amount-confirm) |
| 데이터 노출 | 가게 명의 계좌와 링크만. 우리 회사 계좌·다른 가게 정보 0건(REQ-079). 다른 손님 정보·내부 ID 없음(G6). 새 금액 확인 카드의 사유는 사장님이 쓴 글 그대로 |
| AI 답 | 새 금액 확인 카드는 서버가 결제 안내로 만들고 AI가 쓰지 않음(SPEC-076) |
| 화면 상태 | 상태마다 360·1280 와이어프레임(`wireframes.html#SCR-005`) |
