- 경로: `/owner`
- 접근 권한: 사장님
- 상위 화면: SCR-014 사장님 로그인
- 화면 레이아웃: 사장님 화면(1280 왼쪽 메뉴, 360 위쪽 막대와 메뉴 버튼)
- 플로우: FL-001, FL-002, FL-005, FL-006, FL-007, FL-008, FL-009, FL-011, FL-013
- 관련 SPEC: SPEC-067, SPEC-024, SPEC-037
- API: API-040, API-002
- 와이어프레임: `wireframes.html#SCR-016`(상태 7개, 360·1280)
- 목업: [`SCR-016-360`](../../research/cake-mockup-2026-11/canvas/project/SCR-016-360.dc.html)(normal·empty·error·not-sent), [`SCR-016-1280`](../../research/cake-mockup-2026-11/canvas/project/SCR-016-1280.dc.html)(normal). 캔버스의 '사장님 화면' 페이지([09단계 README](../09-mockup/README.md) 2절)

목적: 사장님이 처리할 일(에스컬레이션 건·맞춤 주문·결제 확인 요청·금액 불일치·결제 기한 지난 주문·변경 요청·문제 신고·환불 결정·환불 보내기·들어온 입금 대조·장부 다시 연결·영업 신고 보류·캘린더 기준을 넘는 날)을 오래된 순으로 보고 눌러 해당 화면을 엽니다. 상단 배너로 빠진 설정을 봅니다. (FL-001, FL-002, FL-005, FL-006, FL-007, FL-008, FL-009, FL-011, FL-013)

## 액션

| 액션 | 결과 | 실패 |
| --- | --- | --- |
| 할 일 누르기 | 종류에 맞는 화면이 열림: 에스컬레이션 건은 SCR-017, 맞춤 주문은 SCR-022, 변경 요청은 SCR-024, 문제 신고는 SCR-027, 결제 확인 요청과 금액 불일치와 들어온 입금 대조는 SCR-029, 결제 기한 지난 주문은 SCR-023, 환불 결정과 취소된 주문에 들어온 입금은 SCR-025, 환불 보내기는 SCR-026, 장부 다시 연결은 SCR-042, 영업 신고 보류는 SCR-035, 캘린더 기준을 넘는 날은 SCR-032 | 그 사이 처리된 할 일이면 열린 화면의 stale('이미 처리됐어요') |
| 배너 누르기 | 알림 채널 추가는 우리 서비스 채널(SCR-019), 영업 신고 확인 중·보류는 SCR-035, 예약 링크 전은 SCR-043, 장부 다시 연결은 SCR-042 | 열린 화면의 상태 |
| '처리한 일' 탭 | 닫힌 할 일을 최근 순으로 | SCR-016#error |
| 더 보기 | 다음 페이지(커서)를 목록 아래에 추가로 불러옴 | 실패하면 목록 끝에 '다시 시도' |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이 상태로 오는 응답 |
| --- | --- | --- |
| SCR-016#normal | 1280: 왼쪽 메뉴, 위에 배너(있으면), 탭 '열린 할 일'·'처리한 일', 표(종류·요약·주문번호·연 시각·기다림). 360: 위쪽 막대와 메뉴 버튼, 할 일마다 카드. 지연 안내를 보낼 시각이 지난 할 일은 '지연' 라벨과 굵은 테두리(색만으로 구분하지 않음). 결제 확인 요청·금액 불일치·환불 결정도 기다림이 있음(REQ-215). '처리한 일' 탭에서 사장님 답 없이 닫힌 할 일(맞춤 주문 요청·변경 요청·에스컬레이션 건·결제 확인 요청)은 '답 없어 닫힘' 라벨 | API-040#200:open_tasks, API-002#200:mvp, API-002#200:friend |
| SCR-016#loading | 레이아웃은 그대로 두고 데이터 자리에 회색 막대를 보임. 액션 버튼은 누를 수 없음. 배너 자리는 보이지 않다가 받은 뒤 나타나 아래 목록이 밀리지 않게 높이를 미리 잡음 | (데이터를 불러오는 동안) |
| SCR-016#empty | '지금 처리할 일이 없어요'. 배너는 그대로 보임 | API-040#200:empty |
| SCR-016#error | 주소의 필터·페이지 값이 틀림(422 validation_failed): '입력한 내용을 확인해 주세요'와 '처음부터 보기'. 그 밖의 실패: '문제가 생겼어요. 다시 시도해 주세요'와 다시 시도 버튼, 추적 ID | API-040#422:validation_failed, API-040#default:internal, API-002#default:internal |
| SCR-016#permission | 로그인이 없거나 만료됨(401 unauthenticated): 로그인 화면으로 이동하고, 로그인하면 이 화면으로 돌아옴('다시 로그인해 주세요'). 로그인한 사장님에게 가게가 아직 없음(404 shop_not_registered): 가게가 없으면 가게 등록(SCR-015)으로 보냄('가게를 먼저 등록해 주세요'). 가게가 없는 계정의 API-002 no_shop도 같음 | API-040#401:unauthenticated, API-040#404:shop_not_registered, API-002#200:no_shop, API-002#401:unauthenticated |
| SCR-016#stale | 목록은 연 시각 기준이라 그 뒤 바뀐 것이 안 보일 수 있음: 맨 위에 'HH:MM 기준'과 '새로 고침'. 다른 화면에서 처리하고 돌아오면 다시 불러옴. 이미 처리된 할 일을 누르면 그 화면에서 '이미 처리됐어요' | - |
| SCR-016#not-sent | plusfriends 설정을 켠 경우 사장님이 우리 서비스 채널 친구가 아님(not_friend): 할 일은 그대로 보이고 맨 위에 '알림을 받으려면 우리 서비스 채널을 추가하세요'와 '채널 추가'. 알림은 '못 보냄'으로 남고 할 일 목록에만 쌓임(SPEC-067). MVP는 채널 추가 배너를 보이지 않음(DEC-21) | API-040#200:not_friend, API-002#200:not_friend |

## 케이스 유형

| 케이스 유형 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 로그인한 사장님의 가게 할 일만(SPEC-068). 401은 SCR-016#permission |
| 입력 | 주소의 필터·페이지 값이 틀리면 SCR-016#error |
| 대상 | 가게가 없으면 SCR-016#permission에서 가게 등록으로 |
| 상태 변화 | 알림 채널 친구가 아니면 SCR-016#not-sent의 배너. 지연 안내를 보낼 시각이 지난 할 일은 '지연'(다시 알림과 손님 지연 안내는 한 번씩, SPEC-024). 맞춤 주문 요청은 그 픽업 날짜의 주문 마감, 변경 요청은 변경 마감, 에스컬레이션 건은 남긴 지 7일, 결제 확인 요청은 결제 기한 상한에 '답 없어 닫힘'으로 '처리한 일'로 감. 금액 불일치·환불 결정·문제 신고는 닫히지 않고 남음 |
| 반복 | 할 일은 이벤트마다 하나(G2). 같은 종류의 알림이 1분 안에 여럿이면 하나로 묶어 보냄(SPEC-067) |
| 데이터 노출 | 요약에 손님 연락처·계좌·알레르기 없음(SPEC-067) |
| 빈 응답·끊긴 응답 | 할 일이 없으면 SCR-016#empty |
| 화면 상태 | 상태마다 360·1280 와이어프레임(`wireframes.html#SCR-016`) |
