# SCR-017 에스컬레이션 건

- 경로: `/owner/handoffs/:handoffId`
- 접근 권한: 사장님
- 상위 화면: SCR-016 할 일 목록
- 화면 레이아웃: 사장님 화면(1280 왼쪽 메뉴, 360 위쪽 막대와 메뉴 버튼)
- 플로우: FL-005
- 관련 SPEC: SPEC-022, SPEC-023, SPEC-056
- API: API-041, API-042
- 와이어프레임: `wireframes.html#SCR-017`(상태 7개, 360·1280)

목적: 사장님이 AI 상담이 에스컬레이션한 건의 사유와 손님 말을 보고 답을 쓰면 손님에게 그대로 전해집니다. 마감된 날 문의면 추가 수락이나 받지 않음을 고릅니다. (FL-005)

## 데이터

| 데이터 | 출처 |
| --- | --- |
| 사유(먹어도 되는지·답할 수 없음·마감된 날·법·의료·손님 요청·다른 카카오 사용자·받기 전 문제·AI 오류·AI 비용 한도·콜백 시간 초과·마스킹 실패·빈 답·조문 없음) | API-041 reason |
| 손님 말(마스킹 원본 값 포함, 최근 50개까지)과 사진, 관련 주문, 원한 날짜 | API-041 customerLines·order·requestedDay |
| 손님 채널 친구 여부 | API-041 customerChannelFriend |
| 상태(열림·답함)와 보낸 답·고른 결정·추가 수락 기한(24시간)·답한 시각 | API-041 status·answerText·dayDecision·dayAcceptExpiresAt·answeredAt |

## 액션

| 액션 | 결과 | 실패 |
| --- | --- | --- |
| 보내기 | 답(1~1,000자)을 고치지 않고 손님에게 전함. 친구면 '손님에게 보냈어요', 아니면 '손님이 채널 친구가 아니어서 다음 대화 때 먼저 전해요'. 에스컬레이션 건이 닫히고 할 일에서 빠짐 | 빈 답·1,000자 넘음(422)은 SCR-017#error의 필드 옆, 이미 답함(409 already_decided)·본 뒤 바뀜(409 version_conflict)은 SCR-017#stale |
| 추가 수락·받지 않음(마감된 날 문의) | 추가 수락이면 그 상담의 그 날짜를 24시간 동안 '마감 후 추가 수락'으로 표시. 답 글과 함께 보낼 수 있음 | 보내기와 같음 |
| 상담 대화 보기 | 상담 대화(SCR-018)가 열림 | 그 화면의 상태 |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이 상태로 오는 응답 |
| --- | --- | --- |
| SCR-017#normal | 위에 사유 라벨·받은 시각·기다림(남은 시간이나 '지연'), 손님 말(최근 50개와 사진 썸네일), 관련 주문 링크. 아래 답 필드(1,000자, 남은 글자 수)와 '보내기'. 마감된 날 문의면 원한 날짜와 '추가 수락'·'받지 않음'. 손님이 채널 친구가 아니면 '손님이 채널 친구가 아니어서 다음 대화 때 전해요'를 미리 보임 | API-041#200:edibility, API-041#200:closed_day |
| SCR-017#loading | 레이아웃은 그대로 두고 데이터 자리에 회색 막대를 보임. 액션 버튼은 누를 수 없음 | (데이터를 불러오는 동안) |
| SCR-017#error | 없거나 다른 가게의 에스컬레이션 건(404 not_found): '찾을 수 없어요'와 '할 일 목록으로' 링크(SCR-016). 다른 가게 기록이 있는지는 말하지 않음(G1). 입력이 한도나 형식에 맞지 않음(422 validation_failed): 필드 옆에 '입력한 내용을 확인해 주세요'와 필드마다의 사유. 넣은 값은 그대로 둠. 같은 요청 키로 다른 내용을 보냄(422 idempotency_key_reused): '다시 시도해 주세요'. 새 요청 키로 다시 보냄. 그 밖의 실패: '문제가 생겼어요. 다시 시도해 주세요'와 다시 시도 버튼, 추적 ID | API-041#404:not_found, API-041#default:internal, API-042#404:not_found, API-042#422:validation_failed, API-042#422:idempotency_key_reused, API-042#default:internal |
| SCR-017#permission | 로그인이 없거나 만료됨(401 unauthenticated): 로그인 화면으로 이동하고, 로그인하면 이 화면으로 돌아옴('다시 로그인해 주세요') | API-041#401:unauthenticated, API-042#401:unauthenticated |
| SCR-017#stale | 이미 답한 건(409 already_decided): '이미 처리됐어요'와 보낸 답·시각을 읽기 전용으로. 본 뒤 바뀜(409 version_conflict): '그 사이 바뀌었어요. 지금 상태를 확인해 주세요'와 다시 읽은 지금 상태. 쓰던 답은 지우지 않고 복사할 수 있게 둠 | API-042#409:version_conflict, API-042#409:already_decided |
| SCR-017#submitting | 누른 버튼이 '처리하고 있어요'로 바뀌고 이 화면의 다른 액션과 함께 막힘. 첫 요청을 아직 처리하는 중이면(409 request_in_progress) 1초 뒤 같은 요청 키로 다시 보내고, 결과는 한 번만 보임 | API-042#409:request_in_progress |
| SCR-017#done | 보냄(sent)이나 다음 대화 때 전함(deferred): 결과 문구와 보낸 답·결정을 읽기 전용으로. 답한 건을 다시 열어도 이 모습 | API-042#200:sent, API-042#200:deferred |
| empty (해당 없음) | 에스컬레이션 건은 사유와 손님 말이 있을 때만 생김(SPEC-022). 빈 건은 없음 |  |

## 케이스 유형

| 케이스 유형 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 그 가게의 에스컬레이션 건만. 다른 가게 건은 '찾을 수 없어요'(SCR-017#error, G1) |
| 입력 | 답 1~1,000자. 빈 답·넘는 답은 SCR-017#error의 필드 옆 사유 |
| 대상 | 없는 건은 SCR-017#error와 할 일 목록 링크 |
| 상태 변화 | 이미 답한 건은 SCR-017#stale(이미 처리됐어요) |
| 반복 | 보내기를 두 번 눌러도 한 번 전함(같은 요청 키, SCR-017#submitting) |
| 동시 변경 | 두 탭에서 답하면 먼저 보낸 것만 남고 뒤는 SCR-017#stale(G3) |
| 외부 서비스 | 손님이 채널 친구가 아니면 다음 대화 때 먼저 전함(SCR-017#done). 보내기 실패는 다시 보내고 그래도 안 되면 다음 대화 때(G4) |
| 데이터 노출 | 손님 말의 전화번호·계좌번호는 이 화면에서 원래 값(SPEC-021). 사장님 답은 AI가 고치지 않음(SPEC-023) |
| 화면 상태 | 상태마다 360·1280 와이어프레임(`wireframes.html#SCR-017`) |
