# SCR-047 영업 신고 확인 목록

- 경로: `/operator/shops`
- 접근 권한: 운영자
- 상위 화면: SCR-046 운영자 로그인
- 화면 레이아웃: 운영자 화면(1280 왼쪽 메뉴, 360 위쪽 막대와 메뉴 버튼)
- 플로우: FL-014
- 관련 SPEC: SPEC-003, SPEC-002, SPEC-078
- API: API-012, API-005, API-006, API-081
- 와이어프레임: `wireframes.html#SCR-047`(상태 6개, 360·1280)
- 목업: [`SCR-047-360`](../../research/cake-mockup-2026-11/canvas/project/SCR-047-360.dc.html)(normal·empty·error), [`SCR-047-1280`](../../research/cake-mockup-2026-11/canvas/project/SCR-047-1280.dc.html)(normal). 캔버스의 '운영자 화면' 페이지([09단계 README](../09-mockup/README.md) 2절)

목적: 운영자가 영업 신고를 확인할 가게를 상태(확인 중·보류·확인됨)별로 보고, 눌러서 영업 신고 확인을 엽니다. 사업자 정보 변경 요청도 '사업자 정보 변경' 탭에서 요청한 차례로 봅니다. 손님 문제나 분쟁으로 가게 기록을 찾을 때도 여기서 가게를 고릅니다. 운영자의 첫 화면이고 로그아웃도 여기서 합니다. (FL-014)

| 데이터 | 출처 |

| 상태 탭(확인 중·보류·확인됨)과 다음 페이지 | API-012 요청 status·cursor, nextCursor |
| 사업자 정보 변경 요청: 가게 이름·바뀌는 값(지금 값 → 새 값)·요청 시각·결제 계좌의 은행·예금주·끝 4자리와 예금주가 새 대표자·상호와 같은지 | API-081 items |
| 사업자 정보 변경 탭의 상태와 다음 페이지 | API-081 요청 status·cursor, nextCursor |
| 로그인한 운영자 이름 | API-005 displayName |
| 로그아웃 | API-006 |

## 액션

| 액션 | 결과 | 실패 |
| --- | --- | --- |
| 상태 탭 누르기 | 그 상태의 가게 목록을 다시 불러옴 | 주소의 상태 값이 틀리면(422) SCR-047#error |
| 가게 누르기 | 영업 신고 확인(SCR-048). 가게 기록을 찾을 때는 거기서 '가게 기록 보기'(SCR-050) | 그 화면의 상태 |
| '사업자 정보 변경' 탭 | 확인을 기다리는 사업자 정보 변경 요청을 요청한 차례로 불러옴 | 주소의 상태 값이 틀리면(422) SCR-047#error |
| 변경 요청 누르기 | 그 가게의 영업 신고 확인(SCR-048)에서 그 요청을 반영·보류 | 그 화면의 상태 |
| 더 보기 | 다음 페이지를 목록 아래에 추가로 불러옴 | 실패하면 목록 끝에 '다시 시도' |
| 로그아웃 | 운영자 로그인(SCR-046)으로 이동. 두 번 눌러도 같음 | 실패(default)는 SCR-047#error |

## 상태

| 상태 | 사용자가 보는 것과 할 수 있는 것 | 이 상태로 오는 응답 |
| --- | --- | --- |
| SCR-047#normal | 1280: 왼쪽 메뉴(영업 신고 확인·운영자 알림), 위 오른쪽에 운영자 이름과 '로그아웃'. 탭 '확인 중'·'보류'·'확인됨'·'사업자 정보 변경'(처음에는 '확인 중'), 표: 가게 이름·상호·대표자·사업자등록번호·영업 신고 번호와 종류·등록 시각, 등록이 오래된 순. 같은 사업자등록번호의 다른 가게가 있으면 '사업자등록번호 중복' 라벨. '사업자 정보 변경' 탭은 표: 가게 이름·바뀌는 값('달빛케이크 → 달빛케이크 공방')·요청 시각, 요청한 차례. 예금주가 새 대표자·상호와 다르면 '예금주가 새 대표자·상호와 달라요' 라벨(막지 않음, REQ-197). 360: 가게마다 카드 | API-012#200:pending, API-005#200:operator, API-006#204, API-081#200:pending |
| SCR-047#loading | 레이아웃은 그대로 두고 데이터 자리에 회색 막대를 보임. 액션 버튼은 누를 수 없음. 표의 행 자리는 그대로 | (데이터를 불러오는 동안) |
| SCR-047#empty | 그 탭에 가게가 없음(empty): '확인할 가게가 없어요'('보류' 탭은 '보류한 가게가 없어요', '확인됨' 탭은 '확인된 가게가 없어요', '사업자 정보 변경' 탭은 '확인할 변경 요청이 없어요') | API-012#200:empty, API-081#200:empty |
| SCR-047#error | 주소의 필터·페이지 값이 틀림(422 validation_failed): '입력한 내용을 확인해 주세요'와 '처음부터 보기'. 로그아웃 실패와 그 밖의 실패: '문제가 생겼어요. 다시 시도해 주세요'와 다시 시도 버튼, 추적 ID | API-012#422:validation_failed, API-012#default:internal, API-005#default:internal, API-006#default:internal, API-081#422:validation_failed, API-081#default:internal |
| SCR-047#permission | 운영자 로그인이 없거나 만료됐거나 운영자 계정이 아님(401 unauthenticated): 운영자 로그인(SCR-046)으로 이동하고, 로그인하면 이 화면으로 돌아옴('다시 로그인해 주세요'). 이동하기 전에도 운영자 기록은 하나도 보이지 않음(G1, 06단계 DEC-11) | API-012#401:unauthenticated, API-005#401:unauthenticated, API-081#401:unauthenticated |
| SCR-047#stale | 목록은 연 시각 기준이라 그 뒤 바뀐 것이 안 보일 수 있음: 맨 위에 'HH:MM 기준'과 '새로 고침'. 다른 화면에서 처리하고 돌아오면 다시 불러옴. 다른 운영자가 처리한 가게는 다시 불러올 때 그 상태의 탭으로 옮겨 감 | - |

## 케이스 유형

| 케이스 유형 | 화면에 보이는 것 |
| --- | --- |
| 접근 | 운영자 계정만. 로그인이 없거나 만료됐거나 운영자가 아니면 SCR-047#permission(운영자 기록은 보이지 않음) |
| 입력 | 주소의 상태·페이지 값이 틀리면 SCR-047#error |
| 상태 변화 | 다른 운영자가 처리한 가게는 다시 불러올 때 다른 탭으로 옮겨 감(SCR-047#stale). 반영·보류한 변경 요청은 다시 불러올 때 '사업자 정보 변경' 탭에서 빠짐 |
| 반복 | 로그아웃은 두 번 눌러도 같음. 더 보기는 불러오는 동안 막힘 |
| 동시 변경 | 목록은 연 시각 기준(SCR-047#stale) |
| 데이터 노출 | 가게 등록 정보만 보이고 손님·주문 기록은 없음(SPEC-003). 연락처와 신고증 사진은 목록에 없고 영업 신고 확인(SCR-048)에서만. 손님·주문 기록은 가게 기록 보기(SCR-050)의 가린 값으로만(SPEC-073). 변경 요청은 결제 계좌의 은행·예금주·끝 4자리만(계좌번호 전체 없음, SPEC-003) |
| 빈 응답·끊긴 응답 | 그 탭에 가게나 변경 요청이 없으면 SCR-047#empty |
| 화면 상태 | 상태마다 360·1280 와이어프레임(`wireframes.html#SCR-047`) |
