AI는 명령 종류/선택 주문번호만 제안합니다. 가게·수신 손님·상담의 저장 기록에서 대상 하나를 고르고 카드의 제목·요약·금액/픽업일·버전·30분 기한·버튼/불투명 키를 만듭니다. AI의 reply/완료 주장/금액은 카드에 쓰지 않습니다. 미연결 견적/변경 값·다른 카드와 섞인 초안 변경은 기존 실패 안내로 넘깁니다. 해당 업무의 검증·저장은 TASK069/각 업무 모듈이 맡습니다.

카드와 메시지를 같은 트랜잭션에서 저장하고 기존 서버 전용 confirm_cards.payload의 sourceMessageId로 연결합니다. AI/clientExtra에서는 이 값을 받지 않고 공개 버튼에는 cardKey/choice만 넣습니다. 메시지에는 시스템이 만든 카드 제목만 남겨 모델 대화에 내부 키가 들어가지 않습니다. 콜백 전송 뒤 전달 표시가 중단돼도 저장한 카드로 다시 읽고 모델/카드 생성은 한 번입니다. 다음 대화 전달도 같은 출력 부품을 쓰고 최신 버전/기한을 다시 확인해 오래된 키를 새 카드로 갱신합니다. 사용한 카드는 버튼을 보내지 않고 이미 처리 안내만 보입니다. 이 경로는 업무 실행기를 부르지 않습니다.

기본 서비스의 미등록 업무는 retry_needed이며 카드를 소비하지 않습니다. 실제 취소/환불·결제/주문 요청 등 업무별 실행기 등록은 TASK122/099/083 등 해당 작업에서 연결합니다. 이번 자동 시험의 취소는 공통 실행기 계약을 검증하기 위한 합성DB 상태 변경입니다. 실제 취소/환불 업무 전체를 구현했다고 하지 않습니다. 사장님 고지·이전 안내·새 카드의 순서와 세 outputs 한도를 유지합니다.
