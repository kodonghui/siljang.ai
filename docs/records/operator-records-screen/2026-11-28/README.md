# TASK-161 합성 화면 확인

2026-11-28 서울의 로컬 Vite와 헤드리스 Chromium에서 OpenAPI의 합성 응답을 이용해 SCR-050을 확인했습니다. `list`, `detail`, `loading`, `empty`, `error`, `permission`, `stale`, `confirm`, `submitting`, `done`을 각각 360·1280 너비로 캡처했습니다.

`report.json`과 `states.json`의 page-check는 모두 오류 0이며 문서 가로 너비가 화면 너비를 넘지 않았고 브라우저 오류도 없었습니다. 표시된 버튼과 링크의 크기는 모두 44px 이상이었습니다. 모달이 열린 상태에서는 가려진 배경 글자에 대한 대비 수동 확인 경고가 5~21개 나왔습니다. 캡처에서 모달 본문과 버튼을 직접 보았지만 가려진 배경의 대비를 통과로 세지 않습니다.

실제 스테이징 DB·Cloudflare·운영자 계정과 학원컴 확인은 하지 않았습니다. 로컬 서버는 합성 JSON만 반환했습니다.

리뷰 처리 뒤 전체 Chromium의 합성 뒤로 가기 캐시 시험을 360·1280에서 실행했습니다. `pagehide`와 `pageshow`의 `persisted=true`를 관찰했고 복원된 `pageshow`의 첫 관찰과 로그인 재확인 전 화면에서 연 이름과 사유가 없었습니다. 첫 `pagehide` 관찰자는 화면의 삭제 처리보다 먼저 실행되어 그 순간 원문이 보였으며, 복원 결과와 구분합니다.

재리뷰 뒤 IBM Plex Sans KR의 실제 글꼴 로딩을 기다려 모든 합성 화면을 다시 캡처했습니다. 확인 창의 제출 버튼은 360·1280 모두 48px입니다. 같은 문서에서 프래그먼트 기록을 뒤로 탐색하는 별도 Chromium 시험은 360·1280 모두 원문·사유 노출 0건이었습니다. 모달 배경의 대비 경고는 위와 같습니다.

Codex 리뷰 뒤 수동 CSS를 기존 토큰과 공통 1260px 경계로 바꾸고 스타일 검사의 대상에 추가했습니다. 합성 Chromium에서 360·600·601·768·1259·1260·1280을 확인해 1259까지는 상세만, 1260부터는 목록과 상세가 함께 표시됐으며 가로 넘침은 없었습니다([측정](breakpoints.json)).
