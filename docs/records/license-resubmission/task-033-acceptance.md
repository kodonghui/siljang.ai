# TASK-033 수락 조건 대조

API-011은 보류된 자기 가게의 신고 번호·영업 종류·신고증을 다시 받고 확인 기다림으로 돌립니다. 신원3개·계좌·다른 가게 자료는 바꾸지 않습니다. 실제0033/기존 역할 실행1문장·계정은 미확인이며 finished는 표시하지 않습니다.

| API-011 | 자동 확인 |
| --- | --- |
| 200 | 새 신고 번호/종류·자기 사진으로 pending,이유/판정자·시각 없음입니다. 같은 키는 현재 결과를 읽고 복사1회이며 다른 본문 재사용은422입니다. |
| 401 | 무인증은 데이터베이스0이고 앱 인증 뒤 끝난 세션도 전용 함수가 다시 거절해 저장0입니다. |
| 404 | 실제 사장님 세션이 있어도 등록 가게가 없으면 shop_not_registered입니다. 전용 함수는 자기 세션으로 다른 가게를 고르면 not_found입니다. |
| 409 | 보류가 아닌 pending/verified는 invalid_state이며 사진 복사0입니다. 오래된 버전과 같은 버전 동시 요청은 version_conflict이고 동시는200/409·복사1회입니다. |
| 422 | 신고 번호/두 영업 종류/업로드 ID·필수/유니코드/알 수 없는 필드와 사진 없음·다른 사장님·다른 용도·정확히1시간 지남·크기·종류를 대조합니다. 실제 다른 용도 객체는 upload_wrong_purpose입니다. |
| 기본 오류 | 저장소 head/copy 장애503은 판정을 보존합니다. 변경 뒤 서명500은 신고/사진/보류 할 일도 되돌리고 같은 키 복구200입니다. COMMIT 응답만 잃으면 사용 중 사진을 보존하고 같은 키200을 읽습니다. |

보류 처리: 자기 license_on_hold 할 일과pending 알림 예약만 같은 트랜잭션에서 닫습니다. 다른 가게의 보류/예약과 같은 가게의 다른 할 일은 그대로입니다. 재업로드 자체는 새 할 일/알림을 만들지 않습니다.

G1: 실제 사장님 세션 쿠키로 가게 분리 시험에 새 경로를 등록했습니다. 본문 다른 가게 ID는422,쿼리의 다른/없는/틀린 가게·사장님 ID는 자기 가게의 상태만 보고 두 가게 기록은 그대로입니다. 함수도 자기 세션/가게와 license_photo 경로를 확인합니다.

최소 권한: 로컬 제한 역할에서 함수 권한 없이는500/저장0,실행 권한1문장 뒤 같은 키200/재전송입니다. 신고/판정 직접 UPDATE와 내부 보류 정리 함수 실행은42501입니다. 공개 실행 금지와pg_catalog 검색 경로,살아 있는 자기 세션/소유/보류/버전·사진 경로를0033에서 확인합니다.

신고/사진 입력 규칙과 검사는 가게 등록/사업자 변경과 공유합니다. 사진 복사는 공통 promoteUpload,실패 정리는 공통 ShopCommandSpec.cleanup을 쓰고 COMMIT 응답 유실 때 현재 사진 키가 같은지 확인한 뒤에만 지웁니다. 로컬 초안은 정식0033으로 옮겼고 시험의 임시 SQL 적용 구문은 없앴습니다. 적용한0033은 바꾸지 않습니다.

첫 경로 부재5실패와 결합 때 옛 함수 import로 생긴16실패를 고쳤습니다. 정식33개 마이그레이션의 관련5파일160개·타입과 서버96파일/2,025개·웹237개·빌드917ms/Worker dry-run이 통과했습니다. 설계9단계07:43:17~07:46:42 종료0·규칙404개/안 막힘0이고 schema/33개 버전 카탈로그가 같습니다. 마지막 부모 기록/원격 main 기준 결합에서 앱 실행 코드/계약/DB/권한 변화0을 확인했습니다.

실제 환경은 아래처럼 구분합니다.0033/실행1문장은 실제 기존 역할에 미적용입니다. 실제 사장님 재업로드와 운영자 목록/판정 확인도 미실행이며 Aside 연결/Vault 대기를 유지합니다. 학원컴 프로필의 connected=true·CLI SSH0은 브라우저 복구/로그인 성공으로 세지 않습니다. 모델 API 호출/예상 비용·유료 변경0입니다.
