# TASK-053 결제 수단 화면 수락 대조

SCR-040의 10개 상태와 API-024/025의 16개 응답을 합성 데이터로 대조했습니다. 서버는 기존 TASK-040 계약을 사용하며 이 작업은 계좌 원문을 브라우저 저장소나 로그에 남기지 않습니다.

| 응답 | 화면과 확인한 동작 |
| --- | --- |
| API-024 200 account | 현재 계좌·선택 링크·등록 시각·예금주 확인 답을 읽습니다. |
| API-024 401 unauthenticated | 로그인 경로를 한 번 요청합니다. |
| API-024 404 shop_not_registered | 가게 등록 경로를 한 번 요청합니다. |
| API-024 404 not_set | 빈 양식과 예약 링크에 필요한 등록 안내를 보여 주고 baseRevision:null로 첫 저장합니다. |
| API-024 default internal | 양식 대신 추적 ID와 재조회 동작을 보여 줍니다. |
| API-025 200 created | 새 계좌 안내를 표시하고 신고 보류 가게의 상태를 재조회합니다. |
| API-025 200 unchanged | 바뀐 것이 없다고 표시하며 신고 상태 재조회/재확인 알림을 만들지 않습니다. |
| API-025 401 unauthenticated | 입력을 남기고 로그인 경로를 요청합니다. |
| API-025 404 shop_not_registered | 가게 등록 경로를 요청합니다. |
| API-025 409 version_conflict | 내 입력을 보존하고 최신 은행/링크 위에 내 계좌 변경을 적용한 뒤 최신 revision과 새 키로 저장합니다. |
| API-025 409 confirmation_required | 예금주 확인 창의 돌아가기는 보존하고 확인은 holder_mismatch와 새 키로 저장합니다. |
| API-025 409 holder_not_verified | 서버 errors 배열이 없어도 예금주 옆에 계약 문구·오류 연결과 초점을 둡니다. |
| API-025 409 request_in_progress | 1초 뒤 같은 본문과 키로 이어 보내고 결과를 한 번 보여 줍니다. |
| API-025 422 validation_failed | 계좌/카드 링크 옆에 오류를 붙이고 첫 오류 초점과 원문을 유지합니다. |
| API-025 422 idempotency_key_reused | 같은 본문과 새 요청 키로 다시 시도합니다. |
| API-025 default internal | 원문·추적 ID를 유지하고 같은 요청 키로 다시 시도합니다. |

초기 세션 확인/실패 때 GET을 보내지 않고 회복하면 한 번 읽습니다. 확인 창을 연 뒤 세션이 실패해도 확인 전송을 막고 로그아웃은 허용합니다. 보내는 동안 입력과 다른 액션을 잠급니다. 실제 OwnerArea 경로에서 확인 중·확인됨·보류 가게의 계좌를 열 수 있습니다. 은행은 계약에 목록이 없으므로 입력 가능한 선택 상자에서 현재 은행을 제안합니다. 계좌 숫자10~16개와 기호/길이, 이름의 유니코드30자, https 링크 한도는 API/양식 시험으로 대조합니다.

가격표·운영규정·결제 양식은 초기/충돌 조회·중단·늦은 응답 무시를 공통 useVersionedRead로 처리합니다. 취소 때 loading을 false로 돌리며 TASK-051 병합 뒤 검토7107032418의3번을 처리합니다.

## 실제 환경에서 남은 것

학원컴 Aside CLI의 공통 CDP 장애로 이번 두 폭·10상태 페이지 검사·44px 관측·스크린샷·실제 사장님 계정은 미확인입니다. 같은 조건의 실패를 반복하지 않았습니다. 실제 카카오 계좌 변경 알림도 확인하지 않았으며 전송했다고 표시하지 않습니다. TASK-053은 끝남이나 구현 완료로 세지 않습니다.
