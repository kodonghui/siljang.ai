# 사진 후기 누적 사용량 결정 대기

## 확인한 문제

[보안 발견4690767876](https://github.com/kodonghui/siljang.ai/pull/275#discussion_r4690767876)은 받은 자기 주문을 가진 사용자가 사진 후기를 반복 제출하면 과거 버전 사진이 쌓이는 문제입니다. 현재 유효 스킬 키·같은 손님의 받은 주문·요청마다 사진5장/장당20MiB·3750ms 응답 기한·중단 파일의 지우기 대기는 적용되지만, 합산 저장량이나 새 버전 총수의 제한은 없습니다. 이 발견은 미해결입니다.

## 바로 한도를 넣지 않은 근거

- `research/cake-api-2026-11/api_ops.py`의 API072 omit429는 '후기는 주문마다 받아 빈도 한도가 없음'입니다.
- SPEC062는 '주문마다 후기 하나(고치면 새 버전)'이고 SPEC063은 동의한 후기 사진의 게시·철회를 정합니다. 옛 사진을 즉시 지우면 버전 보존이나 게시 중인 사진을 바꿀 수 있습니다.
- AGENTS.md 1번은 '제품 결정이 필요하면 추천안과 함께 확인 요청을 하고, 답을 기다리는 동안 다음 작업을 한다'입니다. 임의 한도/조기 삭제를 수락 조건으로 추가하지 않습니다.

## 검토할 제안

사진 수신만 같은 손님 기준1분20건으로 합산하고(참고·후기 합계, 일반 글/카드 한도와 구분), 외부 GET 전에 막는 안을 먼저 제안합니다. 별도로 보관 중인 사진의 손님/주문별 총바이트·장수와 후기 버전 수, 새 버전에서 쓰지 않는 옛 사진의 정리 시점을 정해야 합니다. 최신 후기/이미 게시된 사진과 동의 기록을 보존하고, 게시되지 않은 옛 사진의 물리 파일은 새 버전 이후 정리하는 안을 추천하되 제품 결정 전에는 적용하지 않습니다. 구체적인 총량은 실제 합성 사용량과 Free 저장소 여유를 함께 보고 정합니다.

[제안 시험](proposed-aggregate-limit.patch)은 고정 로컬88779ba4b5f31cc614687d0517f1f1889735c019에서 합산20건·동시19건 경계·참고 사진 우회3실패/34건너뜀을 재현했습니다. 현재 계약의 시험이 아니므로 앱 수락 시험에서 제거했고 패치와 결과를 따로 보존합니다. 제품 코드나 계약은 바꾸지 않았으며 '한도 고침'이나 '보안 통과'라고 세지 않습니다.
