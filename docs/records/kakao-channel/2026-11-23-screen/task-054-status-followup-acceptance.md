# TASK-054 상태 후속 대조

원본은 PR #208의 병합 뒤 검토7110341332입니다. 낮음4건·보안0건에 대해 아래와 같이 처리합니다.

| 발견 | 처리 | 확인 |
| --- | --- | --- |
| 1: 실패 배너의 재조회에서 내 변경 재적용이 없음 | 마지막 명령 종류를 stale 조회에 연결 | 입력한 봇 ID가 최신 값 위에 남음 |
| 2: failed/기한 지난 저장의 재확인 안내 | 블록 변경과 확인 초기화를 따로 판단 | 두 상태에서 다시 확인 안내 |
| 3(나): 끝난 확인에도 시작 안내가 남음 | pending을 벗어나면 확인 명령의 지난 안내를 지움 | linked/failed 전환 |
| 4: 새 확인 창에 지난 늦음 배너가 남음 | 연결·기한 key를 대조 | 늦음 배너의 나타남/사라짐 |
| 3(가): revision 변경 때 실패 명령 자동 reset 제안 | 기존 G2의 같은 키 복원을 위해 유지 | 키 교체 실패 뒤 polling revision이 바뀌어도 같은 본문/키 |

첫 관련6개 실패·35개 통과 뒤 실제 다시 불러오기 경로의 재적용 부재도 별도로 재현했습니다. 수정 후 전체 웹939개·타입/lint·빌드824ms와 두 Worker가 통과했습니다. 서버·DB·의존성은 바꾸지 않습니다.

같은 키 재시도는 이미 끝난 결과를 복원할 수 있어야 합니다. polling의 새 revision으로 본문/키를 자동 바꾸면 다른 명령이 됩니다. 기존 본문을 다시 보내 실제 버전 충돌이 오면 G3의 최신 상태/재적용으로 처리하며, 추가 왕복이 생길 수 있다는 검토 의견은 인정합니다.

실제 학원컴 화면/카카오 결과는 공통 Aside CLI CDP 문제로 미확인입니다. finished/구현 완료는 표시하지 않습니다. main208-deployment.json은 실제 Wrangler 원격 대조이며 화면 검사와 구분합니다.
