# 장부 조회와 연결 해제의 좁은 함수

0048은 아직 main에 합치지 않은 이행입니다. main의0047은 바꾸지 않았습니다. 실제 Supabase에0048을 적용하지 않았습니다.

- read_owner_ledger는 가게와 사장님 ID로 소유를 확인한 뒤 장부 상태/시트/열/시각/버전과 미완료 수만 반환합니다. 열 JSON의 숨은 필드는 제거하고 자격 증명 참조는 반환하지 않습니다.
- unlink_owner_ledger는 같은 소유 확인과 가게/연결의 행 잠금 아래 연결을 끊고 대기 쓰기를 연결 끊김 상태로 남깁니다. 적힌 결과와 실패 이력은 보존합니다. 반복 해제는 연결 시각/버전을 바꾸지 않습니다.
- 실제 사장님 세션 확인은 HTTP 해석기가 먼저 합니다. 사장님 ID는 세션에서 만든 가게 범위에서 가져오며 API033/034 입력으로 받지 않습니다. 함수도 전달된 두 ID의 소유 관계를 확인합니다.
- 함수는 PUBLIC 실행0·고정 search_path이고 기존 실행 역할에는 함수 EXECUTE만 줍니다. 기존 가게 설정 조회의 shop_id/status 두 열 권한은 유지하고 시트/자격 증명 참조 직접 조회와 상태 직접 수정은 열지 않습니다.

기록 처리의9개 시험과 기존 보호 시험6개를 포함한17파일438개, 함수의 다른 가게0행·PUBLIC 실행0·열 JSON 숨은 필드 제거를 확인했습니다. 이전 직접 열 권한 방식은 기존 보호 시험에서435통과/1실패였고 그 보호 시험은 바꾸지 않았습니다.

API036의 HTTP 명령/시크릿 삭제와 API035의 연결·재연결은 아직 연결하지 않았습니다. 토큰 저장 위치 제품 결정에 따라 그 부분을 이어야 합니다. 이 기록 처리는 구글을 부르거나 실제 토큰을 지우지 않습니다. 미완료 쓰기는 모두 보존하며 응답의 수는 계약 상한100000입니다. TASK160 화면은 이 상한을100000개 이상으로 표시해야 합니다.
