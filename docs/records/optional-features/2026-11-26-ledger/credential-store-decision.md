# 장부 OAuth 토큰의 저장 위치 결정안

2026-11-26. 아직 결정되지 않았고 실제 토큰/저장소를 만들지 않았습니다.

기존 전달문4절은 비밀 값을 Aside Vault·Workers secrets·GitHub Actions secrets·로컬 .dev.vars에만 두도록 합니다. AGENTS.md6번과 tech-stack.md의 비밀 값 항목도 이 구성을 따릅니다. API035는 가게마다 생기는 구글 OAuth 토큰을 시크릿 저장소에 두고 ledger_links에는 credential_ref만 남기는 계약입니다. 설정용 Workers secrets만 사용하는 현재 구성에는 요청 중 가게별 토큰을 지속해서 저장하는 어댑터가 없습니다.

추천은 **무료 제공이 확인될 때만 기존 서울 Supabase 프로젝트의 Vault에 이 토큰을 암호화해 저장하는 예외**입니다. 앱 설정 키는 기존 Workers secrets에 둡니다. 일반 장부 표·요청 키·로그·응답에는 토큰을 넣지 않습니다. 새 외부 회사나 유료 요금제는 더하지 않습니다.

구현 경계는 다음과 같습니다.

- Vault 표/복호화 뷰를 공용 실행 역할에 직접 열지 않습니다. PUBLIC 실행0·고정 search_path의 좁은 함수로 활성 사장님 세션/가게/연결 소유를 검증합니다. 정기 장부 쓰기 역할의 토큰 읽기도 별도 권한으로 나눕니다.
- 장부 표에는 무작위 참조만 둡니다. 연결 실패 시 새로 만든 비밀 값만 정리하고, 연결 해제 시 그 연결의 토큰을 지웁니다. 다른 구글 서비스의 권한을 일괄 취소하지 않습니다.
- 데이터 API는 다시 켜지 않고 기존 서버 전용 PostgreSQL 연결을 사용합니다. 백업에는 암호문만 들어가며 Vault 복구 키는 Aside Vault에 별도로 보관해야 합니다. 새 프로젝트로 수동 복구하는 조건도 TASK165에서 확인해야 합니다.
- 실제 무료 제공/확장/역할 적용·키 사본·합성 연결/재시작 후 읽기/해제는 학원컴 Aside CLI로 확인합니다. 유료 전환은 하지 않습니다. 로컬의 모의 Vault 시험을 실제 Vault 확인으로 세지 않습니다.

대안은 현재 저장 규칙을 유지하고 다른 플랫폼 시크릿 어댑터를 더 검토하는 것입니다. 그동안 API035의 실제 자동 연결은 완료 처리하지 않습니다. Vault도 권한이 있는 실행 역할은 복호화할 수 있다는 반론이 있어 좁은 함수와 역할 분리가 필요합니다.

공식 문서 확인일은2026-11-26입니다. [Supabase Vault](https://supabase.com/docs/guides/database/vault)는 인증 암호화·복호화 뷰·프로젝트 밖에서 관리하는 암호화 키·수동 프로젝트 이전의 키 조건을 설명합니다. [요금표](https://supabase.com/pricing)만으로 Vault 무료 제공을 확정하지 못했습니다. 따라서 이 안은 무료가 확인되는 경우에 한정하며 실제 설치/결제/키 조회는 하지 않았습니다.
