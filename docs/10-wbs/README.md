## 3. 나눈 방식

- 작업 하나는 PR 하나로 끝내고 검사를 지날 수 있는 크기입니다. 크기는 0.5·1·2·3일 가운데 하나이고, 3일을 넘으면 나눕니다. 크기는 Claude의 어림이고 시간 약속이 아닙니다.
- 맡은 이는 동희님이나 Claude 하나입니다. 동희님 몫은 동희님 계정이나 판단이 있어야 하는 일(카카오 채널·봇·앱 만들기, AI 회사에 신청, 전문가 확인, 결정 카드 답, 운영 계정)이고, 나머지는 Claude가 만들어 PR로 올립니다.
- 서버 작업은 SPEC 하나나 그 일부와 그 API를, 화면 작업은 화면(SCR) 하나를 맡습니다. 여러 기능이 함께 쓰는 바탕(요청 키, 오류 응답, 가게 나누기, 자동으로 하는 일 실행기, 암호화, 모델 호출, 웹 바탕)은 반복 1에 따로 둡니다.
- 끝난 조건의 첫 줄은 손으로 쓰고, 나머지 줄은 원본에서 생성합니다.
  - 수락 기준: SPEC마다 그 SPEC을 출처 맨 앞에 둔 서버 작업이 #1~#n을 모두 받습니다. 그런 작업이 둘 이상이면 원본의 `ac`로 나눕니다(예: SPEC-001은 TASK-020이 #1~#4, TASK-021이 #5).
  - API: 계약(`api/openapi.yaml`)의 응답 코드마다 시험 한 줄. 카카오 스킬 API 넷(API-070~073)은 그 작업의 SPEC에 속한 스킬 결과 코드도 받습니다.
  - 화면: 08단계 상태 전부와 응답 행. 사장님·운영자 웹 화면은 360·1280에서 그려 page-check(누르는 곳 44px)를 지나고, 손님 화면(카카오톡 안)은 스킬 응답이 08 정의와 같은지(출력 3개 이하, 카드 설명 400자 이하) 봅니다.
  - 규칙: 05 앱 규칙(A)과 04 공통 규칙(G)을 받은 작업은 그 규칙을 지키는지 보는 시험 줄을 받습니다.
- 앞선 작업은 원본에 적은 것에, 화면 작업이면 그 화면이 부르는 API를 만드는 작업이 자동으로 더해집니다. API는 처음 그 API를 적은 작업이 만들고, 뒤 작업은 고칩니다.
- 화면이 부르는 API 가운데 뒤 반복에서 만드는 것이 있으면, 화면 작업은 그 API를 기다리지 않고(`later_api`) 뒤 반복에 그 API 몫만 하는 화면 작업(`only_api`)을 둡니다. 지금은 둘입니다: SCR-017의 API-083(문제 신고로 남기기, 반복 6), SCR-021의 API-048(가게 사정 취소, 반복 5). 그래서 앞 반복의 작업이 뒤 반복의 작업을 기다리지 않습니다(7절 검사).
- 테이블은 서버 작업이 출처 SPEC에서 닿는 테이블(05 `erd_map.py`)을 받고, 마이그레이션 작업(TASK-017)이 모든 테이블을 만듭니다.
- 06 열린 질문은 반복 0의 시험·결정 작업이 받고, TASK-011이 그 결과로 04·05·06의 확인 전 가정을 고칩니다. SPEC 행에 없는 유효 요구사항(2절 표)을 받은 작업은 `wbs.md` 부록 E에 있습니다.
- ID는 바꾸거나 다시 쓰지 않습니다. 새 작업은 끝 번호 다음이고, 없앤 작업은 지우지 않고 `status='removed'`와 날짜·이유를 남깁니다(`wbs.md`의 '지운 작업' 절).

## 6. 기술 스택

TASK-001은 2026-11-15에 끝났습니다. 우리 프로젝트가 스택에 요구하는 것, leetmaster-v3에서 가져올 것, 추천 구성과 한도 대조, 옮길 길, OVH 평가, 비용, 반론, 확인하지 못한 것은 [`tech-stack.md`](tech-stack.md)에 있습니다. 고르는 일은 TASK-002(동희님)입니다.

- 추천(Claude): 서버는 Cloudflare Workers + Hono(TypeScript), 웹은 React + Vite를 같은 Worker의 정적 자산으로, 데이터베이스는 Supabase 서울의 PostgreSQL 17을 Hyperdrive(읽기 캐시 끔)로, 자동으로 하는 일은 Cron Trigger 매분과 작업 표(05 A33)로, AI 답·콜백·다시 하기는 Queues로, 사진은 Supabase Storage 서울의 비공개 버킷에 둡니다.
- 언어: 이 절의 첫 버전([PR #50](https://github.com/kodonghui/siljang.ai/pull/50))은 A(Python 서버 + TypeScript 웹)를 추천했지만, 동희님이 Cloudflare로 MVP를 하자고 하셔서 B(TypeScript 하나)로 바꿨습니다(tech-stack.md 7절). 저장소의 생성·검사 도구는 Python 그대로입니다.
- PostgreSQL 17: Supabase 새 프로젝트의 기본이 17이라, 05 검사 15개(마이그레이션 0001~0020, 규칙 테스트 324개, 동시 쓰기 D5)를 로컬 PostgreSQL 17.11에서 돌려 모두 통과했습니다(2026-11-15 17:29 KST).
- 월 비용 어림(공식 가격표, AI 사용료 따로): 개발 0~5달러, 가게 10곳 약 30~35달러, 가게 100곳 약 35~60달러. PITR(7일)을 고르면 월 100달러가 더해집니다(tech-stack.md 6절).
- OVH 뭄바이·싱가포르 서버: 손님 개인정보를 두거나 처리하는 운영에는 권하지 않고(국외 이전·지연·운영 부담·대역폭), 개인정보가 없는 1분 외부 감시·합성 상담 AI 평가·카카오 시험과 지연 측정에 권합니다(tech-stack.md 5절).
- 실제 서비스로 옮길 곳: AWS 서울(Fargate + RDS)이나 Google Cloud 서울(Cloud Run + Cloud SQL). 옮기기 쉽게 지금 지킬 것 여섯은 tech-stack.md 4-3입니다.
- 사장님·운영자 앱(동희님 결정, 9-1): 휴대폰 홈 화면에 추가하는 웹앱(PWA)을 먼저 내고(TASK-176), 스토어 앱은 웹 다음에 같은 웹을 Capacitor로 감싸 만드는 길을 추천합니다(tech-stack.md 9-2, 반복 9). 웹을 먼저 만들 때 지킬 것 여섯(라우팅, 인증 쿠키, 앱 알림, 카메라·파일, 로그인 방법, 계정 지우기)은 9-3, 스토어 계정 비용(Apple 연 99달러, Google 한 번 25달러)과 심사는 9-4입니다. 사장님 알림은 지금 설계대로 우리 서비스 채널의 카카오톡이고, 앱 알림은 스토어 앱 때 더합니다(TASK-180).
