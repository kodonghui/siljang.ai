# 09단계 목업: 수제케이크 주문제작 화면

상태: 진행 중. 첫 체크포인트(방향 고르기)를 2026-11-13 13:41에 지났고(8절), 고른 방향(후보 A '주문서'에 손님 화면의 사진을 크게)으로 화면 49개의 주요 상태를 그려 화면 정의에서 링크했습니다(5절). 남은 것은 개발 전에 토큰을 고정하는 두 번째 체크포인트입니다(9절). 원본은 토큰을 쓰는 [`make_tokens.py`](../../research/cake-mockup-2026-11/make_tokens.py), 화면 49개를 쓰는 [`gen_screens.py`](../../research/cake-mockup-2026-11/gen_screens.py)와 그 예시 값 [`screen_samples.py`](../../research/cake-mockup-2026-11/screen_samples.py), 후보 아트보드를 쓰는 [`gen.py`](../../research/cake-mockup-2026-11/gen.py)이고, 검사는 [`check_mockup.py`](../../research/cake-mockup-2026-11/check_mockup.py)입니다.

## 1. 요약

- 고른 방향으로 화면 49개를 모두 그렸습니다. 화면마다 360 보드 하나(normal 전체 길이, 이어서 모습이 크게 다른 상태를 360 × 800으로)와 1280 보드 하나(normal 전체 길이)이고, 아트보드 98개·프레임 193개입니다(5절). 360에 따로 그린 상태는 error 49, empty 24, confirm 11, expired 7, deferred 2, not-sent 2입니다.
- 새 아트보드는 [`design/base.tokens.json`](../../design/base.tokens.json)의 토큰 55개만 씁니다(아이콘 크기도 `size.icon-sm`·`md`·`lg`). 손님 화면의 포트폴리오 사진은 `size.photo` 240px로 크게, 가격표의 도안 그림은 `size.thumb` 104px로 둡니다. 글과 숫자는 08단계 정의와 06단계 예시에서 가져왔습니다(7절).
- 화면 정의 49개의 머리말에 '목업' 줄을 넣어 그 화면의 360·1280 보드를 링크했습니다. 화면 정의는 생성 파일이라 08단계 원본(`build_screens.py`)이 캔버스 배치(`canvas.json`)를 읽어 씁니다.
- 캔버스는 페이지 넷입니다: 손님 화면(13개), 사장님 화면(32개), 운영자 화면(4개), 후보 A·B(방향 고르기 기록)(2절).
- 검사: `check_mockup.py` 14개 모두 통과, page-check는 아트보드 111개 모두 오류 0입니다(6절). 08단계 검사(`check_screens.py`)도 다시 생성한 화면 정의로 통과합니다.
- 방향을 고르기 전에는 후보 A '주문서'와 B '쇼케이스'를 화면 3개(SCR-001·016·022) × 너비 2개(360, 1280)로 나란히 그렸습니다(4절). 후보 토큰은 A 51개, B 55개이고, 같은 내용이 B에서 더 깁니다. 전체 길이 프레임 높이가 SCR-001은 360에서 A 1384·B 1840, 1280에서 A 1442·B 1894이고, SCR-022는 360에서 A 1164·B 1378, 1280에서 A 890·B 1068입니다(Playwright Chromium으로 잰 값).
- 방향: 2026-11-13 13:41 결정 카드에서 동희님이 질문 넷 모두 추천을 고르셨습니다. A '주문서' + 손님 화면 사진 크게, 보는 곳은 Claude Design 캔버스 유지, 49개 화면을 모두 그리되 주요 상태만, 빠진 입력은 임시로 두고 진행입니다(8절).
- 다음: 개발 전에 토큰을 고정하는 두 번째 체크포인트입니다(9절). 로고·브랜드 색·글꼴·실제 케이크 사진·서비스 이름을 받으면 그 전에 반영합니다.

## 10. 관리 방법

- 고른 방향의 화면 보드 98개는 `gen_screens.py`가 08단계 레이아웃(`research/cake-screens-2026-11/screens_*.py`)과 `screen_samples.py`의 예시 값으로 씁니다. `python3 -B research/cake-mockup-2026-11/gen_screens.py`는 98개 모두, 뒤에 `SCR-001 ...`을 붙이면 그 화면만 다시 씁니다. 이때 `canvas.json`의 페이지 4개와 화면 보드·줄 제목·설명 메모도 함께 씁니다(후보 보드와 메모는 '후보 A·B' 페이지에 두고 자리는 그대로). 화면 정의를 바꿀 때는 08단계를 먼저 고친 뒤 다시 생성합니다. 높이는 `heights.json`에서 읽습니다. 내용이 바뀌어 높이가 달라지면 C11(page-check)이 '그린 크기'와 `$preview`가 다르다고 알려 주므로, 잰 높이로 `heights.json`을 고치고 다시 생성합니다.
- 후보 아트보드를 바꿀 때는 `gen.py`를 고치고 `python3 -B research/cake-mockup-2026-11/gen.py [이름 ...]`로 다시 씁니다. 높이는 `heights.json`에서 읽습니다. 내용이 바뀌어 높이가 달라지면 page-check가 잰 높이로 `heights.json`과 `canvas.json`의 크기를 고칩니다. `A·B-SCR-001-360`과 `Main`은 이전 세션에서 쓴 파일이라 `gen.py`가 쓰지 않습니다.
- 화면 정의의 '목업' 줄은 08단계 생성기(`python3 -B research/cake-screens-2026-11/build_screens.py --write`)가 `canvas.json`과 보드 파일의 제목(그린 상태)을 읽어 씁니다. 보드를 더하거나 페이지를 바꾸면 이것도 다시 돌립니다(08단계 C13이 생성 파일과 원본이 같은지 봅니다).
- 토큰을 바꿀 때는 `make_tokens.py`를 고치고 다시 만든 뒤(`python3 -B research/cake-mockup-2026-11/make_tokens.py`가 후보 두 개와 `design/base.tokens.json`을 함께 씀), 아트보드 루트의 변수를 같게 맞춥니다(C2가 다르면 실패). 화면 보드 98개는 `gen_screens.py`를 다시 돌리면 `base.tokens.json`의 변수로 다시 씁니다.
- 고른 아트보드의 PNG: `dc2html.py`로 혼자 열리는 HTML을 만든 뒤 `node research/cake-mockup-2026-11/export_png.js <HTML 절대 경로> <아트보드 너비> docs/09-mockup/exports/<이름>.png 2`.

- 캔버스에 올리기: 바뀐 파일을 같은 Artifact 주소에 올립니다(root는 `research/cake-mockup-2026-11/canvas`, 파일은 `project/<이름>`, `canvas.json`과 바뀐 보드 파일을 한 번에). 올리기 전에 캔버스의 지금 판을 한 번 읽습니다(읽지 않은 판 위에는 올라가지 않습니다). 올린 뒤 캔버스의 `project/` 파일을 모두 내려받아 저장소 파일과 바이트까지 견줍니다(한글 한 글자를 바꾸면 바이트 수가 그대로일 수 있어 크기만 보지 않습니다). 2026-11-13 화면 98개를 올린 뒤 파일 112개(보드 111개와 `canvas.json`)가 모두 같았습니다.
