## 2. 도구와 쓰는 차례

명령·API로 되는 일은 명령으로 하고, 화면에서만 되는 일은 Aside·agent-desktop으로 한다.

| 일 | 도구 | 시작할 때 할 것 |
| --- | --- | --- |
| 코드, git, 시험, CI, PR | 네 셸 | 지금처럼 |
| Cloudflare 배포·Hyperdrive·Queues·Cron·비밀 값 | `wrangler`(app의 고정 버전, `npx --no-install wrangler`) | `wrangler login`(브라우저 인증은 Aside가 누름) 또는 API 토큰 환경 변수 |
| Supabase 프로젝트·마이그레이션 | Supabase CLI나 대시보드, 데이터베이스는 `psql`과 `tools/db-migrate.sh` | `supabase login`(브라우저 인증은 Aside) |
| 로그인이 필요한 웹 화면(대시보드, 카카오비즈니스, 오픈빌더 i.kakao.com, 카카오 디벨로퍼스, 구글 클라우드, 신청 양식, 문의 글) | Aside: `aside exec "<할 일>"` | `aside --version`, `aside --help`, `aside guide`를 먼저 읽고 그 버전의 명령을 따른다 |
| 스크린샷·화면 확인을 직접 스크립트로 | Aside: `aside repl "<스크립트>"` | `aside guide repl`. 스크립트 끝에 본 것을 표시하는 줄을 찍고, 그 줄로 성공을 판단한다(종료 코드만 보지 않는다) |
| 카카오톡 PC 앱 조작 | agent-desktop | `agent-desktop version`, `status`, `skills get desktop`, `skills get platform`을 읽는다. snapshot → ref에 행동 → 다시 snapshot으로 확인 |
| 휴대폰에서만 되는 확인(PWA 홈 화면, 앱 알림) | 동희님 휴대폰 | 따라 할 단계를 짧게 써서 동희님께 요청하고, 받은 사진을 기록한다 |

- `aside exec`의 답은 주장이다. 화면·파일·API 응답으로 확인한 뒤 기록한다.
- Aside가 Linux에서 돌지 않으면 `aside --host <컴퓨터>`로 동희님 컴퓨터의 Aside를 쓴다(`aside host list`).
- 캡차·휴대폰 인증 번호·패스키처럼 사람 확인 화면이 나오면 그 단계만 동희님께 요청하고, 끝나면 이어서 한다.

### 2-1. 비밀 값을 두는 곳

| 값 | 두는 곳 | 저장소·기록에 적는 것 |
| --- | --- | --- |
| 계정 로그인, 데이터베이스 비밀번호, 대시보드에서 만든 토큰 | Aside Vault | 만든 날, 이름, 용도 |
| Worker가 쓰는 값(데이터베이스 연결, 카카오 키, AI 키, 계좌번호 암호화 키 `FIELD_KEY_*`) | `wrangler secret put`(스테이징·운영 환경마다) | 변수 이름 |
| CI가 쓰는 값(배포 토큰 등) | GitHub Actions secrets | 변수 이름 |
| 로컬 실행에 쓰는 값 | `app/server/.dev.vars`(이미 .gitignore) | 변수 이름, `.dev.vars.example`에 이름만 |

- 명령에 값을 넣어야 하면 환경 변수나 표준 입력으로 넘기고 출력하지 않는다.
- 계좌번호 암호화 키는 잃으면 계좌번호를 되살릴 수 없다(05 E20). 운영 키는 Worker 비밀 값과 Aside Vault 두 곳에 둔다.
- 커밋 전에 `node tools/check-no-keys.mjs --repo`를 돌린다.
